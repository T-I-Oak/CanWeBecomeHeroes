# ランの集計と記録

## 1. 集計範囲

ゲーム中の事実を、今回のラン用と累積用に収集する。一般集計はモードを分けない。試験・チャレンジの開始回数と試験の合格・不合格回数はモードと初期Heroの組合せごとに保持する。組合せは順不同の全28組である。

一般集計は以下を扱う。

- 課題種類・構成indexごとの挑戦回数、クリアー回数、最高クリアーレベル。
- 敵種ごとの討伐回数と、獲得貢献ptの合計。ギルドで消費しても獲得合計は減らない。
- ギルドで実際に消費した貢献ポイントの合計（今回ラン・累積に収集）。
- 施設ごとの出発回数とHero別の出発回数。目的地への出発確定時に数える。倉庫は対象外。
- Hero・武器種類ごとの装備回数。試験場への出発確定時だけ、装備武器1個につき1回を数える。他施設への出発では数えない。
- Hero・タグごとの最高タグ数。Hero本体と装備のタグを合わせ、能力上限を適用しない。
- Heroごとのショップで宝石スキルによって実際に追加され、配送されたタグ数、ギルドで成立した延長時間、訓練で幸運によってスタミナ消費が減った成功回数。

ラン用だけに、特定できた討伐者Heroごとの敵種別討伐回数と、その敵を倒した課題レベルの最高値を保持する。討伐者は最後のダメージを与えたHeroとする。炎の付与元Heroが分かる場合も含み、不明な攻撃者や敵同士の攻撃を推測しない。

Itemの全件履歴、戦闘ログの全件履歴、通算の討伐者別履歴は保存しない。

## 2. 保存と終了記録

メモリ上の集計は随時更新する。課題決定とゲーム終了の集計を反映した後に、共通DataManagerのゲーム名前空間へ保存する。

途中でページを閉じた場合、最後に保存が成功した時点までの累積集計が残る。終了履歴は作らず、途中のゲーム状態や再開データも保存しない。

試験合格・期限切れの終了記録には、ランID、開始・終了日時、モード、結果、到達ステージ、開始Hero、順序を保持した終了メンバー、経過ticks、残り期限、クリアー課題数、獲得貢献pt、敵討伐数、ラン内集計、アチーブメントの判定結果を保持する。

終了履歴は最新50件を保持する。終了済み試験数、合格・不合格回数、終了ランの獲得ptの合計と最高値、記録された初回・直近合格日時と合格回数は履歴上限で減らない。一般の累積集計には、途中ランの保存分も含まれるため、終了ランだけの統計と区別する。

終了通知と保存再試行では二重集計しない。保存失敗時もメモリ上の未保存データを保持し、保存処理の再呼び出しで二重集計しない。利用者向けの失敗表示・再試行操作は後続のUIブランチで扱う。

既存の解放状況、クリアーフラグ、設定、言語、チュートリアルを維持する。旧クリアーフラグから日時・回数・成績を生成しない。記録導入前の初回合格日時は不明として保持する。

## 3. ランキング

ランキングはアチーブメントから独立して、ゲーム終了時に終了結果を登録する。

| モード | 順位基準 |
| --- | --- |
| 試験 | 残り期限、討伐数、獲得貢献pt |
| チャレンジ | クリアー課題数、経過時間、討伐数、獲得貢献pt |

各値は大きい方が上位。同順位は終了時刻が新しい方を上位とする。試験不合格の残り期限は0とし、不合格同士の残り期限の順位はクリアー課題数を比較する。

基準ごとに上位N件、Nは定数で10件とする。全基準の上位N件の和集合を保持し、どの基準にも入らないランキングデータは破棄する。独立した直近50件の終了履歴はこの削除の影響を受けない。

チャレンジの集計・順位定義は用意するが、チャレンジのゲーム進行は今回実装しない。

## 4. 判定と後続作業

今回の範囲は基礎情報の収集・保存、アチーブメント定義・評価・差分判定、ランキングの収集・順位付け・保持・保存とする。アチーブメントの最新仕様は14.achievements.mdを参照する。ゲーム終了情報を値として渡し、グレード更新をコールバックで受け取れる接続を用意する。

トースト、レコード画面（アチーブメント・ランキング）、終了画面への表示追加、共通CSS・DOM生成は対象外。終了画面のデザインを先に確定した後、UIを別ブランチで実装する。合意した表示仕様・所見は後続用に保持する。表示件数上限等のUI上の未決定事項は今回の完了条件に含めない。

試験合格時の二つ名選定・表示は、正式な合格通知の実装時に扱う。今回のブランチでは判定材料を収集して結果へ渡すまでとする。
