# Hero・Item操作と倉庫エリア

## 1. 画面構成

倉庫・戦闘・ショップ・ギルド・訓練エリアは、対応する `public/assets/background/<area>.png` をエリア内でrepeat表示する。これらのエリア枠と名称ラベルは描画しない。開発確認用のHeroスロット表示は残す。

倉庫へ新規に追加・返却するItemは、共通の倉庫追加処理を通してチップを上方から落下させる。

ゲーム画面は以下の6エリアで構成する。

- 倉庫エリア: 画面中央。Itemが存在する。
- 準備エリア: 画面左。4人分のHero準備領域を持つ。
- 戦闘エリア: 倉庫の上。
- ショップエリア: 画面右上。
- ギルドエリア: ショップの下。
- 訓練エリア: ギルドの下。

Heroはすべてのエリアをシームレスに移動できる。
現在のアプリは全エリアの配置・移動を検証するデモシナリオを起動している。ランダム生成や確認用ガイド以外のチップ・Hero・Item・移動・時間進行はゲーム仕様として実装する。

倉庫エリアは枠線・ラベルを描画せず、`public/assets/background/warehouse.png` をエリア範囲内で繰り返し描画する。

## エリアテーマ

各エリアのテーマ色は、Heroチップのベース色、エリア・スロットの補助表示、行き先Itemのベース色に用いる。

- 準備: 青 `#3b82f6`
- 倉庫: スレート `#64748b`
- 戦闘: 赤 `#d66060`
- ショップ: 琥珀 `#c48a38`
- ギルド: 紫 `#8767b5`
- 訓練: 緑 `#4e9a72`

Heroは移動先エリアまたは滞在中エリアのテーマ色をチップのベース色に用いる。準備エリアでは準備色を使い、スタミナ3以上では低速スイングで出発可能を表現する。選択中のHeroは基点枠で表現するため、選択状態専用の高速スイングは用いない。行き先Itemは対応施設のテーマ色をチップのベース色に用い、準備エリアの装備スロットへ表示した場合もスロット背景を同じ色にする。

ゲーム空間はビューポートに依存しない固定ワールド座標とし、各エリアの座標・サイズは基本定数から派生計算する。初期の gap はすべて 32px とする。

- 戦闘: `x=632, y=0, width=1344, height=608`
- 準備: `x=0, y=640, width=600, height=1120`
- 倉庫: `x=632, y=640, width=1344, height=1120`
- ショップ: `x=2008, y=640, width=600, height=416`
- ギルド: `x=2008, y=1088, width=600, height=320`
- 訓練: `x=2008, y=1440, width=600, height=320`

サイズ関係は、`準備エリア高 = 準備サブエリア高 x 4 + 準備サブエリア間 gap x 3`、`準備エリア高 = 倉庫エリア高 = ショップ高 + ギルド高 + 訓練高 + 右エリア間 gap x 2` とする。戦闘エリア幅は倉庫エリア幅と等しくする。倉庫と準備・戦闘・右列の間には倉庫周囲 gap を置く。

### 1.1 戦闘エリア

戦闘エリアは内部的に上下2陣営へ分ける。セパレータは描画しない。

```text
敵 敵 敵 敵 敵 敵
□ 自 自 自 自 □
```

- 敵陣営の高さはHeroチップ直径192pxの2体分（384px）とする。敵スロットは中央ラインに横6個置き、中敵（192px）の上下には各96pxの余白を取る。
- 敵キャラクターのチップ直径は小128px・中192px・大384pxを想定する。大敵は横2スロットを占有し、中央の敵配置ラインから上下へ0.5体分ずつ張り出す。よって大敵のみの場合は最大3体置ける。
- 味方陣営は同寸の味方スロットを横4個、敵陣営の2〜5列目に相当する位置へ中央寄せで置く。
- Heroスロットはチップ直径192pxに四辺16pxの余白を加えた224px四方とする。
- `trampled-ground.png` をrepeatせず、敵6枠・味方4枠の各224px四方へ1枚ずつ、戦闘背景の上に描画する。

### 1.2 ショップ・ギルド・訓練エリア

ショップは、客側336px・将来のカウンター用64px・店側200pxに分ける。店側は地面印字の情報パネルとし、`SALE FOR` とその下の今回販売タグアイコン、`NEXT SALE` とその下の次々回販売タグアイコンを縦に表示する。内部データではそれぞれ次回・次々回の販売傾向だが、UI上は現在の販売内容として表示する。客側ではHeroスロットを上寄せにし、その直下12pxに枠なしの袋アイコンと、準備エリアの装備スロットと同じ表現の中身3枠を横並びにする。

各エリアは内部的に左右2分割する。分割線は描画しない。ショップ・ギルド・訓練の色付きスロット枠は配置確認のためのデモ専用ガイドであり、最終UIではない。

- 左エリアの中央に、Heroチップと同寸のHero用スロットを1つ置く。
- 右エリアの具体的なUIは今後定義する。
- 現在の色付きスロット枠は配置確認のためのデモ専用ガイドである。

準備エリアは縦4等分のサブエリア（各600 x 256）で構成する。各サブエリアは、左に職業・和名・6行ステータス、中央にキャラクター印字、右に3 x 3装備グリッドを置く。装備グリッドの配置は、上段中央が頭、中段が右手・胴・左手、下段中央が足である。装備Item画像はスロット下端へ寄せ、画像サイズは従来のまま維持する。Itemタグは画像の上に最大3個重ねて表示する。タグ一覧は、キャラクター印字下の空きと装備グリッド左側の空きに15列のタグバッジ（アイコン／数量）として置き、未所持タグも数量0で表示する。Heroチップは未装備中である準備時には装備グリッド上に置く。ステータスは名前とゲージを横並びにし、上下中心を揃える。ゲージは将来値7まで表示できる7枠を確保するが、点灯・消灯の対象は各ステータスの現在MAX（初期値3）までとし、残りは未解放として表示する。ゲーム・デモともにスタミナ初期値は0とする。

準備サブエリアは、将来のHero・Enemy共通の情報カードの基礎とする。情報の識別性を優先して表示を見直す際、現在の要素寸法・固定px数は維持条件としない。ただし、可読性のために必要以上に大型化してゲーム画面全体の視認性を損なわないよう、情報密度との均衡を取る。

職業と名前は1対1に対応する。剣士:Avery（アヴェリー）、衛兵:Briar（ブライアー）、魔法使い:Casey（ケイシー）、僧侶:Darcy（ダーシー）、盗賊:Ellis（エリス）、狩人:Finley（フィンリー）、商人:Garnet（ガーネット）、交渉人:Harper（ハーパー）。

タグスキルはタグ1個から最初のスキルが発動する。表示上は最大10個のスキルを扱う。

カメラは設定上の最小ズームと、ワールド全体が縦横ともに収まるズームのうち大きい方より縮小できない。
縦または横の一方でワールド全体が収まる場合、その軸は中央寄せで表示する。

ゲームは一時停止と、x1／x2／x4の速度切替を持つ。一時停止中も描画とカメラ操作は継続し、チップ物理・移動・取得アニメーションなどのゲーム状態更新のみ停止する。

準備エリアに滞在するHeroは、ゲーム時間1/60秒ごとにスタミナを0.005回復する。通常速度では約3.33秒で+1、スタミナ3までは約10秒とする。ゲーム・デモともに開始スタミナは0とする。

## 1.1 Chipの移動可能範囲

各Chipは移動可能な矩形範囲を指定できる。

- 指定された場合、落下、衝突、重なり解消、移動のすべてで、その矩形外へ出ない。
- 未指定の場合、固定ワールド全体を移動可能範囲とする。
- 実際のゲームでは、Chipごとに状況に応じた移動可能範囲を指定する。
- 倉庫Itemは倉庫エリアを移動可能範囲として指定する。
- Heroは状況に応じて、ワールド全体または特定エリアを移動可能範囲として指定する。
- HeroがItemの取得へ向かい始めるときは、Heroの移動可能範囲を未指定（ワールド全体）へ戻す。

## 2. Hero

Heroは職業に対応する固定タグ2個を持つ。
HeroはゲームルールのデータとCanvas描画用Chipを保持する。

### 2.1 ステータス

Heroは以下のプロパティを持つ。

- パワー、魔力、スピード、交渉力、運
- 各ステータスのMAX値
- スタミナ

各値は内部的に実数で管理する。
各ステータスMAXとスタミナは、デフォルト値3、最大値7とする。

ステータスは対応するステータス系タグの個数から計算する。

```text
パワー = min(パワーMAX, max(武勇タグ数, 鉄タグ数))
魔力 = min(魔力MAX, max(魔導タグ数, 布タグ数))
スピード = min(スピードMAX, max(軽業タグ数, 羽タグ数))
交渉力 = min(交渉力MAX, max(信用タグ数, 宝石タグ数))
運 = min(運MAX, max(加護タグ数, 幸運タグ数))
```

## 3. Item

Itemは付与タグ、価格、単体重量、装備部位に対応するアセット、Canvas描画用Chipを保持する。

### 3.1 タグ

タグはステータス系10種と属性系5種の合計15種である。

- Itemのタグ数は0〜3個。
- ステータス系タグは最大2個。
- ステータス系タグを2個付与する場合は同種タグを2個にする。
- 属性系タグは最大2個。
- 属性系タグを2個付与する場合は同種・異種のどちらでもよい。

Item重量は付与タグ重量の合計とする。
タグなしItemの単体重量は1、価格は1とする。

### 3.2 装備部位

アセット名の接頭辞で装備部位を表す。

- `head-*`: 頭
- `torso-*`: 胴
- `hand-*`: 手
- `feet-*`: 脚

Heroの装備スロットは頭、胴、右手、左手、脚の5か所とする。
HeroがItemを装備すると、ItemのタグはHeroのステータスおよび重量計算へ即時に加える。
タグなしItemはHeroへタグ重量を加算しない。

頭・胴・脚Itemの表示名は画像番号で固定し、タグや職業によって変えない。将来のi18nでは以下の日本語・英語をそれぞれの `type` の表示名として用いる。

| type | 日本語 | English |
|---|---|---|
| `head-1` | 兜 | Helmet |
| `head-2` | とんがり帽 | Pointed Hat |
| `head-3` | フード | Hood |
| `head-4` | 冠 | Crown |
| `head-5` | 羽根帽 | Feathered Hat |
| `torso-1` | 鎧 | Armor |
| `torso-2` | ローブ | Robe |
| `torso-3` | ベスト | Vest |
| `torso-4` | ジャケット | Jacket |
| `torso-5` | コート | Coat |
| `feet-1` | グリーヴ | Greaves |
| `feet-2` | ブーツ | Boots |
| `feet-3` | シューズ | Shoes |
| `feet-4` | ローファー | Loafers |
| `feet-5` | ファーブーツ | Fur Boots |

### 3.3 手Item

武器は左右いずれの手にも装備できる。
行き先指定Itemは、左右の手を合わせて最大1個だけ装備できる。
行き先指定Itemを装備しない状態は許可する。

行き先指定Itemは以下の3種とする。

- `hand-shopping-bag`: ショップ
- `hand-hero-license`: 訓練場
- `hand-renewal-form`: ギルド

行き先指定Itemにはタグを付与しない。

### 3.4 Shopping bag

`shopping-bag` は最大3個の通常Itemを保持できる特別な行き先Itemである。行き先Itemは袋へ格納できない。基点が通常Item、終点が格納可能な袋である選択を確定すると、Itemは袋チップの中心へ縮小しながら吸収され、完了時に盤面から消える。袋から取り出せない。袋は所持数を `n/3` でチップ上に表示する。

## 4. 共通チップ選択UI

すべてのChipは選択の基点になれる。基点はドラッグ開始またはタップで選択する。選択中は基点からポインタ位置へ点線を描き、基点には選択枠を描く。

- ドラッグ操作では、ポインタを離したときに終点を確定する。タップ操作では終点Chipをタップしたときに確定する。
- ポインタ位置が基点以外のChipに重なる場合、組み合わせが有効なら終点枠と点線を緑、無効なら赤で表示する。Chip以外を指す場合は中立色で表示する。
- 確定後のゲーム処理は基点・終点の組み合わせごとに定義する。終点がChip以外、または基点・終点の組み合わせが無効な場合、赤い点線を示したうえで基点選択を解除する。

## 5. HeroとItemの選択

Heroは基本的に待機エリアに存在する。準備エリアにいてスタミナ3以上のHeroを基点に、Itemを終点として確定すると、Item取得への移動を開始する。出発時に選択できるItemは、スタミナに関わらず常に1個とする。スタミナ3未満のHeroはこの組み合わせを確定できない。

## 6. 指定Itemへの移動と拾得

Item選択が完了すると、アクティブなHeroは選択Itemへ移動を開始する。

- Heroの目的地は固定座標ではなく指定Itemそのものとする。
- Itemが他のチップとの衝突で移動しても、Heroは対象Itemの現在位置を追跡する。
- 複数Heroは同時にそれぞれのItemへ移動できる。
- 他Heroに拾われるなどして目的Itemが盤面から消えた場合、Heroは次に装備可能な最寄りのItemへ目標を切り替える。
- Heroと目的Itemが重なった時点で、HeroはItemを拾う。
- 拾われたItemは倉庫から消える。
- 指定Itemが2個ある場合、Heroは1個目を拾った後に2個目へ移動して拾う。

## 7. 自動装備探索

指定Itemをすべて拾った後、Heroは未装備スロットに対応するItemを倉庫内から探索する。

- 対応Itemが複数ある場合、最も近いItemを目的Itemにする。
- Heroは目的Itemを追跡し、重なった時点で拾う。
- 拾得後、残る未装備スロットに対して探索を繰り返す。
- 全5スロットを装備した場合、または未装備スロットに対応するItemが倉庫にない場合は、行き先スロットへ移動する。

## 8. 装備完了後の行き先スロット

自動装備探索を終えたHeroは停止せず、装備状態から行き先スロットを決めて移動する。

- `shopping-bag` を装備している場合: ショップのHeroスロット
- `renewal-form` を装備している場合: ギルドのHeroスロット
- `hero-license` を装備している場合: 訓練のHeroスロット
- 行き先指定Itemを装備していない場合: 戦闘の味方スロット

戦闘の味方スロットは、画面上の左から1〜4番として、`2 → 3 → 1 → 4` の優先順で選ぶ。スロット選択時は、占有されているスロットだけでなく、他Heroの予約済みスロットも利用不可とする。

Heroはスロットへ移動中は `targetSlotId`、到着後は `currentSlotId` を保持する。到着時に予約を占有へ移し、`targetSlotId` は `null` にする。
到着後のHeroの移動可能範囲は、そのスロット矩形（224px四方）に制限する。

Itemチップは直径75pxとし、チップ中央画像は描画倍率85%により63.75pxで描画する。これは準備エリアの装備Item画像64pxとほぼ同じ大きさである。

## 9. Heroの重量と段階移動

Heroは装備Item由来のタグ重量合計を所持重量として扱う。職業由来のタグ重量は所持重量に含めない。所持重量により、1回の「ズッ」の移動量を線形に決める。

```text
重量0時の移動量: 96px
重量基準値: 25
移動量 = 96 / (1 + (所持重量 / 25)^2)
```

各「ズッ」は0.38秒で、前半で進み後半で止まる。Item追跡およびスロット移動では、各「ズッ」の完了後に目標の現在位置を読み直して次の移動方向を決定する。

## 10. ショップでの売買

`shopping-bag` を装備してショップへ到着したHeroは、袋の中身を売却し、頭・右手・胴・左手・脚の5部位セットを2組購入して帰還する。各セットは販売傾向を必ず1つ含む3タグ候補を独立して抽選する。購入結果は到着から100 tickごとに1つずつ表示し、500 tickで1セット目の5品すべてを表示する。600 tickで1セット目の購入品5個を倉庫へ落下追加する。2セット目は700〜1100 tickで表示し、1200 tickで2セット目の5個を倉庫へ落下追加して帰還を開始する。購入結果グリッドは上段=頭、中段=右手・胴・左手、下段=脚とする。tickはゲーム時間で計測するため、停止中は進行せず、速度倍率の影響を受ける。袋の中身は2セット目の配送時に消費され、取り出せない。ショップから帰還を開始する時点でHeroのスタミナは0になる。

- 売却額は袋内Itemの `price` 合計とする。タグ単価は `10 - 交渉力`、購入セットのタグ数は `max(5, min(15, 5 + floor(売却額 / タグ単価)))` とする。
- 決定したタグ数を各部位へランダムに割り振り、各部位は最大3タグとする。
- 商品候補タグは、現在の販売傾向タグを必ず1つ含む、通常のタグ付与パターンに従う3タグとして先に生成する。各部位のタグ数決定後、その候補の3枠から非復元抽選する。武器は既存の武器タグ制約に従う。
- 宝石タグのタグスキル「購入品強化」は、所持数により最高発動レベルを決める。Lv1「掘り出し物」（宝石1〜2）は運判定1回、Lv3「目利き」（3〜4）は2回、Lv5「秘蔵の鑑定眼」（5〜6）は3回、Lv7「黄金の審美眼」（7以上）は4回行う。各部位について1回でも成功した場合、そのItemの隠れた能力を見抜き、タグ数を1増やす（上限3）。直前レベルのスキルは継続して発動しているが、この処理では最高発動レベルに対応する判定回数を用いる。
- 購入した5Itemは、倉庫内の互いに近い位置へ新規追加と同じ落下アニメーションで配置する。
- 購入後、販売傾向は「次回」を現在の販売へ繰り上げ、新しい次回傾向を追加する。Heroは施設共通の帰還処理で準備エリアへ戻る。
- 宝石タグの運判定でタグ数が増えたItemを表示する時は、`職業・名前は買った部位名の隠れた能力を見つけた。` を `fortune` ログとして通知する。
