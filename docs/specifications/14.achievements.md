# アチーブメント

## 実装範囲（確定）

基礎情報の収集・保存、アチーブメントの定義・評価・差分判定、ランキングの収集・順位付け・保持・保存に加え、試験終了画面の成績表示、取得トーストと共通CSS・DOM生成を実装済み。レコード画面は勇者認定試験ランキング・アチーブメント・課題記録の3タブを実装済みで、アチーブメントは未達成を含め全件表示する。閲覧仕様は[レコード仕様](16.run_records.md)を正本とする。

終了画面はオーナー承認済みの通知表形式で、表示上限は10件。共通表示部品は終了画面から利用し、後続画面へ向けた表示モードの境界を備える。選定と表示の責務は分離する。詳細は17.trial_result_screen.mdを参照する。

## 検討と記録の方針（確定）

収集・集計する情報と、アチーブメントの名称・達成条件を分けて設計する。収集する情報は、複数のアチーブメントの判定材料として利用する。

まず情報のカテゴリーを整理し、集計を担当するコンポーネント、その責務、フックの設置場所と呼び出し方を検討する。個別の集計処理をソースへ追加する前に、この収集・集計の設計を定める。

本書の状態区分は「検討中」「確定」の2つとする。仮決定した内容も確定として記録し、見直しが決まった時点で更新する。「確定」は実装済みを意味しない。

## 収集する情報のカテゴリー（確定）

### ラン開始（確定）

- 開始Heroの組合せごとの試験開始回数・合格回数・不合格回数・チャレンジ開始回数。不合格は試験が不合格として終了した回数であり、途中離脱は含めない。
- 初期Heroの組合せは順不同の全28パターンを個別に集計する。

### ラン結果

ラン結果のランキングはアチーブメントとは別に、ゲーム終了時に集計する。ランキングの保持・削除はアチーブメント判定に影響しない。

複数の順位基準でそれぞれ上位N件を保持する。Nは定数とし、現時点では10件とする。最新の終了結果を追加し、各基準の上位N件の和集合を保持する。どの基準でも上位N件に入らない結果は破棄する。

順位基準は次のとおり確定している。各基準は値が大きいほど上位、同順位なら終了日時が新しい方を上位とする。

- 試験：合格時の残り時間、討伐数、獲得貢献ポイント。残り時間で不合格を比較するときは残り時間0とし、クリアー課題数が多い方を上位とする。
- チャレンジ：クリアー課題数、経過時間、討伐数、獲得貢献ポイント。

| モード | 結果に含める情報の案 |
| --- | --- |
| 試験 | 合格／不合格、合格時の残り期限、累積貢献ポイント、敵討伐数、各施設利用回数、終了時メンバー |
| チャレンジ | クリアー課題数、継続時間、累積貢献ポイント、敵討伐数、各施設利用回数、終了時メンバー |

### 施設利用（確定）

- 試験場（戦闘エリア）を含む出発回数。
- 利用したHero。
- 出発が確定した時点、すなわち行き先に応じてチップに色を着けるタイミングで数える。到着や利用完了では数えない。
- ギルドで実際に消費した貢献ポイントを、今回のランと累積の両方で集計する。消費が成立した時点の実消費量を加算する。

### 戦闘

- 敵ごとの討伐回数。
- 累積で獲得した貢献ポイント。
- 通算の討伐者別カウントは行わない。特定できるHeroの討伐者情報は、今回のラン内の情報として別途収集する。

### キャラクター（確定）

- 各タグの最高タグ数。
- Hero本体と装備のタグを合わせた数を使用し、能力上限を反映しない。

## 収集範囲の補足（確定）

- 終了時メンバーは `[初期1, 初期2, 追加1, 追加2]` の順序を保持する。途中加入はこの配列から読み取れるため、独立した収集項目を設けない。
- Itemの詳細な入手・消費履歴は収集対象に含めない。Hero別・武器種類別の装備回数を収集する。
- キャラクターカテゴリーの各タグの最高タグ数は、Hero個別に集計する。

## 課題ごとの集計（確定）

課題ごとに次の3項目を保持する。

| 項目 | 意味 |
| --- | --- |
| 挑戦回数 | その課題にチャレンジした回数 |
| クリアー回数 | その課題をクリアーした回数 |
| クリアーした最高レベル | その課題でクリアーしたレベルの最大値 |

課題レベルはクリアーした最高値として保持する。レベルごとの回数や、挑戦のたびの履歴を保持する方式は採用しない。

課題の識別は種類と構成indexの組を使用する。構成配列はregular・elite・boss別に保持され、indexは0始まりとする。構成配列の並べ替えでは既存集計の識別を維持するための移行を必要とする。

## 集計とアチーブメントの責務（確定）

- 集計クラスは情報の収集・集計を担当し、累積の集計と今回のランだけに閉じた集計を扱う。
- アチーブメントクラスは、渡された集計状態から各アチーブメントの達成グレードを判定する。達成／未達成の2値だけでは扱わない。
- 累積の差分判定は、アチーブメントクラスへ現在の集計情報と前回の達成グレード表を渡し、現時点の達成グレード表と上昇した項目を求める。前回表を省略した場合は空ハッシュとして扱う。初めての達成も上昇に含む。
- 比較用に保持するのはアチーブメントIDごとのグレード表であり、集計クラスに差分比較用のsnapshotは設けない。
- 今回のランの集計もアチーブメントクラスで評価し、そのランだけで達成したグレードを求める。
- フックは中間クラス（StatisticsCollector）を呼び、中間クラスが今回のラン用・累積用の2つの集計インスタンスへ配信する。累積もゲーム中に随時更新する。
- イベントから集計値への変換を中間クラスで行うか集計クラスで行うかは、処理コストに応じて決めるため検討中とする。
- Collectorは初期化時に渡された累積集計をアチーブメントクラスで評価し、ラン開始前のグレード表と、ラン中の比較用グレード表を保持する。ラン中の差分判定の呼び出しと比較用グレード表の更新もCollectorが担当する。グレードの計算自体はアチーブメントクラスが担当する。

## ゲーム中の達成通知（確定）

ゲーム中にアチーブメントの達成グレードが上がったとき、トーストを表示する。トースト表示の責務は、集計クラス・アチーブメントクラスから分離する。

集計クラスは収集・集計、アチーブメントクラスは達成グレードと差分の判定を担当し、トースト表示の責務を持たない。

通知はAchievementToastが担当し、右下に見出しと評価項目名・達成判定のテーブルを表示する。各行は旧判定から最新判定へ変化し、個別に表示時間を管理する。表示と演出の詳細は[取得トースト仕様](18.achievement_toast.md)を参照する。

## 結果画面に表示する達成（確定）

表示する判定・所見には、今回のラン終了後の累積達成グレードを使用する。今回のランだけのグレードを表示する旧方式は採用しない。

ラン開始前と終了後を比較して累積の整数達成グレードが上がった項目（初回達成を含む）を優先して採用する。更新ありを優先し、更新・非更新のそれぞれで累積G値の増加量（deltaG）が大きい順、終了後の累積G値（G）が0以外で小さい順、G値0、定義順の順に選定する。後ろのキーは前のキーが同じ場合だけ使用し、グレードの上昇段階数は比較しない。開始イベント・初期メンバーのタグ記録より前に全項目のG値を保持し、整数化前・上限制限前の値で差を計算する。

G値が1以上であるという候補条件は設けない。累積で未達成の項目も表示対象になり得る。今回ラン単独のG値は選定に使わず、同じ項目を重複採用しない。更新項目だけで上限を超える場合も、同じキーで上限まで採用する。

採用する項目の選定と表示順は分離する。選定後は、グレード更新の有無にかかわらず全体をアチーブメントの定義順に表示する。G値の大小によって表示を並べ替えない。

表示件数の上限は10件。選定後の表示順はアチーブメントの定義順とする。

## 共通の表示形式（確定）

試験モードの成績ページのタイトルは「成績表」とする。通知ページと同じ紙の質感を持つ通知表の内側のページとして、中央に成績の表を配置する。

取得時のトースト、ゲーム終了画面、レコード画面で共通実装を使用する。見た目はカードではなく、通信簿のテーブル形式とする。

| 表示場所 | エントリ数 | 表示する項目 |
| --- | --- | --- |
| トースト | 表示高さに収まる複数行 | 評価項目・判定 |
| ゲーム終了画面 | 上限ありの複数 | カテゴリ・評価項目・判定・所見。条件は記載しない |
| レコード画面 | 全エントリ | カテゴリ・評価項目・判定・判定基準・達成度。次評価に必要な値への進捗を表示する |

CSSは共通とし、DOM生成も共通処理へ表示モードとエントリ一覧を渡し、モードに応じて構成を切り替える。終了画面用の選定はDOM生成の外で行う。DOM生成は、受け取った表示対象の一覧を描画する。

カテゴリ順に並んだ実際の表示エントリから、同じカテゴリの連続行を動的にまとめる。カテゴリセルのrowspanはその一覧での行数から計算する。終了画面は選定後の一覧、レコード画面は全一覧に対して処理する。カテゴリのないトーストではセル結合を行わない。

終了画面には到達度の独立した表示欄を設けず、レコード画面には次評価までの達成度を表示する。通常項目はD−〜S＋の15段階、タグはD・C・B・A・A＋・S・S＋の7段階とする。

評価項目は評価対象を簡潔に示す。判定は最高位からS、A、B、C…の順に割り当てる。通常項目はD−・D・D＋、C−・C・C＋、B−・B・B＋、A−・A・A＋、S−・S・S＋。タグはD・C・B・A・A＋・S・S＋。1段階の定義も扱える構成とする。ゲーム終了画面で累積整数グレードが0の項目を表示する場合、判定はEとし、未達成用の所見を表示する。Eは追加の達成グレードではない。

所見は先生が生徒にコメントするイメージで、成果・成長を評する文章にする。断定的な称号ではなく、「〜に成長したようですね」などの語りかけを使う。E評価の所見は全項目で共通のコメントを使用し、個別定義には持たせない。共通コメントは「もっと頑張りましょう」とする（確定）。B・A・Sの所見は従来のアチーブメント名称から個別に見直す。評価項目名と所見は後述の一覧で確定。終了画面の装飾・レイアウトはオーナー承認済みの通知表形式とする。

## アチーブメント条件と集計機能の拡張方針（確定）

現時点では複合条件のアチーブメントを作成しない。既存の集計値の合算・最大値は定義側の `func` で求め、派生値を集計項目として追加しない。将来、既存の集計値では判定できない条件を追加する場合は、必要な情報を集計機能へ追加する。

## モードと保存タイミング（確定）

一般の集計（施設利用、敵討伐、獲得貢献pt、Heroのタグ最高値、課題の集計）はモードを分けず共通に保持する。ラン開始・合格回数やラン結果に必要なモードの区別とは分けて扱う。

累積集計は課題決定時とゲーム終了時に永続保存する。課題決定時には決定した課題の挑戦を集計へ反映してから保存し、ゲーム終了時には終了に伴う集計を反映してから保存する。ゲーム中のメモリ上の集計は引き続き随時更新する。

途中離脱時には最後に成功した保存時点までの累積集計が残り、その後の未保存分は残らない。途中ランの終了結果や再開可能なゲーム状態は作成しない。

## ラン内の討伐者情報（確定）

敵へ最後のダメージを与えたHeroを、特定できる場合だけ討伐者として扱う。直接攻撃のほか、炎の継続ダメージで付与元Heroが分かる場合も対象とする。攻撃者不明や敵同士の攻撃をHeroの討伐として推測しない。

今回のランに限り、討伐者Hero IDと倒した敵の情報を収集し、ゲーム終了画面から参照できる終了情報へ渡す。通算の討伐者別履歴カウントは追加しない。Hero別・敵種別の討伐回数と討伐時の最高課題レベルを保持する。

試験合格時にギルドが終了メンバーへ二つ名を与える処理と、正式な合格通知での表示は実装済み。選定・展開・表示の正本は[試験終了画面仕様](17.trial_result_screen.md)とする。

二つ名は今回ランのHero別情報から選定し、アチーブメントのグレード判定から独立させる。本番語句の正本はpublic/data/epithet.jsonとする。

### Hero別の終了時参照情報（確定）

二つ名の判定材料として、今回のランのHero別情報を終了画面から参照できるようにする。

| 情報 | 集計内容 |
| --- | --- |
| 討伐 | 特定できた討伐者Heroごとの敵種別討伐回数・討伐時の最高課題レベル |
| 武器装備 | Heroごとの武器種類別装備回数 |

討伐者別の回数は今回のラン内で参照するための集約であり、通算の討伐者別カウント・全件の討伐履歴を要求するものではない。

武器装備回数は試験場への出発が確定した時点で、装備した武器1個ごとに1回を加算する。他の施設へ向かうときの装備は対象外とする。同じ武器の再装備はゲーム仕様上発生しない。

### 施設での詳細情報（確定）

- ショップ：Heroごとの宝石タグスキルによって追加されたタグ数。
- ギルド：Heroごとの延長時間。
- 訓練：Heroごとの幸運によってスタミナ消費が減った回数。単なる訓練実行回数とは区別する。

これらの情報をHero別に収集する。

## アチーブメント定義とグレード計算（確定）

### 段階テーブルと表示リソース（確定）

定義は適用する段階テーブルを参照する。共通の段階構成はテーブルを共有し、必要な項目だけ専用テーブルを持つ。判定クラスは高い段階からG値の条件を調べ、最初に条件を満たした行を採用する。

各行は段階の開始G値、判定表示、所見番号comment、通知段階noticeを持つ。commentとnoticeはそのアチーブメント内の番号であり、全体の通し番号ではない。共通テーブルでも参照元の定義に対して解釈する。noticeが前回より上がった場合を通知対象とし、表示段階の上昇と通知の節目は分ける。

敵・タグの定義はJS内で対象ごとに展開する。共通所見テンプレートに各言語の敵名、段階ごとに異なるタグスキル名を差し込み、言語別の評価項目・条件・所見の完成済みリソースを定義に持たせる。表示側は現在の言語と所見番号で完成文を取得し、敵・タグ別の差し込み処理を行わない。Eの共通所見も言語別リソースとして扱う。

通常項目は最高位の開始G値s=15、段階数15、開始G値は1〜15。所見番号はD/Cが1、B/Aが2、Sが3。通知は−／無印／＋を含む15段階。タグは最高位の開始G値s=3を維持し、段階数7、開始G値0・0.5・1・1.5・2・2.5・3、判定D・C・B・A・A＋・S・S＋とする。タグの所見番号は順に1・1・2・2・3・3・4、通知は7段階。未達成はEとし、一度に複数段階を越えた場合は最終到達段階だけ通知する。

定義は判定処理から分離したJSモジュールで管理する。IDを識別・差分比較のキーとし、次の情報を持つ。

- 計算に使う値pの取得方法：集計項目の参照、合算、最大値など。
- グレード式G(p)。
- 段階テーブルと最高位の開始G値s（段階数はテーブル行数）。
- 表示用の評価項目と、整数グレードごとの所見。

段階数は定義ごとに可変とする。68種類のうち通常58種類を15段階、タグ10種類を7段階とする。

### 連続評価値と整数達成グレード

G(p)は連続評価値。G値以上ではない開始G値を持つ最上位の行を選び、その行番号を整数達成グレードとする。0は未達成。通常はfloor(G)を0〜15へ制限した値と一致する。タグはG値の整数化ではなく7行の段階テーブルで判定する。未記録は未達成とし、記録された0とは区別する。

グレード上昇・判定・所見には整数達成グレードを使う。取得通知は対応する通知段階の上昇で判定する。終了画面の表示対象選定には、整数化前・上限制限前の累積G値の増加量と終了後の累積G値を使う。G値自体の上昇だけではグレード更新とは扱わない。

### 共通の基本式

最高位の目標実績をt、最高位の開始G値をsとして、タグ以外は次の式を使う。

`G(p) = sqrt(p / t) × s`

通常項目はs=15。最上位S＋の到達値tを維持する。整数pでG=kに到達する条件は `p >= ceil(t × (k/15)^2)`。離散的な集計値では、1回の更新で複数段階を越える場合がある。

課題クリアーもこの共通式に合わせる。「最初の課題クリアー」を独立した達成点にする旧方針は採用しない。

### タグの式

`G(p) = (p − 1) / 2`

式は維持し、p=0はE、p=1〜7を順にD・C・B・A・A＋・S・S＋とする。7個以上はS＋だが、選定用G値は上限で切らない。pは装備込みで全Heroに記録された対象タグ最高数の最大値であり、累計獲得個数ではない。
