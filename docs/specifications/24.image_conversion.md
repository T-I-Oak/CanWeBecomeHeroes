# 配信用画像の生成

## 制作元・定義・公開ファイル

制作元は `assets/images/source/` に保持する。画像パス `/assets/heroes/guard.png` に対して
制作元は `assets/images/source/heroes/guard.png`、配信用は `public/assets/heroes/guard.png` となる。
既存の配信用画像113枚を縮小前のバイト列のまま制作元として保存した。
敵の未正規化原画は従来の `assets/enemies/source/` にも保持する。

`assets/image-sizes.json` は画像ごとの配信用長辺 `size` と、制作元の `sourceSha256` を定義する。
アプリはこの定義や制作元を読み込まない。配信用画像の実寸と生成済みマニフェストだけを使う。
サイズ定義と制作元が一致しない場合は変換前にエラーとし、意図しない制作元変更を見逃さない。

## 変換

プロジェクトルートで `npm.cmd run generate:images` を実行する。
互換用の `generate:image-levels` も同じコンバーターを実行する。
PlaywrightとChromeを使い、`IMAGE_LEVELS_CHANNEL=chromium` で付属ブラウザーも選べる。

1. 全画像のパス・サイズ・制作元ハッシュ・拡大不要であることを事前検証する。
2. 制作元から高品質縮小で配信用PNGを生成する。寸法変更不要なら制作元をバイト列のままコピーする。
3. 配信用サイズ未満の8・16・32・64・128・256・512・1024pxの段階を制作元から直接生成する。
4. 配信用PNGのハッシュを段階画像名に付け、実寸とパスを `src/chips/image-levels.json` に記録する。
5. 旧ハッシュ・旧サイズの生成済み段階画像を削除する。制作元と無関係のファイルは削除しない。

同一バイト列の出力は書き直さない。再生成時に不要なホットリロードやファイル書き込みを起こさない。
通常のbuild・実機上では変換しない。制作元・定義・配信用・段階画像・マニフェストはGit追跡し、
公開されるのはpublicの画像とアプリに取り込まれたマニフェストだけとする。

## 配信用サイズの根拠

基準はDPR 3・最大camera zoom 1.5。選択画面・情報ウィンドウ・開始劇にも同じ図柄を使う。
元画像を超える表示は従来同様で、制作元以上の拡大生成は行わない。

| 図柄 | 配信用長辺 | 根拠 |
| --- | ---: | --- |
| 勇者 | 1024px | 通常最大734.4画素。情報・選択・演出でも共用 |
| 小型敵・分身 | 512px | 通常最大489.6画素。情報ヘッダー最大約224画素も含む |
| 中型・大型敵 | 1024px | 中型734.4画素、大型は制作元1024px以上に表示するため元解像度を維持 |
| タグ | 512px | 大型敵の図柄261.3画素、情報UIの拡大にも使用 |
| 看板・ステータス | 512px | 通常は看板198・ステータス108画素だが、情報UIは44CSS px×最大scale 2×DPR 3＝264画素 |
| アイテム | 256px | 既存制作元256pxを維持。最大装備欄は288画素で既存と同じ拡大 |
| 戦闘枠の地面 | 256px | 制作元256pxを維持。背景の画像密度は変更しない |

条件アイコン・属性・盾等の演出・タイル背景・外周背景・ロゴは今回の変換対象外。
生成対象一覧はサイズ定義を正本とする。PNGの縦横比・透明余白・図柄位置は保持する。
看板の安全領域比率など、描画上の比率定数は変えない。

## キャッシュ予算

通常画面の想定は勇者4種類、小型敵3・中型1・大型1、看板6、タグ15、ステータス7、アイテム28、地面1の計66種類。
現在のサイズ定義と生成済みマニフェストからRGBA寸法換算で集計する。

| 図柄 | 上位2段階の合計MiB |
| --- | ---: |
| 勇者 | 5 |
| 敵 | 3.4375 |
| 看板 | 1.875 |
| タグ | 4.6875 |
| ステータス | 2.1875 |
| アイテム | 2.1875 |
| 地面 | 0.078125 |
| 合計 | 19.453125 |

この66種類のさらに小さい全段階まで含めても20.74462890625MiBで、24MiB以内。
登録カタログ全種類を同時保持する予算ではなく、異なる職業・敵種への切り替えでは未使用画像を破棄する。
制作元・配信用画像・ブラウザーの追加保持メモリはこのキャッシュ予算とは別である。

## 更新と検証

画像を追加・変更するときは制作元とサイズ根拠を更新し、SHA-256を定義へ反映して再生成する。
制作元を配信用PNGから逆生成しない。サイズを変更しても制作元は同じファイルから作り直す。
敵の図柄正規化は `node scripts/normalize-enemy-art.js` が高解像度の制作元へ出力する。
その後、更新した制作元のハッシュをサイズ定義へ反映し、`generate:images` を実行する。

`ImageConversion.test.js` でパスの妥当性・縦横比・拡大拒否・制作元ハッシュ・全画像の寸法と段階を確認する。
`ScaledImage.test.js` で配信用画像のハッシュと段階PNGの実寸を照合する。
敵の図柄は既存のsafe-circle・輪郭サイズ契約でも検証する。
画像サイズ変更の見た目はブラウザーで確認する。テスト成功だけを実機での画質確認とは扱わない。
