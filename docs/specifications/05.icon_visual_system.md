# アイコン視覚システム

## 1. 目的

タグ、ステータス、属性エフェクトを、同じ意味の色・図柄・動きで関連付ける。
タグ図案は、最小の雑魚Chipで約27pxのタグ円盤、その内側で約19pxの図案として表示されても判読できなければならない。情報ウィンドウなどの大きな表示ではなく、この最小表示を設計と検査の基準にする。

## 2. タグアイコンの構成

タグアイコンは、共通円形フレーム、分類色ベース、タグ固有図柄を別レイヤーとして構成する。

- 共通円形フレーム: Canvas の円形描画（濃紺の外周と明るい内周線）
- 分類色ベース: 描画時に6分類の色で円盤を描く
- タグ固有図柄: 各タグの透過図柄レイヤー

共通円形フレームはすべてのタグで同一の描画式を使用する。タグ固有図柄は円盤・枠を含めず、外枠の中央に収める。描画順は「濃紺の外周 → 分類色ベース → タグ固有図柄 → 明るい内周線」とする。これにより、縮小時も枠の太さが揃い、生成時の個体差で装飾位置が揺れることを防ぐ。

## 3. タグ図案セットの設計制約

- タグ図柄のソースはすべて1024px四方・透明背景とする。円盤・枠・背景を含めない。
- 図案の専有面積は、ソース画像の画素数ではなく、実際に描画された分類色の円盤に対して評価する。最小の雑魚Chipで、図案の主シルエットと分類色の円盤面の両方を即座に認識できる大きさにする。図案が小さすぎて主題を読めない状態、および図案が円盤を埋めて分類色を読めない状態の、どちらも許可しない。
- 図案は、タグ名と結び付けられるひとつの太い主シルエットを持つピクトグラムとする。厳密な物の絵である必要はなく、月を魔導の手掛かりにするような象徴表現も使える。ただし、個別の図案だけを細密な物の絵にしたり、別の図案だけを抽象記号にしたりせず、全タグを同じ単純さ・線の太さ・描き込み密度で揃える。
- 図案セットは、太い濃紺の輪郭と二〜三枚の大きな色面で構成する、炎・水のようなイラスト化ピクトグラムの表現に揃える。色面は内側／外側、または波の層のように主シルエットを読み分ける目的だけで使う。面取り、反射、光沢、投影など、光源や材質を想像させる塗り分けは使わない。完全に平面的な記号、細密な物体イラスト、立体感を前面に出した図案を混在させない。
- 図案へ補助的な意味を加える場合も、主シルエットの内側へ収める。主シルエットから離れた星、粒子、軌跡などを足して意味を補わない。
- 図案は濃紺の輪郭を共通して持ち、主色には分類色ベースと明度・色相のいずれも近すぎない色を使う。背景が変わっても図案が読めることを優先し、分類色と同系の塗りで図案を埋めない。
- 色数を絞る図案では、主色だけでなく輪郭以外の各色面を分類色ベースと同系色にしない。補助色も含めて分類色ベースとのコントラストを持たせ、少ない色面の一つが背景へ溶ける状態を許可しない。
- フレーム内に収める余白は、アセットごとではなく描画側の共通倍率で確保する。タグごとの余白や縮小率で見た目を調整しない。したがって図案セットの制作時には、全図案を同じ倍率で実際の円盤へ合成し、円盤内の専有面積を横並びで調整する。
- 外枠は図柄より前面に描画する。
- 図柄色に固有の意味がないタグは、対応するステータスの分類色を図柄に使わない。分類色ベースとの同化を避け、図柄の輪郭を優先する。
- タグ数・タグスキルレベルは図柄へ焼き込まず、UIのバッジ・枠・背景で別途示す。
- 図柄は全タグで共通の描画倍率を使用する。タグごとの余白や縮小率で見た目を調整しない。
- タグ単体だけでなく、5つのステータス系統と属性系が同時に並んだ縮小表示で確認する。この確認は最小の雑魚Chipにおける約27pxの円盤・約19pxの図案で行い、各図案について「主シルエットが読めること」と「分類色の円盤面が十分に残ること」を確認する。個別に良い既存図案であっても、セット全体の輪郭・描き込み密度・色の役割・円盤内専有面積から外れる場合は置換対象とする。

## 4. フレームの分類色

外周の濃紺と内周線は共通とし、5つのステータス系統と属性系の分類色ベースを描画時に付与する。図案の配色は分類色ベースとは独立して設計する。

| 分類 | 対象タグ | エナメル色 |
| --- | --- | --- |
| パワー | 武勇・鉄 | 茶 |
| 魔力 | 魔導・布 | 紫 |
| スピード | 軽業・羽 | シアン |
| 交渉力 | 信用・宝石 | 明るい金 |
| 運 | 加護・幸運 | 桃 |
| 属性 | 炎・水・雷・範囲・活力 | 真珠色の淡い青灰 |

パワーには炎との誤認を避けるため赤・橙を使用しない。属性フレームは中央の属性図柄を際立たせるため、属性ごとの枠色には分けない。ステータス系タグのベース色・ステータスゲージの枠色・ステータスアイコンの参照先は `StatusVisualCatalog` で一元管理する。各用途は同じ分類色から導出し、個別の描画側へ色を直書きしない。

## 5. 属性との対応

## 5.1 Chipの状態アイコン

`ChipRenderer` は、戦闘中に有効な状態をChip下部の状態アイコン列として描画する。状態アイコンはタグ・装備・固有タグとは異なる「角丸のべた塗り背景に白抜き図案」の共通スタイルを用いる。図案は状態の種類を、背景色は状態値の強さを表す。炎・水・雷の属性状態、物理防御、諸刃の剣状態をこの列の対象とし、将来の戦闘状態も同じ仕組みで追加する。

値を持つ状態の背景色は、最小値の鈍い青灰から最大値のくすんだ赤茶へ連続的に変化させる。鮮やかな原色は使わず、Chip上の状態アイコンはマットな色面として扱う。最小値と最大値が同じ状態は、最小色で表示する。Chip上では数値を重ねず、属性値が増減する際の色変化から強さを学習できるようにする。静的な情報ウィンドウの状態アイコンは現在値を持たないため、各状態の最小色で表示する。

状態アイコンはChipの表示枠の左端から固定順で並べる。表示中の状態が増減しても、先行する状態の位置は変えない。列がスロット幅へ収まらない場合は、後続を表示せず最後に`[…]`アイコンを置く。`[…]`は省略を示すだけで、情報ウィンドウを開く操作は持たない。

状態アイコンは状態の追加・解除に合わせて即時に表示・非表示を切り替える。追加・解除そのものには明滅・拡縮などの専用アニメーションを付けない。状態変化の演出は、属性オーバーレイなど各状態の本体演出が必要な場合だけに用いる。

各状態アイコンは対応する静的な状態情報を開く。炎・水・雷は属性タグの静的情報を使い、物理防御と戦闘状態は状態情報を使う。Chip上の既存の属性オーバーレイ・物理防御オーバーレイは、状態の大きさや戦闘中の変化を示す演出としてこのアイコン列と併用する。

炎・水・雷の共通属性状態アイコンは、対応する属性値が0より大きい間に表示する。値域は0から7とし、固有スキルが属性値を変えても、この共通表示規則だけで表示・色を決める。図案は白一色のシルエットとし、炎・水滴・雷光のように形だけで種類が分かるものにする。属性タグの記号図案・色・円盤・枠は流用しない。

状態アイコンの図案は `public/assets/conditions/` に置く。数値ステータスを表す `public/assets/status/` やタグ図柄とは混在させない。すべて1024px四方・透明背景とし、白抜きの図案だけを描く。角丸背景、背景色、余白、リンク判定は共通の状態アイコンRendererが担当する。この白抜き図案は未承認の仮版であり、演出画像と同一にしてはならない。演出は、状態アイコンとは別のカラー画像で表示する。

物理防御の状態アイコンは白抜きの盾図案を角丸矩形へ載せる。Chip上の物理防御オーバーレイは別画像 `public/assets/effects/defense/physical-shield.png` を使い、金属の盾の縁と透明な内側で描く。状態アイコンの仮シルエットには合わせない。

炎・水・雷のタグ図柄と、戦闘中の属性オーバーレイは、同一属性と認識できる色・図形モチーフ・アニメーションを共有する。

- タグ図柄: 常時見える識別用の簡潔な図柄
- 属性オーバーレイ: キャラクターを囲み、属性付与値を大きさ・動きで示す演出

水は深い青、水面、霧、波紋を共通モチーフとする。属性オーバーレイは中央を大きく空け、キャラクターの視認性を妨げない。

## 6. ステータス表示との対応

ステータス表示は、アイコンと色の両方で種別を示す。7セグメントゲージでは、点灯セグメントの色とは別に、ゲージの土台・外枠へステータス固有色を使用する。

パワーの色は炎との誤認を避けるため、炎系の赤・橙を使用しない。タグ図柄・ステータスアイコンの最終的な色と形状は、相互の見分けやすさを確認して決定する。

## 7. ステータスアイコン

ステータスアイコンは `public/assets/status/` に置く。タグアイコンと同じく、1024px 四方の透明背景に図柄だけを描き、円盤・枠・文字は含めない。実際の円形フレームとステータスカラーは描画側で付与する。

図柄は、対応するステータスカラーと同系色を避ける。分類色の上に重ねても図柄を即座に見分けられるようにするためである。

| ステータス | ファイル | 図柄 | 図柄の基本色 |
| --- | --- | --- | --- |
| パワー | `power.png` | 籠手の拳 | 象牙・銀 |
| 魔力 | `magic.png` | 開いた魔導書 | 象牙・珊瑚 |
| スピード | `speed.png` | 走るブーツ | 象牙・黄 |
| 交渉力 | `negotiation.png` | 握手 | 象牙・淡青 |
| 運 | `luck.png` | サイコロ | 象牙・桃 |
| スタミナ | `stamina.png` | 水筒 | 象牙・石板灰 |
| HP | `hp.png` | 医療十字 | 象牙・珊瑚赤 |

図柄は、既存のタグ図柄と役割・外形が重ならないことを優先する。特にステータスの種類は、色だけではなく図案でも識別できなければならない。

## 8. エリア・施設名の表示

場所名は、場所アイコンと名称を一つのCanvas描画フレームに収めて表示する。画像プレートは使わず、名称・アイコン・枠を同じ当たり判定の中で描画する。これによりi18n時も表示名の長さに対して一貫した構造を保てる。

場所名フレームは、明るい背景と控えめな古金の二重枠を持つ。高さは `52px` とし、横幅はCanvasで測定した「図柄の安全領域 + 6px + 文字の実際の字形幅 + 左右各12px」とする。内容は左寄せで置き、文字縮小や切り詰めを行わない。描画で得た同じフレーム矩形をクリック判定にも使う。

Home・Warehouse・Battleを含む全ての名称表示は、タップすると対応する情報ウィンドウを開く。

## 9. エリア・施設アイコン

エリアと施設のアイコンは、ゲーム内の場所を示すための位置アイコンである。タグ・ステータスの図柄や、名称表示のフレームとは別の視覚体系として扱う。同じ場所を示す限り、エリア情報、施設情報、名称表示、本文中の参照で同じ位置アイコンを使う。

### 9.1 アセット契約

- ソース画像はすべて `1024 x 1024px` の透明PNGとする。縦長・横長のキャンバスは使用しない。
- 描画できる領域は、外周96pxを除いた中央 `832 x 832px` とする。影・縁取りを含む全ての画素をこの領域へ収める。
- 図柄の視覚的な中心はキャンバス中心へ置く。上部や下部へ意図なく重心が寄る構図は使用しない。
- 文字、名称、表示サイズごとに異なる枠や背景は画像へ焼き込まない。名称と枠は表示側の責務とする。
- 全アイコンは同じ余白契約で制作する。個別の `scale`、`object-position`、CSS余白で視覚サイズを補正しない。

### 9.2 表示契約

- 本文中の位置参照は、すべて同じインライン参照コンポーネントで表示する。アイコンは `1.4em`、`vertical-align: -.25em` を共通で使う。
- 情報ウィンドウの見出しは `44px`、名称表示のアイコン領域は `44px` を共通の表示サイズとする。名称表示では、暗い場所アイコンを背景から判別できるよう、アイコンと名称を同じ明るいフレーム面へ直接配置する。個別のアイコン背景を持たない。
- 位置アイコンは、表示コンテナの寸法へ `contain` で収める。アセット契約を満たすため、表示側はアイコン種別ごとの倍率を持たない。

### 9.3 データと責務

- 位置アイコンのパスは、場所を示すためのCatalogで一元管理する。表示層はアイコンのパス・倍率・余白を個別に判断しない。
- エリアと施設が同じ場所を表す場合だけ、同じCatalogの位置アイコンを参照する。名前が一致することではなく、同じ場所を表すことが共有の条件である。
- 名称表示Rendererは名称表示のレイアウトと描画を、情報ウィンドウは参照リンクと詳細表示を担当する。どちらも位置アイコンのサイズ規約を変更しない。

## 10. Enemy Chipの中央絵

Enemyの中央絵は、Chipに載せるキャラクターの図柄である。Chipの背景、外周、固有タグ、属性、ステータスバーは描画側の責務であり、中央絵へ焼き込まない。

### 10.1 アセット契約

- ソース画像はすべて `1024 x 1024px` の透明PNGとする。縦長・横長のキャンバスは使用しない。
- 描画できる領域は、外周96pxを除いた中央 `832 x 832px` とする。影・縁取りを含む全ての画素をこの領域へ収める。
- 図柄の視覚的な中心はキャンバス中心へ置く。顔や武器などの重心が意図なく上下左右へ寄る構図にしない。
- 表現するのはEnemy本体と、本体に属する輪郭・影だけとする。Chipの円盤、枠、タグ、数値、背景、光輪は含めない。
- 雑魚・中ボス・ボスは同じ余白・中心・描画密度の契約に従う。ランクによる存在感の差は、ゲーム側のChip径とゲーム上の構成で表す。
- 最小の雑魚Chipで外形と主題が判別できる太さ・明暗差を持たせる。細密な模様や小さな副記号だけへ識別を依存させない。

### 10.2 表現方針

- 透明背景に、親しみやすいデフォルメを保ったファンタジーのキャラクターを描く。写実寄りの材質表現、強い発光、過密な細部だけでランク差を作らない。
- 1体のEnemyにつき、読み取りの核となる大きな外形を一つ決める。水系なら水棲の輪郭・ひれ・うねりを核にし、別の演出用背景やエフェクトを足さない。
- 同じ系統の小・中・大Enemyは、色相、輪郭線の強さ、陰影の段階、デフォルメ比率を揃える。個別のアセットだけをCSSやCanvasの倍率で見かけ上合わせない。

### 10.3 表示と移行の責務

- `ChipRenderer` は、中央絵を正方形の表示枠内へ縦横比を保って中央配置する。元画像を引き伸ばして補正してはならない。
- `EnemyCatalog` はEnemyと中央絵の対応だけを持つ。ランクや個体ごとの表示倍率・位置補正を持たない。
- 既存アセットに契約外のキャンバス寸法、余白、構図がある場合は、描画側の例外処理を増やさず、アセットを契約へ移行する。移行時は実際の雑魚・中ボス・ボスChipの表示サイズで確認する。
