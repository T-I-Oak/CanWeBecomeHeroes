# 多言語対応（i18n）

## 1. 共通方針

- GameWorks OAK 共通の `i18n.js` を使用する。ゲーム側で言語設定の保存、アクティブ言語の解決、フォールバック、他タブ同期を実装しない。
- 言語リソースは `lang-store` 形式で保持し、`loadJsonWithL10nCached` により現在の言語へ解決する。
- UI は `lang-store`、言語コード、保存領域へ直接依存しない。`GameTextRepository` が返す解決済みデータだけを受け取る。
- 言語変更時は `onLanguageChange` を購読し、`GameTextRepository` を再解決して、表示中のUIを同じ状態のまま再描画する。

## 2. リソースの配置

静的な表示文言は `public/data/text/` に置く。`ui.json`、`log.json`、`nameplate.json`、`vignette.json`、および `information/` 配下の種類ごとのファイルである。種類は `area`、`facility`、`status`、`tag`、`term`、`item`、`enemy`、`unique-skill`、`hero`、`profession` である。`log.json` はログ分類とログ文で、組み立て時に `ui` へ合わせる。それ以外の各ファイルの中身は、組み立て後のリソースのその区画である。ゲームルールやアセットパスは既存のゲームカタログに残し、翻訳対象の名称・フレーバー・仕様文・UIラベルだけをここへ置く。

```json
{
  "information": {
    "facility": {
      "training": {
        "name": { "lang-store": { "ja": "訓練場", "en": "Training Ground" } },
        "flavor": { "lang-store": { "ja": "...", "en": "..." } },
        "description": {
          "lang-store": {
            "ja": [
              { "type": "reference", "kind": "status", "id": "stamina" },
              { "type": "text", "value": "を消費してステータス上限を高められる。" }
            ],
            "en": [
              { "type": "text", "value": "Spend " },
              { "type": "reference", "kind": "status", "id": "stamina" },
              { "type": "text", "value": " to raise a status cap." }
            ]
          }
        }
      }
    }
  }
}
```

`text` は翻訳済みの通常文、`reference` はクリック可能な用語を示す意味トークンである。`reference` に表示名を保存しない。表示名、アイコン、リンク先は `kind` と `id` から表示時に解決する。

この形式では、各言語が文法に合わせてトークンの順序、リンクの位置、句読点、文の分割を独自に持てる。

## 3. 表示境界

`GameTextRepository` はこれらのファイルを共通i18n経由で読み、一つのリソースにまとめたうえで、以下を提供する。

- `getInformationDetail(kind, id)`
- `getName(kind, id)`
- `refreshLanguage()`

`InformationWindowLayer` は情報ウィンドウの生成、操作、配置だけを担う。Hero・Enemy・Item・固有スキルの情報対象は、`kind`・`definitionId`・任意の`instanceId`で表す。`instanceId`がない定義対象は `CatalogInformationRenderer` が静的な名称・アセット・説明を生成し、`instanceId`がある実体対象は `EntityInformationRenderer` が同じ定義情報へ現在値・装備・タグ・重量などを加えて生成する。定義対象は`kind + definitionId`、実体対象は`kind + instanceId`で一意にする。実体対象だけは、実体が破棄された時点で情報ウィンドウを閉じる。

タグ、ステータス、用語、施設、エリアは実体状態を持たない静的カタログ情報として `CatalogInformationRenderer` が生成する。説明文中のトークン列は `InformationWindowReferenceRenderer` が既存のアイコン付きリンクへ変換する。各レンダラーは解決済みの `flavor` とトークン配列を受け、文の順序や表示名を決定しない。

Canvas上のプレートも `getName('area', id)` または `getName('facility', id)` を使う。文字をアセットへ焼き込まない。

## 4. 言語切替

設定モーダルはタイトル画面とHUDで共通のコンポーネントを使用し、共通の `setupLanguageSelector('#language-selector', ['ja', 'en'])` を初期リソース読込前に呼び出す。タイトルメニューからの起動時は「言語」「チュートリアル」セクションを表示し、HUDからの起動時は「言語」「チュートリアル」「ゲーム進行」「頭上ステータス」の4セクションを表示する。起動元に応じた表示切替は共通設定モーダル側で制御する。ゲーム全体の方針に従い、キーボード操作やフォーカス（Tabキーによる要素移動やボタンへのフォーカスリング表示）は行わず、開閉時も要素へのフォーカス呼び出しを行わずにフォーカスを解除する。選択肢生成、保存、未対応言語の解決、他タブ同期は共通実装を利用する。言語以外の設定を初期化しない。言語切替時はタイトルメニューの文言（コマンド・クレジット・レコード）も即時反映する。

言語変更時の処理順は以下とする。

1. 共通i18nがアクティブ言語を確定し、変更イベントを通知する。
2. `GameTextRepository.refreshLanguage()` がキャッシュ済みの生リソースを現在言語へ再展開する。
3. Canvasは次フレームから新しい名称で描画する。
4. `InformationWindowManager.refreshEntries()` が開いているエントリを保持したまま `InformationWindowLayer` を再描画する。

再描画で維持するものは、ウィンドウのID、親子関係、アンカー、手動位置、ピン留め、コンパクト状態である。本文とリンク列は現在言語のトークン配列から作り直す。

## 5. 移行順

1. `GameTextRepository` とリソース読込、言語変更再描画を導入する。
2. エリア・施設の名称、フレーバー、説明文、プレート名を移行する。
3. ステータス、タグ、タグスキル、アイテム、敵、固有スキルを移行する。
4. フロー表示、選択UI、ログを移行する。

移行済みの文言をゲームカタログへ重複して残さない。ゲームカタログは識別子、ルール、数値、アセットパスを担当する。

## 6. 操作UIとログ

店舗看板と戦闘ポップアップも日英リソースから解決する。ポップアップには文言キーと数値を保持し、描画時に解決することで経過時間を変更せずに言語へ追従する。ログ分類名は `labelKey` で定義し、通知時に解決する。利用されなくなった日本語固定の時間整形関数は削除した。

操作パネルの文言とアクセシブル名は `ui` リソースから解決する。言語切替では文言要素だけを更新し、チェックボックス、速度入力、停止状態を維持する。文書の `lang` も更新する。

試験課題選択は見出し、ステージ番号、店舗ラベル、選択ボタン、敵名、タグのアクセシブル名を更新する。選択肢とイベントハンドラを作り直さない。ギルドの残り時間・経過時間・延長見込は次フレームで再描画する。

戦闘・訓練・買い物・出発・ギルド交渉のログは、テンプレートキーと人物ID・名称ID・数値を保存する。表示時に `GameTextRepository.formatLog()` で解決する。`GameLog.logLocalized()` は引数を複製し、後続のゲーム状態変更からログを切り離す。発生時のメッセージも記録として保持する。

固有スキルのログに含めるHero・Enemy・Item・固有スキルの参照は、個体の経過後も同じ内容を表示できるよう、`instanceId`なしの静的情報参照として保存する。フローログは各参照をアイコンと名称で非操作表示し、ログ履歴パネルは同じ参照を情報ウィンドウへのリンクとして表示する。

`FlowLog.refreshLanguage()` は表示中の文言と参照アイコンを描き直す。ログID、タイムスタンプ、表示ノード、アニメーションの進行を維持する。従来の任意文字列ログはそのまま表示する。
