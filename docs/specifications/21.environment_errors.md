# 起動と記録保存の環境エラー

## 起動失敗

起動に失敗したときは、ゲーム画面を隠し、画面中央へ `Failed to load game data.` と `Retry` ボタンを表示する。
Retryはページを再読み込みし、途中まで構築したアプリを重複して初期化しない。
この二つの文言はオーナー指示により多言語化せず、index.htmlへ固定で記述する。
文言JSONやゲームのJSが取得できない場合でも、HTMLが届いていれば同じ案内を表示できるようにする。
CSS自体を取得できない場合も、HTML標準の表示とボタンで再試行できる。

index.htmlの先行スクリプトが、起動時の外部script・stylesheetの取得失敗を監視する。
main.jsはstartGameの初期化失敗をこの受け皿へ渡す。JSON取得・解析、初期画像のdecode、保存領域へのアクセス等を例外種別で限定しない。
GameAppはロゴ、タイトル背景、外周背景の3画像をdecodeしてからタイトルを開く。
初期化エラーの詳細はconsoleへ記録し、論理エラーを無言で隠したり初期値へ置き換えたりしない。

初めてタイトルメニューを表示した時点で起動完了とし、起動時のresource監視を解除する。
起動完了後のゲーム中のエラーを、この起動エラー画面へ誘導しない。
ゲーム中の画像段階のfallbackは既存のScaledImage仕様、記録保存は次節の仕様に従う。
装飾用タイトルチップの全素材や、その後に必要となる全ゲーム素材を起動時に一括先読みするものではない。
HTML自体の取得失敗・ブラウザーがJSを実行できない環境は、この画面での復帰の保証対象に含まない。

## 記録保存の失敗と再試行

TrialSessionは課題決定時のcheckpointと終了記録の保存をRunRecordsSaveControllerへ渡す。
QuotaExceededErrorとSecurityErrorではゲーム進行と結果画面への遷移を維持し、画面下部のRecordSaveNoticeへ通知する。
それ以外の例外はそのまま送出する。
文言はpublic/data/text/ui.jsonのrecordsSaveFailed・recordsSaveRetryから解決する。

日本語の本文は「記録を保存できませんでした。このページを閉じると、未保存の記録が失われます。」、ボタンは「保存を再試行」。
英語の本文は「Your records could not be saved. Unsaved records will be lost if you close this page.」、ボタンは「Retry saving」。
通知は保存が成功するまで維持し、言語切替でも未保存状態を維持して文言だけを更新する。
タイトルへ戻っても同じ通知と保存対象を保持する。

再試行では現在のRunRecordsRepository.save()だけを呼び出す。
開始・終了処理やStatisticsCollectorの収集をやり直さず、最新のメモリ状態の絶対値を保存する。
再失敗時は通知を維持し、再試行または通常の次回保存が成功したら通知を隠す。
オフラインに保存領域の容量確保・権限変更を代行するものではなく、保存不可が続く間は未保存状態を知らせる。

## 配置と検証

通知はsafe areaを考慮した画面下部の固定領域で、再試行ボタンは44px以上の高さを持つ。
本文が長い場合は通知内をスクロールさせる。狭い画面では本文とボタンを縦に並べる。
RecordSaveNoticeがResizeObserverで実高さを測り、rootの--record-save-notice-heightへ設定する。
ModalLayerの下端とModalDialogの最大高からその高さを差し引き、閉じる・タイトル復帰等の操作を通知の背後へ隠さない。
起動エラーの案内はゲーム画面から独立し、外部CSSが届かない場合の標準HTML表示でもRetryを残す。

Nodeテストは起動監視の終了境界、起動前のresource失敗、未保存保持・再試行・二重集計防止・論理エラーの送出を確認する。
productionのブラウザー検証内で、JSON・画像・JS・CSSの503と保存領域のSecurityErrorからの再読み込み、保存Quota失敗と再試行、日英切替、スマートフォン縦横の通知とモーダルの配置を確認する。
障害注入はブラウザーテスト側だけで行い、本番コードに障害を発生させる操作や検証リンクは設けない。
