# ランタイムシステム仕様

## 1. ゲーム時間

`GameClock` は一時停止、x1／x2／x4のゲーム速度を管理する。描画とカメラ操作は常に続け、ゲーム状態だけを停止または加速する。シミュレーションは最大1/60秒の内部更新へ分割し、経過ゲームtickを `tick` として保持する。

## 2. スタミナ回復

`StaminaRecoverySystem` はゲーム内1/60秒ごとのtickを蓄積する。`currentArea === 'preparation'` のHeroだけに、tickごと0.005のスタミナを加算し、スタミナMAXで止める。ゲーム・デモの開始値はいずれも0である。

## 3. 段階移動

Heroは1回の「ズッ」を0.38秒で行い、前半で移動、後半で停止する。所持重量は装備Itemのタグ重量合計とし、次の段階移動量は以下で求める。

```text
96 / (1 + (所持重量 / 25)^2)
```

Item追跡・Heroスロット移動では、1段階ごとに目標の現在位置を読み直す。複数Heroの拾得・吸収・行き先移動は独立して進行する。目的Itemが盤面から消えた場合は、次の装備可能Itemへ再ターゲットする。

行き先スロットが予約できた時点で、`GameLog` は `【職業・名前】は戦闘に向かって出発した。` の形式で通知ログを記録する。ショップ・ギルド・訓練も同様に通知する。

## 4. Heroスロット

スロットはチップ直径192pxに各辺16pxの余白を加えた224px四方である。`HeroSlotManager` は予約と占有を別管理する。到着前はHeroの `targetSlotId`、到着後は `currentSlotId` を保持し、到着後のChip移動範囲はスロット矩形へ制限する。

戦闘の味方スロット予約順は `2 → 3 → 1 → 4`。ショップ・ギルド・訓練は各1枠である。

## 5. エリアテーマ

`AreaTheme` は準備・倉庫・戦闘・ショップ・ギルド・訓練の濃いテーマ色を定義する。Heroは移動先または滞在先のテーマ色をチップのベース色に使う。アクティブHeroは倉庫色とする。行き先Itemとその装備スロット背景も対応施設のテーマ色を使う。ショップ・ギルド・訓練のHeroスロットも、同じテーマ色の濃い半透明塗りと縁取りで常時表示する。

## 6. 施設待機アニメーション

`FacilitySwingSystem` は、ショップ・ギルド・訓練のスロットに到着しているHeroへ、物理回転とは別のポーズ角を重ねる。目標角は正立（0度）を中心とする±10度の正弦波とし、到着時の実際の向きから最終的な表示角が目標角へ徐々に近づくようにする。周波数は training（最速）・shop（中速）・guild（最遅）の順とする。準備エリアでスタミナ3以上のHeroも、色明滅の代わりに低速でスイングする。アクティブHeroはtrainingより速くスイングする。ゲーム時間に連動するため、一時停止中は停止し、速度倍率の影響を受ける。

## 7. ゲームログと通知

`GameLog` はゲーム起動中だけメモリに記録を保持する。各記録はメッセージ、発生時刻、主体、結果レベル、通知対象かどうか、任意の補足データを持つ。主体と結果レベルは別パラメータであり、いずれも定義追加できる。

- `subject`: `hero`（名前を持つ味方Hero）、`enemy`（名前を持つEnemy）、`system`（ゲーム全体・共有資源・期限・進行状態）
- `level`: `info`（通常情報）、`luck`（主体に有利な上振れ）、`unluck`（主体に不利な下振れ）

通知対象の記録は、画面右の固定領域へ右外からスライドインする。複数通知は下に積み、表示時間後に先頭が上へ消えたら残りが上方向へ詰まる。通知表示の有無はカテゴリと独立した `notify` で指定する。

現在ログを出力するイベントは以下である。選択、Itemへの移動開始、Item装備、ゲーム開始ではログを出力しない。表示内容・レベルはゲームバランスとUIを見ながら今後調整する。

- Heroの行き先スロット予約が確定し、戦闘・ショップ・ギルド・訓練へ出発した: `hero/info`
- 訓練でステータスMAXを強化した: `職業・名前はステータス名を強化した。`。運の成功時は `hero/luck`、通常のスタミナ消費時は `hero/info`
- ショップで売買を完了した: `職業・名前はショップで買い物をした。`: `hero/info`
- ショップで宝石タグの運判定により購入品のタグ数が増えた: `職業・名前は買った部位名の隠れた能力を見つけた。`: `hero/luck`
- 戦闘アクションで通常ダメージを与えた: `主体は対象にダメージNNを与えた。`: 攻撃者の `hero/info` または `enemy/info`
- 戦闘アクションがすべてミスだった: `主体の対象への攻撃は外れた。`: 攻撃者の `hero/unluck` または `enemy/unluck`
- 戦闘アクションで会心ダメージを与えた: `主体は対象に会心ダメージNNを与えた。`: 攻撃者の `hero/luck` または `enemy/luck`
- 戦闘アクションで相手を倒した: `主体は対象を倒した。`: 攻撃者の `hero/info` または `enemy/info`。同一対象へのダメージ通知はこの撃破通知へ置き換える。
- 最後のEnemyを倒してステージ勝利を確定した: `敵を全滅させた。`: `system/info`。200 tickの勝利待機へ入る時点で記録する。

## 8. 訓練

`TrainingSystem` は、訓練スロットへ到着して `currentArea === 'training'` になったHeroを、200 tickごとに処理する。MAXが7未満の6ステータスを候補とし、現在値（スタミナは現在スタミナ）を重みとして抽選する。候補の合計が0なら帰還する。

抽選できた場合は `Hero.getLuckRate()` で成功判定し、成功ならスタミナ1、失敗なら2を消費する。必要量に足りなければスタミナを0にして訓練結果表示へ移る。消費できた場合は抽選済みステータスのMAXを1増加（最大7）して、次の200 tickを待つ。訓練を終える際は、今回上昇したMAXセルを訓練エリア右側で120 tick表示してから帰還を開始する。

帰還時は行き先Itemだけを倉庫内のランダム位置へ戻し、その他の装備Itemは破棄する。倉庫へ戻すItemは新規追加と同じ落下状態から表示する。Heroは準備エリアの出発位置・移動範囲へ戻り、装備・所持タグ表示・Chip重量を職業由来の状態へ初期化する。ステータスMAXは維持する。

## 9. 施設共通の帰還

`FacilityReturnSystem` は訓練・ショップなどの施設処理が完了したHeroを準備エリアへ戻す。スロット予約・占有を解放し、行き先Itemだけを倉庫へ落下追加して、それ以外の装備Itemを破棄する。Heroは元の準備サブエリアへ段階移動で帰還し、到着後にそのサブエリアの移動範囲へ再制限される。

## 10. ギルド申請

`GuildSystem` はギルド到着から600 tick後に申請を完了する。この時点の貢献ポイントを使い、`基本レート = 0.1[H/pt] × (1 + 信用タグスキルLv × 0.2)`、運判定成功時はさらに`× 1.2`で延長レートを決める。延長時間は`貢献ポイント × 延長レート`、1回の上限は24時間とする。計算結果が1時間未満なら、貢献ポイントを全て消費して1時間を最低保証する（0ptも含む）。上限24時間に達する場合の消費ポイントは`ceil(24 / 延長レート)`とする。

申請完了時は信用タグスキルの有無と運判定結果に応じたHeroログを1件出し、共通帰還を開始する。

## 11. ショップ売買

`ShopSystem` はショップ到着時に購入5部位セットを2組確定する。各セットは販売傾向を含む通常のタグ付与パターンに従う3タグ候補を独立して作り、各Itemのタグ数決定後に候補3枠から非復元抽選する。売却額・交渉力で決めたタグ予算を用いる。1セット目を100〜500 tickで1品ずつ開示して600 tickで近接する倉庫座標へ落下追加する。2セット目を700〜1100 tickで開示して1200 tickで同様に追加する。売却元の袋内Itemは2セット目の配送時に消費する。宝石タグの運判定でタグ数が増えたItemを開示する時は `fortune` ログを記録する。2セット目の配送後には販売傾向を進め、Heroのスタミナを0にして共通帰還処理を開始する。

## 11. 戦闘

`BattleSystem` は戦闘エリアにいるHeroとEnemyのアクションゲージを更新する。ゲージ上限は `15 - speed`、tickごとの増加量は `(13 / 300) / (1 + (weight / 25)^2)` とする。満タン時は0へ戻し、対象があればターゲット決定と暫定物理・魔法ダメージを解決する。対象がいない場合もゲージだけを0へ戻す。

`StageController` はゲームラン中のステージ番号、基準level、抽選後level、編成種別、進行状態を持つ。通常ステージ開始時は、基準level `stageNumber + 2` に `-2〜+2` の整数乱数を加え（最低1）、通常編成を抽選してEnemySpawnSystemへ現在tick基準で予約する。進行状態は `spawning`、`battle`、`victory`、`complete` を経る。勝利待機はBattleSystemが管理し、StageControllerは満了後にだけ`complete`へ遷移する。

敵体力が0になると、Enemy Chipを取り除き、タグ傾向のItemを倉庫へ落下追加し、共有貢献ポイントを加算する。最後のEnemyを倒した時点で、`BattleSystem` はステージ勝利を即時に確定する。確定後もゲーム時間は進むが、200 tick の勝利待機が満了するまでステージ完了には遷移しない。この間に期限が切れても、先に確定したステージ勝利を無効にしない。ボスを含むステージかどうかはステージ管理側が判定し、勝利確定済みならゲームクリアーを優先する。Heroのスタミナが0になると、施設共通の帰還処理を開始する。

デモは最初の敵が着地したtickを記録し、敵全滅時の経過tickを戦闘エリアに表示する。これはデモ専用の計測表示である。

## 戦闘状態と演出

`BattleSystem` は確定済みの武器攻撃、運ロール、範囲補正、炎・水・雷の付与と60tick減衰を解決する。属性付与と直接ダメージは、対象ごとに80%〜120%のランダム補正を乗算する。雷伝搬は起点へ与えた最終ダメージを基に算出し、伝搬先での再抽選は行わない。Enemyは所持武器すべてで攻撃し、武器がない場合だけ素手で1回攻撃する。Heroは左右の手を各1回解決し、非武器の手は素手として扱う。

`CombatEffectSystem` は攻撃周回、ミス・ダメージ・会心の表示、被弾ノックバック、雷伝搬線を描画する。同一アクションで同じターゲットへ出た表示は1つへ集約し、`critical`、`damage`、`miss` の順で優先する。`BattleSystem` のユーザー向けログも同じく、同一アクション内の攻撃者・対象ごとに1件へ集約する。炎・水・雷の付与値はChipに同期し、`public/assets/effects/attributes/` の透明オーバーレイを正立で描画する。属性オーバーレイはチップ下部を基点に拡大・縮小し、低い付与値では足元に表示され、付与値7ではチップ外周を大きく取り囲む。付与値の減衰に合わせて非線形に縮小し、付与値が高いほど揺れ・脈動も大きくする。再付与時は大きく戻す。炎・水・雷のタグアイコンと属性オーバーレイは、色・図形・アニメーションの印象を共通の視覚体系として設計する。物理攻撃軽減値を持つChipには `public/assets/effects/defense/physical-shield.png` をチップ中央基点で重ねる。軽減値が高いほど枠の不透明度と脈動の拡大・縮小幅を強くし、値が0なら表示しない。

## 12. チップ衝突の高さ

チップの落下衝撃および移動時の押し出しは、平面上で重なっていても高さ差が大きいチップ間には発生しない。接触可能な高さ差は、小さい方のチップ半径の25%以下とする。同程度の高さにあるチップ同士は従来どおり干渉し、地面上の重なりを滑らかに解消する処理は両方がほぼ地面にある場合だけに適用する。
