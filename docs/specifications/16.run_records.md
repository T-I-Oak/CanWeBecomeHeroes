# ラン記録の永続化と受け渡し

## 保存Repository

`RunRecordsRepository`は共通DataManagerの`runRecords`キーを使用する。形式版は`RUN_RECORDS_VERSION = 1`、終了履歴上限は`RUN_HISTORY_LIMIT = 50`である。DataManagerが提供するゲーム名前空間内の他のキーを変更しない。

保存するのは一般累積集計、終了履歴、ランキング、終了ランの通算統計、合格日時・回数、記録機能で解放した職業ID、旧クリアーフラグの確認結果、ラン番号である。

初期化時は旧`heroProgress.hasClearedTrial`を確認し、過去の日時・回数を生成せず`legacyClear`として保持する。形式版が未知のデータは上書きせずエラーとする。

`HeroProgressRepository`は旧解放済み職業と記録側の解放済み職業を合わせて取得する。試験セッションでは`TrialRunFlow`の個別の進捗保存を無効にし、終了記録・集計・解放職業・合格情報を1つの保存データへまとめる。合格時に終了メンバーを解放するタイミングは変えない。

`beginRun()`は単調増加するラン番号と独立したラン・累積の集計インスタンスを返す。`completedSequence`以下の終了通知は再集計しない。課題決定時に次のラン番号も保存されるため、途中離脱後の次の開始でも保存済み番号を使い回さない。

保存は集計済みの絶対値を書き込む。保存失敗後の再試行はイベントや終了処理を再実行しない。DataManagerが保存前に内部キャッシュを変更する場合にも、Repositoryは自身の状態を保持して同じ値を再保存する。

## ランの接続

`TrialStatisticsSession`はラン開始の集計、初期Heroの値、Collectorの生成、Heroへのタグ更新フックの接続、終了記録の作成を担当する。終了記録は初回だけ作り、同じセッションの再通知では同じ記録を返す。

`TrialSession`がゲームの各システムの`onStatistics`をCollectorへ接続する。討伐情報にはその時点の`StageController.currentStage.level`を付加する。

| 情報 | フック |
| --- | --- |
| 課題の挑戦 | `StageController.selectStage`の選択成立後。構成indexを課題オブジェクトへ保持する |
| 課題のクリアー | `StageController.update`で勝利／完了へ初めて移った時点。最終課題の勝利も数える |
| Heroのタグ | `HeroItemInteractionController.add`のHero追加時と`Hero.refreshDerivedValues`。初期・加入・装備・解除・タグ移動を観測する |
| 施設出発と武器 | `ItemPickupController.moveToDestinationSlot`で予約が成功し目的地が確定した後 |
| 敵討伐 | `CombatEnemyDefeatSystem.resolve`で盤面上の敵の討伐が成立した時点。`CombatDamageSystem`から最後の攻撃者を受け取る |
| 宝石スキルのタグ追加 | `ShopSystem.deliverSet`。追加前のタグ予算と実際のタグ数から追加分を数える |
| 期限延長・消費貢献ポイント | `GuildSystem.completeApplication`で消費が成立した後。消費前後の差を実消費量として同じイベントへ付加する |
| 訓練の幸運成功 | `TrainingSystem.train`で幸運による消費軽減を伴った訓練が成立した後 |

勝利待機の毎フレーム更新、対象不在の再討伐、施設到着、装備を拾っている途中では対応する回数を増やさない。

## ランキング

`RunRankings`は保存する終了結果の集合を管理する。`RANKING_LIMIT = 10`、基準は`RANKING_CRITERIA`で定義する。

`add(record)`で最新結果を追加し、モード・基準ごとの上位10件のIDの和集合を求め、それに含まれない結果を削除する。`get(mode, criterion)`が指定基準の順位を返す。アチーブメント評価へランキングを渡さない。

## 終了情報の受け渡しと保存エラー

TrialRunResult.recordには値だけの独立した変更不能な終了情報を渡す。将来の終了画面から参照できるよう、TrialSessionはtrial.lastRunResultにも保持する。このブランチでは既存の仮合格・不合格画面へ詳細表示を追加しない。

保存失敗時もRepositoryのメモリ状態と未保存状態を保持し、save()の再呼び出しは同じ絶対値を保存する。QuotaExceededError・SecurityErrorはTrialSessionでコンソールへ報告し、ゲームの進行・既存結果画面への遷移を妨げない。論理エラーは隠さない。利用者向けの失敗表示と再試行操作はUIの後続ブランチで扱う。

## 後続のUI

トースト、終了画面のアチーブメント表示、レコード画面、共通CSS・DOM生成は今回の対象外。合意した表示設計は14.achievements.mdに保持する。終了画面のデザインを先に決めてから、共通表示を別ブランチで実装する。
