# ラン記録の永続化と受け渡し

## 保存Repository

`RunRecordsRepository`は共通DataManagerの`runRecords`キーを使用する。形式版は`RUN_RECORDS_VERSION = 1`、終了履歴上限は`RUN_HISTORY_LIMIT = 50`である。DataManagerが提供するゲーム名前空間内の他のキーを変更しない。

保存するのは一般累積集計、終了履歴、ランキング、終了ランの通算統計、合格日時・回数、記録機能で解放した職業ID、旧クリアーフラグの確認結果、ラン番号である。

初期化時は旧`heroProgress.hasClearedTrial`を確認し、過去の日時・回数を生成せず`legacyClear`として保持する。形式版が未知のデータは上書きせずエラーとする。

`HeroProgressRepository`は旧解放済み職業と記録側の解放済み職業を合わせて取得する。試験セッションでは`TrialRunFlow`の個別の進捗保存を無効にし、終了記録・集計・解放職業・合格情報を1つの保存データへまとめる。合格時に終了メンバーを解放するタイミングは変えない。

`beginRun()`は単調増加するラン番号と独立したラン・累積の集計インスタンスを返す。`completedSequence`以下の終了通知は再集計しない。課題決定時に次のラン番号も保存されるため、途中離脱後の次の開始でも保存済み番号を使い回さない。

保存は集計済みの絶対値を書き込む。保存失敗後の再試行はイベントや終了処理を再実行しない。DataManagerが保存前に内部キャッシュを変更する場合にも、Repositoryは自身の状態を保持して同じ値を再保存する。

## ランの接続

`TrialStatisticsSession`はラン開始の集計、初期Heroの値、Collectorの生成、Heroへのタグ更新フックの接続、終了記録の作成を担当する。終了記録は初回だけ作り、同じセッションの再通知では同じ記録を返す。

`TrialSession`がゲームの各システムの`onStatistics`をCollectorへ接続する。討伐情報にはその時点の`StageController.currentStage.level`を付加する。

| 情報 | フック |
| --- | --- |
| 課題の挑戦 | `StageController.selectStage`の選択成立後。構成indexを課題オブジェクトへ保持する |
| 課題のクリアー | `StageController.update`で勝利／完了へ初めて移った時点。最終課題の勝利も数える |
| Heroのタグ | `HeroItemInteractionController.add`のHero追加時と`Hero.refreshDerivedValues`。初期・加入・装備・解除・タグ移動を観測する |
| 施設出発と武器 | `ItemPickupController.moveToDestinationSlot`で予約が成功し目的地が確定した後 |
| 敵討伐 | `CombatEnemyDefeatSystem.resolve`で盤面上の敵の討伐が成立した時点。`CombatDamageSystem`から最後の攻撃者を受け取る |
| 宝石スキルのタグ追加 | `ShopSystem.deliverSet`。追加前のタグ予算と実際のタグ数から追加分を数える |
| 期限延長・消費貢献ポイント | `GuildSystem.completeApplication`で消費が成立した後。消費前後の差を実消費量として同じイベントへ付加する |
| 訓練の幸運成功 | `TrainingSystem.train`で幸運による消費軽減を伴った訓練が成立した後 |

勝利待機の毎フレーム更新、対象不在の再討伐、施設到着、装備を拾っている途中では対応する回数を増やさない。

## ランキング

`RunRankings`は保存する終了結果の集合を管理する。`RANKING_LIMIT = 10`、基準は`RANKING_CRITERIA`で定義する。

`add(record)`で最新結果を追加し、モード・基準ごとの上位10件のIDの和集合を求め、それに含まれない結果を削除する。`get(mode, criterion)`が指定基準の順位を返す。アチーブメント評価へランキングを渡さない。

## 終了情報の受け渡しと保存エラー

TrialRunResult.recordには値だけの独立した変更不能な終了情報を渡す。TrialSessionはtrial.lastRunResultにも保持し、TrialRunResultModalへ渡す。終了画面の表示・成績表の選定は17.trial_result_screen.mdを参照する。

保存失敗時もRepositoryのメモリ状態と未保存状態を保持し、save()の再呼び出しは同じ絶対値を保存する。QuotaExceededError・SecurityErrorはTrialSessionでコンソールへ報告し、ゲームの進行・既存結果画面への遷移を妨げない。論理エラーは隠さない。利用者向けの失敗表示と再試行操作はUIの後続ブランチで扱う。

## レコード画面

タイトルのStageは`isolation: isolate`で独立した重なりの境界を持ち、落下チップcanvas、暗幕、内容・クレジットの順に表示する。画面回転によるcanvasの再リサイズ中も、レコードは内容の層に属する。本文の拡縮・内部スクロールはこの境界の内側で行い、落下チップ演出は開閉にかかわらず継続する。Safari実機での回転後の描画・操作は、viewport変更による自動検証とは別に確認する。

タイトルのレコードから、勇者認定試験・実力判定試験のランキング、アチーブメント、課題記録を表示する。実力判定試験のタブはTitleMenuと同じHeroProgressRepository.hasClearedTrial()で解放し、ランキングデータの有無では判定しない。タブラベルは「勇者認定試験」「実力判定試験」とし、日英の短い画面でも収まるようにする。TitleMenuは開閉と復帰、RecordScreenは描画と切替、RecordScreenDataは累積の表示データ作成を担当する。GameAppが既存Repositoryを接続する。開くたびに最新のメモリ状態を読み、閲覧・切替・言語変更では集計・保存・削除しない。

ランキングはRunRankingsの試験用3基準を上部のボタンで切り替え、上位10件を共通の表で表示する。列は順位・クリアー課題数・残り期限・討伐数・獲得貢献ポイント・終了時メンバー・達成日時。不合格は残り期限欄へ表示する。選択基準の値をやや大きく表示する。メンバーは保存順のまま、画面外Heroの方向アイコンと同様の顔のアップを表示する。空状態では試験終了後に記録される旨を案内する。

アチーブメントは既存定義で累積を評価し、オーナー確認済みの方針として未達成を含む全項目を定義順に表示する。列はカテゴリ・評価項目・判定・判定基準・達成度。同じカテゴリの連続行を結合し、所見は表示しない。判定基準は行動を示す文言、達成度は現在値／次評価に必要な整数値と控えめなバーとする。目標値は既存評価式を二分探索し、評価と同じ浮動小数点許容値で求める。最高判定は「達成」とする。終了画面・トーストの形式は維持する。

課題記録は通常・エリート・ボスごとに、全勇者・全プレイを通した最高クリアーレベルが高い5構成までを表示する。同じ構成は1件とし、未クリアーを除く。同レベルはhighestLevelClearedAtの新しい順、同日時は定義順とする。日時の欠落チェックや旧データ向けのフォールバックは設けない。記録のない種類には案内を表示する。

StageControllerはクリアー成立時に実日時を一度取得してstage-clearイベントへ付け、StatisticsCollectorが今回ランと累積へ同じ値を渡す。GameStatisticsは最高レベルの更新・同レベル再クリアーでhighestLevelClearedAtを受け取ったISO日時へ更新し、低レベルのクリアーでは変更しない。既存の保存時点で日時も保存し、形式版1の構成別集計に追加する。日時の欠落を補う処理は設けない。

CroppedEnemyLineはcreateEncounterEnemiesを使い、記録された最高レベルと構成パターンから実際の敵種・数・位置を求める。6スロットと空き枠を保持し、大型は2スロットを占める。敵の元画像を透明余白も含めて切り取らず表示する。台座・縁・タグは描画しない。通常・エリート・ボスのサイズ比（128:192:384）を守り、中心の高さを揃える。6スロットの幅を基準に構成全体へ共通の倍率を適用する。オーナー確認により、この切り取りなし表示を採用する。課題選択画面への適用は行わない。

ランキング・課題記録は末尾に達成日時列を置く。ランキングはendedAt、課題記録はhighestLevelClearedAtを参照し、端末のタイムゾーンと表示言語による年月日・24時間表記の時分を表示する。time要素のdateTimeには記録したISO日時を保持する。アチーブメントのタグ判定基準は「いずれかの受験者で○○タグを集める」とする。

レベルは課題が進むにつれて上がることを説明し、計算式・範囲は表示しない。PC・スマートフォン縦横で内部スクロールし、タブとタイトルへ戻る操作を固定領域に確保する。幅のある表は内容領域内で横スクロールする。

レコードのscale使用は共通モバイル規約と[UIスタイル設計規約](03.ui_style_conventions.md)に従う。見出し・タブ・順位基準・タイトルへ戻るボタンは拡縮対象から外し、通常44px以上、横幅900px以下または高さ480px以下では36px以上の操作高と14pxの文字を保つ。本文だけをRecordScreenScaleの基準幅1080pxで75〜100%へ拡縮し、下限を超えて縮小せず縦横の内部スクロールで閲覧する。最低倍率はReadablePanelScaleで管理する。終了画面は別方針であり、縮小下限を設けず紙全体を表示する（17.trial_result_screen.md）。

RecordScreen__ScrollViewportは実寸の表示枠とし、内側のContentFrameは本文の拡縮後の占有幅・高さを保持する。Contentは拡縮前の論理幅で描画し、左上原点のtransform: scale()を適用する。画面全体ではなく本文にのみscaleを適用するため、狭い縦画面でも操作部は小さくならず、スクロールで右端と最終行に到達できる。日付は14pxを基本とし、本文の最小倍率でも10.5pxとなる。

RecordScreenは開いている間だけResizeObserverで表示枠を監視し、閉じると監視を解除する。タブ・言語切替でも倍率を再計算し、画面サイズ変更時には情報ウィンドウの表示位置も再計算する。ボタン操作はDOMの表示後の当たり判定を使用する。情報ウィンドウは拡縮された本文の外へ表示し、倍率を重複適用しない。

タブ・順位基準・戻るボタンのクリックとタップ、表の縦横スクロール・末尾到達、6スロット表示、情報ウィンドウの画面内配置を拡縮後の画面で検証する。独自のチップ判定やドラッグなどを後から追加する場合も、このscaleを考慮する。

レコード画面はブラウザ標準ツールチップと標準スクロールバースタイルを使用しない。ランキングのHero画像・課題記録の敵画像のタップで、既存の情報ウィンドウの定義情報（説明・戦闘スタイル）を開く。個体のステータス・装備・現在状態は表示しない。RecordInformationが独立したInformationWindowManagerとLayerを所有し、関連情報を含めピンを表示しない。レコード本文のscaleから外したbody直下の固定レイヤーへ表示し、タップのclient座標を直接使う。画面を閉じると関連ウィンドウを含め全て破棄し、ゲーム中の情報ウィンドウには影響させない。スクロールバーの縦横の色と形は画面の配色に揃える。

中ボス・ボスの定義情報には、敵定義の固有スキルに対応するExボタンを表示する。CatalogInformationRendererとEntityInformationRendererはInformationWindowUniqueSkillButtonを共用し、定義情報と戦闘中の実体情報から同じ固有スキル説明を開く。Exボタンは親の敵ウィンドウを維持して子ウィンドウを開き、通常敵には表示しない。定義情報から個体の装備・状態を生成しない。

実力判定試験はクリアー課題数・経過ticks・討伐数・獲得貢献ポイントの4基準を切り替える。表は勇者認定試験の残り期限を経過時間に置き換え、他の列は共通とする。経過時間はGAME_TICKS_PER_HOURで換算して完了した時間の整数部を日・時で表示し、順位は丸め前のticksが長い方を上位とする。両モードの選択基準は別々に保持する。保存失敗の利用者向け通知・再試行、終了履歴・ラン詳細・比率表示は対象外。結果画面と通知は17.trial_result_screen.md・18.achievement_toast.mdを参照する。

課題記録の説明文は「高難度の課題をクリアーした記録です。敵構成のレベルは課題が進むにつれて上がります。」。レベル列の見出しは「レベル」とする。

## モードと終了結果

TrialStatisticsSessionはmodeを開始イベント・終了イベント・終了記録・IDへ渡す。trialはcleared／expired、challengeはcompletedで終了する。summary.completedは両モードの終了回数、summary.cleared／expiredとclear・職業解放は勇者認定試験だけを数える。challengeの開始・終了回数はstatistics.runs.challengeへ保存し、試験の合否アチーブメントへ加算しない。stageNumberは到達番号、clearedStagesはstage-clearイベントの実数とする。保存形式版1を維持し、既存記録は書き換えない。
