# UIスタイル設計規約

## 1. 目的

本規約は、ゲームUIで使用するCSSクラスと色の意味を一貫させ、将来も意図したスタイルを選べるようにするための共通契約である。

CSSクラスは、コンポーネントの文脈、表示内容の意味、UI状態を分けて表す。意味だけを示すクラスは、コンポーネント外で見た目を持ってはならない。

本書には、使用が確定している規則だけを記載する。未実装・未確定の画面、状態、テーマ、色は記載しない。

## 2. クラスの役割

### 2.1 コンポーネントクラス

UI部品とその構造を表す。PascalCaseを使う。

- `.Toast`: 通知1件を表示するコンポーネント
- `.Toast__Message`: `.Toast` 内のメッセージ要素
- `.NotificationCenter`: 複数のToastを画面固定位置へ積むコンテナ

要素クラスは `Component__Element` の形式とする。コンポーネントクラスは、配置、寸法、共通レイアウト、出入りアニメーションなど、その部品の構造だけを担う。

### 2.2 意味クラス

表示内容が誰・何に関するものかと、結果の性質を表す。小文字の単語を使う。

#### 主体

- `.hero`: 名前を持つ味方キャラクターが主語の出来事
- `.enemy`: 名前を持つ敵キャラクターが主語の出来事
- `.system`: ゲーム全体、共有資源、期限、進行状態が主語の出来事

効果の対象が味方全体でも、行動者を示せる場合は `.hero` または `.enemy` とする。例: 「○○は味方全体の士気を上げた」は `.hero.info` である。

#### 結果レベル

- `.info`: 通常の情報・状態変化
- `.luck`: ランダム判定などにより主体にとって有利な結果
- `.unluck`: ランダム判定などにより主体にとって不利な結果

`luck` と `unluck` は単なる重要度ではない。原則としてランダム判定の上振れ・下振れを表す。期限延長のような計算結果は、個別仕様が定める基準値に従って分類する。

### 2.3 状態クラス

UIの一時状態は `state-` 接頭辞で表す。状態クラスは、意味クラスを置き換えない。

```html
<div class="hero luck state-clickable">…</div>
```

状態が必要になった場合は、`.state-disabled`、`.state-selected` のように `state-` 接頭辞を付けて定義・使用する。これは状態クラスの命名方針であり、ここに挙げた状態の実装を確定するものではない。

## 3. スタイルを定義する場所

意味クラス・状態クラスだけに、グローバルな見た目を定義してはならない。

```css
/* 禁止: どのコンポーネントに属するか分からない。 */
.hero { color: blue; }
.luck { background: gold; }

/* 正式: Toast内のHeroにとって幸運な表示として定義する。 */
.Toast .hero.luck { /* Toast用のHero幸運スタイル */ }
.Toast .enemy.unluck { /* Toast用のEnemy不運スタイル */ }
.Toast .system.info { /* Toast用のシステム情報スタイル */ }
```

状態スタイルもコンポーネントに限定する。

```css
.Toast .state-clickable { cursor: pointer; }
.Toast .hero.luck.state-clickable { /* 必要な組合せだけ追加の強調 */ }
```

## 4. ToastのHTML契約

Toastは、外側にコンポーネント、内側に意味・状態を持つメッセージを置く。外側は通知の配置と出入りを、内側はメッセージの意味に応じた見た目を担当する。

```html
<div class="Toast">
  <div class="hero luck">剣士・アヴェリーは敵に会心ダメージ120を与えた。</div>
</div>
```

システムの通常通知は以下のように表す。

```html
<div class="Toast">
  <div class="system info">期限の残りは6日です。</div>
</div>
```

## 5. 意味色の変数

同じ意味で使用する色は、個別セレクタへ直接記述せず、`src/styles.css` の `:root` に定義したCSSカスタムプロパティを使う。

```css
:root {
  --color-subject-hero: #2d6ac5;
  --color-subject-enemy: #b84b4b;
  --color-subject-system: #64748b;

  --color-level-info: #64748b;
  --color-level-luck: #bd7b00;
  --color-level-unluck: #a64b61;
}
```

変数名は `--color-subject-*` と `--color-level-*` を使用する。主体色は「誰の出来事か」、レベル色は「結果の性質」を表す。

Toastの組合せスタイルは、必要な意味色を変数から選ぶ。

```css
.Toast .hero.luck {
  --toast-subject-color: var(--color-subject-hero);
  --toast-level-color: var(--color-level-luck);
}
```

色そのものを個別UIへ再記述してはならない。同じ主体・レベルの意味で使用する色は、必ず上記の変数を参照する。

## 6. JavaScriptとの境界

- ログは `subject`（`hero` / `enemy` / `system`）と `level`（`info` / `luck` / `unluck`）を別パラメータとして持つ。
- 描画側は、それぞれを独立した意味クラスとしてメッセージ要素へ出力する。
- JSは必要な状態クラスを付け外しする。
- スタイルに無関係な識別子やゲームデータは、`data-*` 属性またはJSの状態として持ち、CSSクラスをデータ格納先にしない。

## 7. 既存通知の移行

現在の通知実装は、単一カテゴリと `is-visible`、`is-leaving` の旧状態クラスを使用している。通知ログを主体・レベルの2軸へ更新する実装単位で、以下へ移行する。

- 主体: `hero` / `enemy` / `system`
- レベル: `info` / `luck` / `unluck`
- 状態: `state-*`
