# UIスタイル設計規約

## 1. 目的

本規約は、ゲームUIで使用するCSSクラスと色の意味を一貫させ、将来も意図したスタイルを選べるようにするための共通契約である。

CSSクラスは、コンポーネントの文脈、表示内容の意味、UI状態を分けて表す。意味だけを示すクラスは、コンポーネント外で見た目を持ってはならない。

本書には、使用が確定している規則だけを記載する。未実装・未確定の画面、状態、テーマ、色は記載しない。

## 2. クラスの役割

### 2.1 コンポーネントクラス

UI部品とその構造を表す。PascalCaseを使う。

- `.FlowLog`: 流れるゲームログの画面固定コンテナ
- `.FlowLog__Entry`: 流れるログ1件。横断アニメーションとレーン位置を担当する。
- `.FlowLog__Message`: `.FlowLog__Entry` 内の意味を持つメッセージ要素
- `.FlowLog__Text`: 文字の拡大縮小など、メッセージ本文だけのアニメーションを担当する要素
- `.StageSelection`: 進路選択モーダルの画面固定コンテナ
- `.StageSelection__Dialog`: 進路候補全体を収めるダイアログ
- `.StageSelection__Option`: 1つの進路候補を表示する行
- `.StageSelection__SelectButton`: 進路候補を確定するボタン
- `.StageSelection__EnemyLine`: 6つのEnemyスロットを並べる領域
- `.StageSelection__EnemySlot`: 1つのEnemyスロット
- `.StageSelection__Trend`: 今回または次回のショップ傾向表示
- `.ModalLayer`: アプリケーションモーダルを画面全体に重ねるレイヤー
- `.ModalDialog`: アプリケーションモーダル共通のダイアログ構造
- `.ModalDialog__Header`: タイトルと表示を閉じる操作を置く領域
- `.ModalDialog__Heading`: タイトルと補足文をまとめる領域
- `.ModalDialog__Title`: ダイアログの主題
- `.ModalDialog__Subtitle`: タイトルを補足する短い説明
- `.ModalDialog__HeaderActions`: 表示を閉じる操作を置く領域
- `.ModalSelect`: モーダル内で候補を開閉する選択コンポーネント
- `.ModalSelect__Trigger`: 現在の選択を示し、候補を開く操作面
- `.ModalSelect__Options`: 選択肢の一覧
- `.ModalSelect__Option`: 選択肢1件。現在の選択は`.state-selected`を付ける
- `.ModalDialog__Body`: モーダル固有の内容を置き、必要時に内部スクロールする領域
- `.ModalDialog__Footer`: ダイアログ全体の確定・取消操作を置く領域
- `.ModalFormSection`: モーダル内の入力項目を意味ごとにまとめる`fieldset`
- `.ModalFormSection__Legend`: `ModalFormSection`の入力群の名称
- `.InformationWindowLayer`: 情報ウィンドウを重ねて置く画面固定コンテナ
- `.InformationWindow`: 1件の情報ウィンドウ
- `.InformationWindow__Title`: アイコンと名称を置くタイトル部
- `.InformationWindow__Body`: 効果・説明・関連情報を置くボディ部
- `.InformationWindow__EntityProfile`: Hero・Enemy情報ウィンドウの紹介と戦い方を並べる領域
- `.InformationWindow__Compact`: 情報ウィンドウを縦横50%で表示する切替ボタン
- `.InformationWindow__Pin`: 情報ウィンドウをピン止めする切替ボタン
- `.InformationWindow__Skill`: タグスキルの必要タグ数と名称を示す静的な一覧要素
- `.InformationWindow__UniqueSkill`: Enemy固有スキルを示す、タグ領域第6列の縦長`Ex`要素

要素クラスは `Component__Element` の形式とする。コンポーネントクラスは、配置、寸法、共通レイアウト、出入りアニメーションなど、その部品の構造だけを担う。

### 2.2 意味クラス

表示内容が誰・何に関するものかと、結果の性質を表す。小文字の単語を使う。

#### 主体

- `.hero`: 名前を持つ味方キャラクターが主語の出来事
- `.enemy`: 名前を持つ敵キャラクターが主語の出来事
- `.system`: ゲーム全体、共有資源、期限、進行状態が主語の出来事

効果の対象が味方全体でも、行動者を示せる場合は `.hero` または `.enemy` とする。例: 「○○は味方全体の士気を上げた」は `.hero.info` である。

#### 結果レベル

- `.info`: 通常の情報・状態変化
- `.luck`: ランダム判定などにより主体にとって有利な結果
- `.unluck`: ランダム判定などにより主体にとって不利な結果
- `.warning`: 期限など、注意を要する状態

`luck` と `unluck` は単なる重要度ではない。原則としてランダム判定の上振れ・下振れを表す。期限延長のような計算結果は、個別仕様が定める基準値に従って分類する。

### 2.3 状態クラス

UIの一時状態は `state-` 接頭辞で表す。状態クラスは、意味クラスを置き換えない。

```html
<div class="hero luck state-clickable">…</div>
```

状態が必要になった場合は、`.state-disabled`、`.state-selected` のように `state-` 接頭辞を付けて定義・使用する。これは状態クラスの命名方針であり、ここに挙げた状態の実装を確定するものではない。

現在の進路選択では、確定ボタンをクリック可能にする `.state-clickable` と、空のEnemyスロットを表す `.state-empty` を使用する。

情報ウィンドウのタグスキル名は `.InformationWindow__Skill` とする。タグスキル段階の色・枠・背景は、`TagSkillVisualCatalog` が要素ごとの `--tag-skill-*` カスタムプロパティへ設定する。Lv1〜4は濃い背景色と白文字、Lv0だけは中立の淡色とする。Canvas上のタグバッジも同じカタログを参照するため、必要タグ数とタグスキル名は同じ視覚トークンを使う。属性タグはタグスキル段階を持たないため、未所持はLv0、1個以上はLv1のスタイルに固定する。タグスキル名はクリック・ホバーで反応する操作要素にはしない。

Enemy固有スキルの `.InformationWindow__UniqueSkill` は通常タグの16個目ではない。`Ex`を文字で表示し、対応タグの図案と、中ボスLv1・ボスLv2を示す禍々しさの異なる枠色を用いる。固有スキルの名称とLv別効果は、タップして開く情報ウィンドウで表示する。

Hero・Enemy情報ウィンドウは、タイトル下に `.InformationWindow__EntityProfile` を置く。人物または敵の紹介文と、プレイ上の役割・注意点を短く示す戦い方を分け、紹介文へ仕様説明を無理に混ぜない。タイトル右側には、ピン止めの左へ `.InformationWindow__Compact` を置く。通常表示では中央へ向かう斜め矢印2本で縮小操作を、縮小表示では外側へ向かう斜め矢印2本で拡大操作を示す。縮小中はウィンドウ全体を縦横50%で表示し、ピン止め・ドラッグ位置と独立して状態を保持する。

準備サブエリアのステータスアイコンは、対応するステータス情報ウィンドウを開く。情報ウィンドウ内のステータスアイコンは `.InformationWindow__StatusIcon` とし、タグアイコンの円形フレームとは区別する。

Itemの価値はステータスではなく、ショップ交換に使う用語である。Item情報のタグ一覧と属性一覧は別の構造とするが、`.InformationWindow__ItemBadgeList` は両者のバッジを同じ横並びのレーンに置き、横幅が足りない場合だけ同じ間隔で折り返す。`.InformationWindow__ItemTagList` と `.InformationWindow__ItemPropertyList` はこのレーンの意味上のグループであり、個別の行は作らない。各属性は共通の`.InformationWindow__AttributeBadge`を使い、`.InformationWindow__ItemValue` は金貨の `.InformationWindow__ItemValueIcon` と数値を表示して、クリックすると用語情報ウィンドウを開く。重量・価値のバッジは、タグスキルが未発動のタグバッジと同じ表面・枠を使い、値の種類による色分けは行わない。価値のアイコンは `public/assets/terms/item-value.png` を唯一の表示アセットとする。

訓練エリアのステータスアイコンも同じステータス情報ウィンドウを開く。タグ詳細の本文中に置くステータスアイコンは `.InformationWindow__InlineIcon.state-clickable` とし、タグ詳細を親とするステータス情報ウィンドウを開く。

## 3. スタイルを定義する場所

意味クラス・状態クラスだけに、グローバルな見た目を定義してはならない。

```css
/* 禁止: どのコンポーネントに属するか分からない。 */
.hero { color: blue; }
.luck { background: gold; }

/* 正式: FlowLog内のHeroにとって幸運な表示として定義する。 */
.FlowLog__Entry.hero.luck { /* FlowLog用のHero幸運スタイル */ }
.FlowLog__Entry.enemy.unluck { /* FlowLog用のEnemy不運スタイル */ }
.FlowLog__Entry.system.info { /* FlowLog用のシステム情報スタイル */ }
```

状態スタイルもコンポーネントに限定する。

```css
.FlowLog .state-clickable { cursor: pointer; }
.FlowLog__Entry.hero.luck.state-clickable { /* 必要な組合せだけ追加の強調 */ }
```

## 4. FlowLogのHTML契約

FlowLogは、外側に横断アニメーションとレーン位置を持つエントリー、内側に意味を持つメッセージを置く。`subject` と `level` はエントリーへ付与し、本文だけのアニメーションは `.FlowLog__Text` に限定する。

```html
<article class="FlowLog__Entry hero luck">
  <p class="FlowLog__Message"><span class="FlowLog__Text">剣士・アヴェリーは敵に会心ダメージ120を与えた。</span></p>
</article>
```

ログの発生場所はCSSクラスではなく、ログレコードの `channel` として持つ。現在のchannelは以下とする。

- `battle`: 戦闘
- `shop`: ショップ
- `guild`: ギルド
- `training`: 訓練
- `preparing`: 準備
- `event`: 上記に属さないゲーム進行

表示範囲は発生場所から決める。`battle` は画面上半分、その他は画面下半分からランダムなY座標を選ぶ。表示用の待機列は持たず、すべてのログを即時に横断表示する。channelはレイアウト指定ではなく、ログの発生場所を表す。

システム警告は以下のように表す。

```html
<article class="FlowLog__Entry system warning">
  <p class="FlowLog__Message"><span class="FlowLog__Text">期限の残りは3日です。</span></p>
</article>
```

`system.warning` は他のログより大きく、ゆっくり横断し、本文だけを小さく拡大・縮小する。

## 5. 意味色の変数

同じ意味で使用する色は、個別セレクタへ直接記述せず、`src/styles.css` の `:root` に定義したCSSカスタムプロパティを使う。

```css
:root {
  --color-subject-hero: #2d6ac5;
  --color-subject-enemy: #b84b4b;
  --color-subject-system: #64748b;

  --color-level-info: #64748b;
  --color-level-luck: #bd7b00;
  --color-level-unluck: #a64b61;
  --color-level-warning: #c46a10;
}
```

変数名は `--color-subject-*` と `--color-level-*` を使用する。主体色は「誰の出来事か」、レベル色は「結果の性質」を表す。

FlowLogの組合せスタイルは、必要な意味色・文字サイズ・横断時間を変数から選ぶ。

```css
.FlowLog__Entry.hero.luck {
  --flow-subject-color: var(--color-subject-hero);
  --flow-level-color: var(--color-level-luck);
  --flow-duration: 9s;
}
```

色そのものを個別UIへ再記述してはならない。同じ主体・レベルの意味で使用する色は、必ず上記の変数を参照する。

## 6. JavaScriptとの境界

- ログは `subject`（`hero` / `enemy` / `system`）、`level`（`info` / `luck` / `unluck` / `warning`）、`channel`（発生場所）を別パラメータとして持つ。
- 描画側は、`subject` と `level` を独立した意味クラスとしてエントリーへ出力する。
- 描画側はchannelから画面上半分または下半分のランダムなY座標を選び、直ちに表示する。
- CSSは各組合せの色・文字サイズ・基準横断時間を定義し、JavaScriptは基準横断時間の±15%の速度差とY座標を設定する。
- JSは必要な状態クラスを付け外しする。
- スタイルに無関係な識別子やゲームデータは、`data-*` 属性またはJSの状態として持ち、CSSクラスをデータ格納先にしない。

## 7. アプリケーションモーダル

アプリケーションの進行を前面で扱う画面は、`ModalLayer`と`ModalDialog`を使う。`ModalLayer`は暗転と画面内での配置、`ModalDialog`はタイトル、内容、全体操作の構造を担当する。

```html
<aside class="ModalLayer">
  <section class="ModalDialog" role="dialog" aria-modal="true" aria-labelledby="example-title">
    <header class="ModalDialog__Header">
      <div class="ModalDialog__Heading">
        <h1 class="ModalDialog__Title" id="example-title">タイトル</h1>
        <p class="ModalDialog__Subtitle">補足</p>
      </div>
      <div class="ModalDialog__HeaderActions">…</div>
    </header>
    <div class="ModalDialog__Body">…</div>
    <footer class="ModalDialog__Footer">…</footer>
  </section>
</aside>
```

- Header、Footer、Subtitle、HeaderActionsは必要な場合だけ置く。Bodyは常に置く。
- Headerの操作は表示を閉じるなど、内容を確定しない低リスク操作だけに使う。
- Footerは、OK、保存、出発のようにダイアログ全体の内容を確定する操作に使う。未確定の変更を破棄するキャンセルがある場合は、同じFooterに置く。
- 課題カードの選択のように、本文中の個別要素だけを確定する操作はFooterへ移さない。
- 即時反映する設定はFooterを持たない。閉じる操作は表示だけを閉じ、設定値は取り消さない。
- 小さい表示領域では`ModalDialog__Body`だけをスクロールさせ、HeaderとFooterの操作を画面内に残す。
- `ModalSelect`はOS描画の`select`候補へ依存せず、候補をアプリ側で描画する。現在選ばれている`ModalSelect__Option`は金色で表す。候補はモーダル本文の表示範囲に収まる側へ開き、収まらない場合は候補一覧だけをスクロールする。

モーダル内で入力項目を見出し付きの意味ある群へ分ける場合は、`ModalFormSection`と`ModalFormSection__Legend`を使う。これは設定の言語、ゲーム進行、頭上表示のように、関連する入力をまとめるためのフォーム構造である。選択肢カードやキャラクター一覧を見た目だけの理由で`ModalFormSection`へ置き換えてはならない。
