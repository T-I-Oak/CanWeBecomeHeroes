# 戦闘シミュレーション

## 目的

実装済みの戦闘処理を、描画・UIなしで複数試行し、タグ構成・装備・ステータス・Exスキルによる実測値を比較する。シミュレーターは戦闘式を複製せず、実ゲームと同じ `BattleSystem` と移動・チップ物理・実体管理・装備回収・帰還のクラスを利用する。そのため、これらのゲーム処理の変更はシミュレーションにも反映される。

## 実行

```powershell
npm run simulate:battle -- <conditions.json>
```

標準出力へ整形済みJSONを出力する。

最小の比較例は `examples/simulations/valor-x3-vs-iron-x3.json` であり、次のように実行できる。

```powershell
npm run simulate:battle -- examples/simulations/valor-x3-vs-iron-x3.json
```

```json
{
  "ticks": 10000,
  "trials": 10000,
  "seed": 1,
  "left": [
    { "label": "武勇x3", "tags": ["valor", "valor", "valor"], "weapons": ["sword"] }
  ],
  "right": [
    { "label": "鉄x3", "tags": ["iron", "iron", "iron"], "weapons": ["sword"], "maximumHp": 3 }
  ]
}
```

- `left` はHero陣営、`right` はEnemy陣営であり、各配列は複数キャラクターを指定できる。
- `tags` はキャラクター自身が持つタグ。`Aタグx3` は `["A", "A", "A"]` と指定する。
- `maximums` はHero・Enemyそれぞれの各ステータスMAXを上書きする。シミュレーションでは未指定時も全て3。
- Heroの初期スタミナは `stamina`、Enemyの初期HPは `maximumHp` で指定する。未指定時はいずれも3。
- `weapons` は武器種配列。`{ "weapon": "sword", "tags": ["valor"] }` のように武器のタグも指定できる。未指定のHeroは素手2回、Enemyは素手1回で攻撃する。敵定義を指定しても装備はこの配列から作成する。
- Enemyの `enemyDefinitionId` に `medium-cloth`、`large-water` などを指定すると、その敵のランクとExスキルを使用する。未指定は通常敵。`tags` が未指定なら指定した敵定義の固有タグを使用し、指定した場合はその配列で置き換える。
- Enemyの `uniqueSkill` は `{ "id": "cloth-night-familiars", "level": 2 }` のように上書きできる。`null` を指定するとExスキルを無効化し、同じ敵の有無比較ができる。
- Enemyの `slotPosition` は1〜6の配置。ボスは2枠を使用する。未指定なら空き枠へ配置する。Heroは最大4人、Enemyは合計6枠まで指定できる。
- `seed` を固定すれば同じ入力から同じ結果を再現できる。

### 実ゲームと同じ装備のランダム生成

`equipmentTagBudget` を指定すると、試合ごとに `EnemyFactory.createFromDefinition()` の装備生成を両陣営に適用する。頭・胴・脚・武器2本の5個を作り、予算は装備上のタグの合計個数（0〜15）を表す。固有タグは予算に含めない。固定の `weapons` と同時には指定しない。

個別対戦ではHeroの `mainTag`、Enemyの `enemyDefinitionId` で担当タグを指定する。固有タグを上書きしなければ、Heroは担当タグ2個、Enemyは敵定義の固有タグを持つ。15構成の相性表では設定JSONに `"equipmentTagBudget": 6` を追加するだけでこの方式を両陣営へ適用できる。

部位へのタグ数配分、部位ごとの候補タグ抽選、武器種決定は実ゲームの処理そのものを使用する。属性系の担当はランダムなステータスタグから武器を決めるため、固定の武器対応表は使用しない。試行seedが変わるたびに装備を再生成し、同じseed・入力で再現できる。ステータスMAX・初期スタミナ・HPの指定は維持する。

この方式では、旧来の担当タグ3個・タグなし武器2本や、一時試算の担当タグ3個・他の全タグ1個を適用しない。

### 試合開始時の武器・タグと勝敗の関連集計

`collectPartyLoadouts: true` を指定すると、試合開始時のパーティー全体の武器本数・タグ個数を記録する。タグは固有タグと全装備タグを合算した生の個数で、ステータスMAXによる有効個数への切り詰めは行わない。戦闘中の盗みや消耗後の構成ではなく、開始時の構成と最終勝敗を紐付ける。

個別対戦のJSON出力は `partyLoadouts` を追加する。総当たりCLIは従来の勝率・勝敗CSVに加えて次を出力する。

- `tmp_party-loadouts.csv`: 1パーティー・1試合を1行とし、相手と自分のメイン、陣営、試行番号、seed、結果、戦闘tick、全武器・タグの個数を記録する。1戦にHero・Enemyの2行がある。
- `tmp_weapon-contributions.csv`: 武器1本ごとに、そのパーティーの勝・負・引分を加算する。
- `tmp_tag-contributions.csv`: 固有タグ・装備タグ1個ごとに、そのパーティーの勝・負・引分を加算する。

剣・剣・爪・杖を持つパーティーが勝てば、剣2勝・爪1勝・杖1勝とする。割合の分母は各武器・タグの出現累計（勝＋負＋引分）とし、引分を除外しない。本数・個数別の分類は行わない。この集計は勝敗との関連を示し、単独の因果効果を分離するものではない。

## 出力

出力は勝敗数・勝率、平均戦闘tick、平均与ダメージを返す。ダメージは陣営別のほか、武器種、炎継続ダメージ、鉄反射ダメージの発生源別に集計する。属性付与は最新の付与値を採用する実装に合わせ、炎の継続ダメージはその値を付与した攻撃者へ帰属させる。

中ボス・ボスのExスキルを含む設定例は `examples/simulations/ex-cloth-boss.json` にある。勝敗・平均戦闘tick・平均ダメージの出力形式は通常戦と同じ。

`SimulationBattleDriver` は実ゲームのオブジェクトを生成し、1/60秒・1tickごとに盤面 → 実体管理・装備回収 → 戦闘の順序で進める。描画を省略しても、移動やアニメーション完了時の実体追加処理は進める。召喚敵と幻影頭のダメージはEnemy側へ集計する。

Enemyの召喚が残っている間は勝利としない。Heroが倉庫で装備を回収している間や戦闘へ戻る間は敗北としない。全Heroがスタミナを失う、または戦闘・倉庫回収・戦闘への移動から離れた場合は敗北とする。準備エリアでの回復と手動再出撃、次ステージ、他施設の利用は含めない。双方が残ったまま指定tickに達すると引分とする。

倉庫は開始時に空であり、戦闘中の装備落下・敵の報酬・Exスキルによるアイテム追加は実ゲームの処理で反映する。従来のシミュレーションは移動と倉庫を簡略化していたため、旧出力と新出力を同じ実行条件の結果として混在させない。

## タグのメイン・サブ相性分析

対応武器を持つステータス系10タグについて、敵メインタグと敵サブタグの組合せを比較する。

```powershell
npm run analyze:tag-affinity
```

既定値は `ticks: 1000`、`trials: 20`、`seed: 1`、出力先は `tmp_tag-affinity/`。これらを変える場合だけ、任意の JSON 設定ファイルを引数として指定する。

出力する `matchup.csv` は、味方タグ `T` 2人と敵タグ `t1` 2人の基準2対2の相性表である。`enemyDamageShare = enemyDamage / (heroDamage + enemyDamage)` が `0.5` より大きければ、その組合せでは敵側の総ダメージが大きい。`detail.csv` と `summary.csv` は、この基準結果を使ってサブタグ `t2` への置換効果を示す。

1条件は、次の2対2を比較する。`T` は味方タグ、`t1` は敵メインタグ、`t2` は敵サブタグであり、各キャラクターはタグ3個・対応武器2個を持つ。

```txt
基準: 味方 T, T vs 敵 t1, t1
比較: 味方 T, T vs 敵 t1, t2
```

各戦闘は十分に大きいHP・スタミナで指定tickまで継続する。基準の敵ダメージ比率を `f0 = d0 / (D0 + d0)`、比較の敵ダメージ比率を `ft2 = dt2 / (Dt2 + dt2)` とする。サブ相性は `ft2 / (f0 + ft2)` とし、`0.5` は2人目の `t1` と同程度、より大きい値は `t2` への置換が敵側に有利であることを示す。併せて `ft2 - f0` を実量の改善値として出力する。

10タグでは、基準100条件とサブ置換900条件、合計1,000条件を実行する。`trials` は各条件の乱数試行回数であり、初期設定は20回。`detail.csv` には `T, t1, t2` ごとの値、`summary.csv` には味方タグTで平均化した `(t1, t2)` の相性を出力する。

## 15タグの1対1勝率マトリクス

```powershell
npm run analyze:tag-matchups -- examples/simulations/tag-matchup-matrix.json
```

各タグの通常組合せ定義を使い、`main`、`support1`、`support2` がそれぞれタグ3個・対応武器2本を持つ3対3で、15×15の勝率を算出する。全ステータスMAX・Heroスタミナ・Enemy HPは3とする。行がHero主タグ、列がEnemy主タグで、セルはHero側勝率である。既定の戦闘時間は12時間（6,000 tick）、試行数は200回である。既定で8 workerへHero側の行を分割して実行するため、結果を変えずに計算時間を短縮する。`parallelism` でworker数を変更できる。出力先は `tmp_tag-matchup-matrix/` とし、閲覧用の `matrix.md`、表計算用の `matrix.csv`、勝敗数を含む `matchups.csv`、タグごとの両陣営合計 `tag-outcomes.md` / `tag-outcomes.csv`、実行条件の `conditions.json` を作成する。

設定JSONに `"enemyRank": "midBoss"` または `"enemyRank": "boss"` を追加すると、Enemy側のmainだけを該当ランクにし、定義済みのExスキルを使用する。support1・support2は通常敵のまま。タグ3個・武器2本・HP3の比較条件は維持する。既定値は `regular`。実行したランクは `conditions.json` に記録する。

ステータス系タグは対応武器を2本持つ。属性系は同系列のステータス系武器を1本ずつ持つ。炎は剣・盾、水は杖・聖書、雷は爪・弓、範囲は旗・宝珠、活力は聖印・タロットとする。`tag-outcomes` は各主タグをHero側・Enemy側の両方から集計するため、1タグあたり `15対戦相手 × 2陣営 × trials` 件、既定では6,000件となる。倉庫は開始時に空だが、戦闘中に追加されたアイテムはEnemyの盗み対象となる。`TagMatchupMatrix` は同じシミュレーションドライバーを使用する。
