# v0.61.2 モバイル測定結果

オーナー提供 `mobile-performance-0.61.2-1792742019887.json` を分析した。
元ファイルは変更せず、フレーム配列を除く集計と状態、SHA-256を
[測定記録](mobile_performance_0.61.2_measurements.json)に保存した。

## 改善と残課題

全体表示の通常動作区間は、前回の平均フレーム間隔2274.6ms（約0.44fps）から
31.1ms（約32.2fps）へ改善した。同期処理時間は2198.1msから6.4ms。
Canvasは1200×2015、DPRは2.8125、zoomは約0.1332で前回と同じ。
ただしゲームの進行時点や出現数は完全一致しないため、厳密な同一場面比較ではない。

後半は快適とは判定できない。

| 後半の条件 | 平均フレーム間隔 | 間隔からの換算fps | 同期処理の平均 |
| --- | ---: | ---: | ---: |
| 通常描画 baseline-2 | 174.0ms | 5.7 | 4.5ms |
| 画像描画を省略（模様背景は残す） | 42.1ms | 23.8 | 3.6ms |
| Canvas描画命令を省略 | 12.9ms | 77.7 | 2.6ms |

画像描画を省略すると改善するため、画像を含む描画経路に残る負荷がある。
一方、JavaScript側で計った同期処理時間だけでは長いフレーム間隔を説明できない。
GPU、ラスタライズ、合成などのどの段階が原因かは、この測定だけでは確定できない。
stroke/clip省略では平均165.5/170.2msで、大きく改善しない。

11区間が完了、実行時例外なし。各区間終了時の画像読み込み失敗・未完了は0。
後半の画像キャッシュ予約量は9,611,008bytesで24MiB予算以内。
追加画像準備は約0.6ms、追加縮小画像は0件。

## 測定途中の状態変化

live-minimalはzoom約0.1332を維持し、ゲームが進行した。
live-sections中にzoomが1.5、一時停止に変わり、tick600.444で進行が止まった。
後半の全区間はこの状態で固定されている。

実装上、スタミナ3で自動チュートリアルが開始し、一時停止して対象にカメラを寄せる。
スタミナ回復量と停止時刻が一致するため、自動チュートリアルが始まった可能性が高い。
ただしJSONにチュートリアルの表示状態・停止理由はないため断定しない。
計測開始時はチュートリアル表示を除外するが、計測中に始まる場合は除外していない。
通常動作区間と詳細計測区間の差を計測オーバーヘッドと解釈したり、
前回の全体表示と今回の後半を同条件として比較したりしてはいけない。
