# 情報ウィンドウの差分描画の測定

## 対象

情報ウィンドウのフレーム内通知集約を維持し、LayerのDOM更新と同期的な寸法計算を減らす。
[通知集約の測定](06.information_window_performance_improvement.md)とは旧方式の定義が異なる。
旧方式は通知集約済みの全再生成、新方式はIDごとのDOM保持と表示値の差分更新である。
通常ビルドでは差分描画を使用し、旧方式の復元・切替は計測専用ビルドだけへ入れる。

## 条件と測定方法

390×844 CSS px・DPR 3・seed 54・出現完了・速度1倍・情報表示時の停止なし。
regular/pattern10/level5の敵4体・29チップ・Averyの実体情報1枚を基本条件とする。
標準CPUとCPU4倍で、連続30秒×3反復、同一ページのA1→B→A2は各10秒×3反復。
各反復のウォームアップは5秒。情報表示なしも同じ条件で測り、他の描画・計算の負荷を分けて確認する。
CPU制限はPC上の負荷試験であり、モバイル実機の応答時間を表さない。

旧方式のLayerとEntityRendererはコミット`cb55fad55e49045630aa0456c2858dcf9c5bf274`から取得する。
TrialSessionの通知集約は全区間で有効で、Bの更新を省略しない。
旧方式のクラスは計測ビルドの同じモジュール内にだけ追加し、通常のVite設定は計測用pluginを読み込まない。

```powershell
$env:PERF_SETTLED_INFORMATION = '1'
$env:PERF_OUTPUT = 'tmp_performance/incremental-main.json'
node scripts/measure-performance.js information-incremental-paired information-cpu4-incremental-paired information information-cpu4 idle-dpr3 idle-cpu4
```

PERF_SECONDS・PERF_REPEATS・PERF_WARMUPは上書きしない。
列挙順で条件が選択されるため、実際の順序はidle-dpr3、idle-cpu4、information、information-cpu4、標準往復、CPU4倍往復。
主要測定中はテスト・別のビルドを実行しない。
初期基準値`tmp_performance/incremental-baseline.json`は短い対象テストと重なったため参考値に限定する。
3秒・1反復・ウォームアップ1秒の`incremental-preflight.json`も改善率の根拠には用いない。

主処理時間はGameAppの同期フレーム内処理、renderはLayerの同期呼出時間。
情報更新時間はrenderを含むため、両者を加算しない。
CDPのLayoutDuration・LayoutCountとフレーム間隔を併せて見る。
区間境界はCDPとゲーム状態を逐次取得するため、その間のフレームを含み得る。
分位点は各反復の分位点を別々に取得し、その平均とばらつきを示す。

DOM計数はLayer.renderの同期呼出中だけを対象とする。
createElement・createElementNS・createDocumentFragment、置換・挿入、textContent、setProperty、getBoundingClientRectを計数する。
ブラウザーの全DOM変更・全Layoutの回数ではない。B切替直後の初回構築もBの計数に含む。
数値更新のゲージとタグは既存ノードを書き換え、装備など構造変更時だけ領域を再構築する。
境界時点では実体のゲージ各区画と重量をDOMの値と照合する。
表示と更新の機能検証は要求05、言語切替、実ブラウザーの操作検証で補う。

## 判断と適用範囲

通知集約を保った差分描画と必要時の寸法計算により、同一ページの往復で描画・Layoutと主処理の低減を確認した。
情報1枚・29チップの当該構成を根拠とし、実機の指操作・別の情報構成・多数チップへの効果を断定しない。
多数チップの計算、画像や解像度、ゲームルールは変更対象に含めていない。
0.66.0で移動・拡縮はオーナー確認済み。本文だけの内部スクロールを求めるフィードバックにより、
0.66.1ではヘッダーを本文のスクロール領域から分離した。01は0.66.1で再確認する。
機能検証の対象は[テストの構成](../../tests/README.md)を参照する。
実機の未確認事項を保留する場合は、オーナーの明示的な判断を得て[バックログ](../planning/backlog.md)へ記録する。
