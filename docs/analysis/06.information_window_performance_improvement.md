# 情報更新の性能改善

## 実装と検証対象

[初期調査](05.information_window_performance.md)で確認した、分割更新ごとの情報ウィンドウ再構築を減らす。
0.63.1のTrialSession.updateは、そのフレームでシミュレーションを更新したかを記録し、
全ての分割更新が完了した後にrefreshDynamicEntriesを1回だけ呼ぶ。
途中で自動停止が成立しても、実施済みの計算の最終値をそのフレーム内で通知する。
最初から停止しており計算がなかったフレームでは、動的再描画を行わない。

開閉・ピン・ドラッグ・拡縮・言語変更の直接通知は集約しない。
実体消滅時の閉鎖も分割処理内で即時に実行する。ManagerとLayerの描画仕様は維持する。
この対策は更新を省略せず、表示の更新間隔を一定時間ごとに制限するものでもない。

TrialSessionの結合テストで、通常試験・挑戦の両方について次を検証する。

- 50ms分の複数ステップを実行しても、実体情報への動的通知は1回。
- 通知時のtick・Heroスタミナは、全ステップ終了時の現在値に一致する。
- 停止フレームは動的通知0回。
- 分割処理の途中で自動停止しても、実施済みの計算の最終値を1回通知する。

要求05と関連実装テストで、装備・タグ・現在値、親子の置換・ピン・閉鎖・停止設定・位置・拡縮の既存契約も検証する。

## 性能比較の方法

390×844 CSS px・DPR 3・seed=54・出現完了待ち・速度1倍・情報表示時の停止なしは初期調査と同じ。
敵4体・29チップ・regular/pattern10/level5、Averyの実体情報1枚を使用する。
各条件5秒ウォームアップ後30秒×3反復。旧方式/修正方式の切替は各10秒×3反復。

過去の別実行との差だけでは効果を断定せず、同じページで旧方式A1→修正方式B→旧方式A2を比較する。
旧方式の復元は計測用Vite変換だけで行い、通常ビルドには復元処理・フックを含めない。
A1/A2は分割ステップ内で通知、Bは全ステップ後に1回通知する。全区間で情報更新を有効にする。
元の更新完全省略実験とは異なり、Bは通常アプリに実装した修正そのものを通す。

通常の修正方式は標準CPU・CPU4倍で各30秒×3反復し、CPU4倍の詳細計測なしも3反復追加する。
主要比較とテスト・ビルドは並行実行しない。3秒・1反復の予備測定は別保存する。

```powershell
$env:PERF_SETTLED_INFORMATION = '1'
$env:PERF_OUTPUT = 'tmp_information_optimized_main/results.json'
node scripts/measure-performance.js information information-cpu4 information-cpu4-no-probe information-batching-paired information-cpu4-batching-paired
node scripts/summarize-performance.js docs/analysis/information_window_performance_improvement_measurements.json tmp_information_optimized_main/results.json
```

PERF_SECONDS・PERF_REPEATS・PERF_WARMUPを上書きしない。
生データはtmp_information_optimized_main/results.json、保存用は
[集計JSON](information_window_performance_improvement_measurements.json)。
指標の意味・境界取得の時間差・分位点の定義は初期調査と同じ。

Chrome 155.0.8059.86、Intel Iris Xe / ANGLE Direct3D11、主要Canvasは1170×2532 px。

5条件・15反復を完了し、スクリプトは終了コード0。実行時・consoleエラーと採取開始時の未完了画像は0件。
全反復で課題構成・29チップ・敵4体・主要Canvas寸法が一致し、全フレームで29チップ・速度1倍・停止なしだった。

性能改善の判断には、同一ページのA1/B/A2を用いる。

通知集約をこのブランチの性能改善として採用する。通常アプリの動作で毎フレームの現在値を保ちながら、
DOM再構築回数とレイアウト時間を減らし、主処理・フレーム間隔・進行に改善を確認した。

## 適用範囲と残る負荷

通知の集約を実装し、1回ごとの全DOM再構築・寸法計算は維持する。
この変更に、変更部分だけのDOM更新・画像・解像度・多数チップの計算改善は含めない。
別のウィンドウ構成や実機の操作応答については、このPC測定の数値から再現を保証しない。
内部スクロール・ドラッグ・拡縮・親子やピンの操作について新しい表示仕様は設けない。
CPU4倍は実機の代用ではなく、進行や長いフレームが残る場合は追加対策の判断材料とする。
