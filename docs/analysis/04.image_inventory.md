# 描画画像の種類と必要数

v0.61.5の実装・カタログ・PNGヘッダーを照合した一覧。
以下の旧寸法・計算は検討時点の記録である。0.61.6の配信用寸法の正本は `assets/image-sizes.json`、
生成手順と根拠は `docs/specifications/24.image_conversion.md` を参照する。
PNGファイル数と、ある画面で同時に要求する種類数は区別する。
同じ画像を複数の個体が使う場合、同じ段階は1種類として数える。
同じ元画像でも別の描画サイズが別段階を選ぶ場合、その段階は別に数える。
以下は必要量見積もりの入力一覧であり、24MiBの妥当性を確定した資料ではない。

## 容量見積もりに使う同時数

オーナーの指示により、通常画面の見積もりは勇者4種類、敵は小型3種類・中型1種類・大型1種類とする。
敵の数は「ほぼ最大」という見積もり条件であり、全状態の厳密な上限を実証したものとは区別する。
パーティー選択の勇者8種類は他の画像がほとんど出ない別画面なので、通常画面へ8種類を加算しない。
下表の登録数・候補画面の種類数はカタログ情報として残し、同時必要数へそのまま加算しない。
エリア背景6種類はcreatePatternに元画像を使うため24MiBの段階画像キャッシュ外。
ただしゲーム全体の画像メモリ見積もりには256×256×4bytes×6＝1.5MiBを別枠で計上する。
戦闘枠の地面trampled-groundはこの6種類とは別で、段階画像キャッシュの対象として1種類を計上する。
外周CSS背景・元画像・ブラウザー内部の追加保持量も段階画像キャッシュ予算とは分ける。

## 段階画像を生成済みの元画像

| 用途 | 登録種類数 | 元画像寸法 | 通常画面で必要な種類の範囲 |
| --- | ---: | --- | --- |
| エリア・施設の看板 | 6 | 1024×1024 | 常時6種類。各画像44×44のゲーム内寸法 |
| 勇者 | 8 | 1024×1024 | 通常プレイは最大4人で最大4種類。パーティー選択は最大8種類 |
| 小型敵 | 16 | 1024×1024 | 小型15系統と特殊な分身1種類。通常戦闘は6枠の範囲で、出現構成による |
| 中型敵 | 15 | 1024×1024 | 同上。全15種類が同時に必要とはしない |
| 大型敵 | 15 | 1024×1024 | 1体2枠。全15種類が同時に必要とはしない |
| 武器 | 10 | 256×256 | 倉庫・装備・店・落下中アイテム等の内容による。最大10種類として保守的に数えられる |
| 行き先アイテム | 3 | 256×256 | 買い物袋・ライセンス・更新書類。最大3種類 |
| 頭装備 | 5 | 256×256 | タグに応じた図柄5種類 |
| 胴装備 | 5 | 256×256 | 同上 |
| 足装備 | 5 | 256×256 | 同上 |
| タグ | 15 | 1024×1024 | 勇者パネルの一覧で全15種類を描画。チップ・装備・店・演出でも共用 |
| ステータス | 9 | 1024×1024、weightのみ1254×1254 | 通常Canvasは7種類。hp・durabilityは情報UI向けで別扱い |
| 戦闘枠の地面 | 1 | 256×256 | 10箇所に描くが同じ画像なので1種類。ゲーム内224×224 |
| 合計 | 113 | | 同時に113種類使うという意味ではない |

勇者は開始2人＋加入上限2人。人数が増えても職業が同じなら図柄は共用する。
戦闘は6枠で、通常の課題構成は主役・支援1・支援2の3系統。
召喚はsmall-vitality・medium-vitality、分身はsmall-area-headを追加要求し得る。
課題選択は3候補それぞれ最大3系統なので、候補の図柄は合計最大9種類（重複を除くと減る）。
課題選択の図柄は本戦とは描画サイズが異なるため、同じ元画像でも段階を分けて見積もる。
タイトル演出は勇者・敵・装備のカタログから別途生成するため、通常戦闘の同時数をそのまま当てはめない。

## 図柄の内訳

- 看板6種類: battle、guild、preparation、shop、training、warehouse。
- 勇者8種類: swordfighter（ファイル名swoardfighter）、guard、mage、cleric、thief、hunter、merchant、negotiator。
- 敵45種類: 以下の15系統それぞれsmall・medium・largeの3サイズ。
  valor、iron、arcane、cloth、dexterity、feather、gem、reputation、blessing、fortune、fire、water、lightning、vitality、area。
- 特殊な敵1種類: small-area-head（カタログID phantom-area-head）。
- 武器10種類: sword、shield、staff、holy-book、claw、bow、orb、banner、holy-symbol、tarot-cards。
- 行き先アイテム3種類: shopping-bag、hero-license、renewal-form。ファイル名はhand-で始まる。
- 防具15種類: head-1〜5、torso-1〜5、feet-1〜5。
- タグ15種類: valor、arcane、dexterity、reputation、blessing、iron、cloth、feather、gem、fortune、fire、water、lightning、area、vitality。
- 通常Canvasのステータス7種類: power、magic、speed、negotiation、luck、stamina、weight。
- 情報UI向け2種類: hp、durability。
- 戦闘枠の地面1種類: background/trampled-ground。

## 最大zoomでの通常画面1フレームの概算

この区間の9.86MiBは元画像に戻る画像を除外した特定zoomの値であり、キャッシュ予算の判断には使用しない。
オーナーが求めた「各画像の大きい方から2サイズ」の見積もりは次節を採用する。

条件はzoom=1.5、DPR=3、チップscale=1。勇者4種類、小型敵3種類、中型1種類、大型1種類。
実際のselectImageLevelとマニフェストで段階選択を照合した。容量はRGBA換算。
全ズーム・全画面の最大値ではなく、この通常画面条件での保守的な概算である。

| 用途 | 段階寸法 | 種類数 | MiB |
| --- | ---: | ---: | ---: |
| 小型敵 | 512×512 | 3 | 3 |
| 画面端の勇者誘導肖像 | 256×256 | 4 | 1 |
| 看板 | 256×256 | 6 | 1.5 |
| ステータス | 128×128 | 7 | 0.4375 |
| 装備・アイテム上のタグ | 64×64 | 最大15 | 0.234375 |
| 勇者一覧・小型敵・移動演出のタグ | 128×128 | 最大15 | 0.9375 |
| 勇者・中型敵・店のタグ | 256×256 | 最大7 | 1.75 |
| 大型敵のタグ | 512×512 | 1 | 1 |
| 合計 | | | 9.859375 |

256pxタグは勇者4＋中型1＋店2を重複なしとして計上し、実際に図柄が共通なら減る。
各段階15種類のタグと勇者誘導4種類も、多めに計上した条件である。
勇者・中型敵の中央絵は必要734.4pxで512px段階では足りず、元画像1024pxへ戻る。
大型敵も元画像、アイテムと戦闘枠の地面も元画像256pxを使うので、この条件の段階キャッシュ加算は0。
元画像を保持するAssetLoaderのメモリや背景はこの9.86MiBには含まない。
前回使用画像の保護・過去キャッシュ・別zoom・選択画面の段階はこの1フレームとは別に扱う。

寸法は変換前のゲーム内座標。プレビューと画面端の誘導表示は別の座標系なので別記する。
通常チップのscale=1を基準に記載。縮小演出はこれより小さくなる。

| 小型敵の中央絵 | 108.8×108.8 |
| 中型敵の中央絵 | 163.2×163.2 |
| 大型敵の中央絵 | 326.4×326.4 |
| アイテムチップの中央絵 | 63.75×63.75 |
| 装備欄のアイテム | 64×64 |
| 店の買い物袋 | 48×48 |
| 看板アイコン | 44×44 |
| ステータスアイコン | 24×24 |
| 勇者のタグ一覧の図柄 | 14.4×14.4 |
| 装備のタグの図柄 | 11.52×11.52 |
| 勇者・中型敵のタグの図柄 | 29.0304×29.0304 |
| 小型敵のタグの図柄 | 19.3536×19.3536 |
| 大型敵のタグの図柄 | 58.0608×58.0608 |
| アイテムチップのタグの図柄 | 11.34×11.34 |
| 店のタグ・タグ移動演出の図柄 | 最大34.56×34.56、27.36×27.36 |
| 戦闘枠の地面 | 224×224 |

| パーティー選択の勇者中央絵 | 217.6×217.6 Canvas px（256px Canvas、DPR倍率なし） |
| 課題選択の敵中央絵 | 100×敵直径/224×0.85 CSS px（DPRあり、camera zoomなし） |
| 課題選択の店タグの図柄 | 27.36×27.36 Canvas px（38px Canvas、DPR倍率なし） |

PNGはすべて正方形。通常Canvasは各寸法にcamera zoomとDPRを掛け、足りる最小段階を選ぶ。
生成段階は元画像より小さい8・16・32・64・128・256・512・1024pxの該当サイズ。
適切な段階がなければ元画像を描く。元画像は段階画像キャッシュ24MiBの計上外で、AssetLoaderが別途保持する。
従って「元画像の種類数×最大寸法」だけを段階画像キャッシュ量と呼んではいけない。

## 段階画像キャッシュの対象外

| 用途 | 種類数 | 元画像寸法 | 内訳 |
| --- | ---: | --- | --- |
| エリアの模様背景 | 6 | 256×256 | battle、guild、preparation、shop、training、warehouse。createPatternで使用 |
| 外周背景 | 1 | 1536×1024 | outer-ground。CSS背景 |
| 条件アイコン | 9 | 1024×1024 | bewilderment、ellipsis、fire、lightning、misfortune、night-familiar、physical-defense、two-edged-sword、water |
| 属性演出 | 3 | 1254×1254 | fire、lightning、water |
| 盾演出 | 1 | 1024×1024 | physical-shield |
| 混乱演出 | 1 | 1024×1024 | bewilderment-swirl |
| 使い魔演出 | 1 | 1254×1254 | night-familiar |

条件アイコンはdrawScaledImageを経由するが、マニフェスト未登録なので元画像を使用する。
盾・属性演出も同様。混乱・使い魔演出は元画像を直接drawImageする。
ロゴ・DOMの情報アイコン・開始劇の背景・共有画像も公開アプリ全体の画像メモリには関係するが、
今回の通常ゲームCanvasの段階画像24MiB予算には含まれない。

## 各図柄の大きい方から2サイズを保持する見積もり

オーナーの指示に従い、特定zoomの描画結果ではなく、各図柄の最大2段階を合計する。
元画像へ戻ることを理由として、その図柄の段階画像を見積もりから除外しない。
同時数は勇者4・敵5（小型3、中型1、大型1）を使用し、他の種類数は上記一覧を使用する。

| 図柄 | 種類数 | 1種類あたりの段階 | 合計MiB |
| --- | ---: | --- | ---: |
| 勇者 | 4 | 512px＋256px | 5 |
| 敵 | 5 | 512px＋256px | 6.25 |
| 看板 | 6 | 512px＋256px | 7.5 |
| タグ | 15 | 512px＋256px | 18.75 |
| 通常ステータス6種＋weight | 7 | 通常512px＋256px、weightのみ1024px＋512px | 12.5 |
| アイテム | 28 | 128px＋64px | 2.1875 |
| 戦闘枠の地面 | 1 | 128px＋64px | 0.078125 |
| 合計 | 66 | | 52.265625 |

寸法・段階は実際のマニフェストの末尾2段階から集計した。RGBA換算で約52.27MiBとなり、24MiBには収まらない。
元画像を保持する別枠のメモリ・背景画像は含まない。実際の1フレームでこれら最大段階が同時選択されるとの主張ではなく、
オーナー指定の保守的な保持予算である。上限の変更や対象画像の縮小など、実装方針はこの計算だけで自動変更しない。
