# アプリケーション構成

## 1. 方針

本番のゲーム実装と、開発中にだけ必要なランダム生成・確認用ガイドは別の責務として扱う。

- `src/chips/`: ゲーム・デモの双方で使う共通チップライブラリ。物理、描画、衝突、移動を担当する。
- `src/game/`: Hero、Item、タグ、固定ワールド、ゲーム操作などのゲームルールと状態を担当する。
- `src/app/`: Canvas、カメラ、入力、描画ループを持つ本番アプリケーション基盤を担当する。
- `src/demo/`: ランダムな初期配置など、ゲーム本体に含めない検証用シナリオを担当する。

## 2. 起動経路

`src/main.js` は `startGame({ scenario })` を起動する。現在は表示確認のため `createDemoScenario()` を渡している。

将来はデモシナリオを外し、セーブデータや開始時ゲーム状態から生成する本番シナリオへ差し替える。`GameApp` 自身はランダム生成やデモ専用の表示ガイドを持たない。

## 3. 本番アプリ基盤

`src/app/GameApp.js` の責務は以下とする。

- `ChipBoard`、`Camera`、`HeroItemInteractionController` の生成と更新
- Canvasのリサイズ、Chipからの選択ドラッグ、ドラッグ移動、ホイールズーム、詳細表示用のタップ入力
- ワールド・準備エリアのゲーム画面描画
- シナリオが返すHeroと、シナリオ固有の追加操作・確認描画の受け渡し

## 4. デモシナリオ

`src/demo/DemoScenario.js` は検証専用であり、ゲーム仕様ではない。

- ランダムな重複なし2 Heroの初期配置（スタミナ0）と、各Hero向け2セットの開始時装備ドロップ
- 行き先Item 3種のランダム初期配置

## 4.1 Heroスロット管理

`src/game/HeroSlotManager.js` は、戦闘・ショップ・ギルド・訓練のHero用スロットを管理する。予約と占有を別状態として持ち、複数Heroが同時に移動しても同じスロットを選ばないようにする。戦闘スロットの予約優先順は `2 → 3 → 1 → 4` である。

`src/game/ItemPickupController.js` は、Heroごとの拾得状態を保持する。複数Heroの移動・吸収・行き先スロット移動を同時に更新し、目的Itemが盤面から消えた場合は次の装備可能Itemへ再ターゲットする。

`src/game/HeroItemInteractionController.js` は、全Chipを基点にできる共通のドラッグ選択状態と、Hero・Item・袋の組み合わせに応じたゲーム処理を接続する。Canvas上の点線・基点枠・有効／無効の終点枠は `GameApp` が選択状態を描画する。Chipのタップは選択状態を変更せず、将来の詳細表示に使う。選択UI自体は処理の完了内容を持たず、袋格納・HeroのItem取得などの組み合わせ側へ委譲する。

## 4.2 ゲーム時計

`src/game/GameClock.js` は、一時停止とゲーム速度（x1／x2／x4）を管理する。描画・カメラ操作は常に継続し、ゲーム状態の更新だけを停止または加速する。加速時は最大1/60秒の内部更新へ分割し、チップの衝突・移動・吸収アニメーションを安定させる。

`src/game/StaminaRecoverySystem.js` は、ゲーム内1/60秒のtickを蓄積して準備エリア滞在Heroのスタミナ回復を処理する。

`src/game/ShopState.js` は今回・次回・次々回の販売タグ傾向を保持する。UIは今回と次回だけを表示する。進路選択で選んだ候補の傾向を反映し、ShopにHeroが滞在中なら今回販売を維持して次回・次々回へ反映する。

`src/game/ShopSystem.js` はショップ到着後の売買フェーズ、購入品の段階的な開示、購入品の倉庫への配送を担当する。`src/game/GuildSystem.js` はギルド到着後の申請と期限延長を担当する。`src/game/FacilityReturnSystem.js` はショップ・ギルド・訓練に共通の装備整理と準備エリアへの帰還を担当する。`src/game/BattleSystem.js` は戦闘と、敵全滅時の勝利確定・勝利待機を担当する。`src/game/StageController.js` は進路候補の生成、選択後の敵出現、勝利待機後の次回選択を担当する。

`src/app/StageSelectionModal.js` は、カメラ拡大率に影響されない画面固定の進路選択モーダルを担当する。選択中は `GameClock` の理由付き停止によってゲーム内部時間を停止し、Canvasの背景描画は継続する。候補ごとに6敵スロットを表示し、Enemy Chipは通常戦闘と同じ `ChipRenderer` で、雑魚・中ボス・ボスのサイズ比を保って描画する。遭遇イベント・加入候補は現時点では表示しない。

## 4.3 ゲームログと通知

`src/game/GameLog.js` はゲーム起動中のユーザー向けログをメモリに保持する。ログは主体（`hero`、`enemy`、`system`）と結果レベル（`info`、`luck`、`unluck`）を別に持つ。`src/app/NotificationCenter.js` は通知対象のログを画面右へ一時表示するUIであり、Canvas・カメラとは独立した画面固定レイヤーとして描画する。

## 5. 仕様書の区分

- `docs/specifications/`: 実装済みのエンティティ・チップモデル仕様
- `docs/requirements/`: ゲームルール、画面・操作要件、設定資料
- `docs/architecture/`: 実装の責務分割と起動構成
- `docs/demo/`: 検証専用の挙動
- `docs/planning/`: 未実装作業と優先順位
