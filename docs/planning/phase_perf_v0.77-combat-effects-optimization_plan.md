# 戦闘演出の性能改善計画

## 合意内容

- 2026-10-30、オーナーはPERF-02〜04を一つの開発として扱う提案に合意した。
- ブランチ: `perf/v0.77-combat-effects-optimization`
- 予定バージョン: `0.77.0`。計画中は現行`0.76.0`を維持し、初回実装開始時にpackage.json・package-lock.jsonを更新する。
- 根拠: [バックログ](backlog.md)。調査詳細はコミット`8615200`の`docs/planning/phase_perf_v0.75-mobile-performance-investigation_v1.md`と同ブランチのレビュー報告を履歴から参照する。

## スコープと実装方針

### PERF-02 雷の描画状態

`src/game/CombatEffectSystem.js`の雷ループ前後でCanvas状態をsave/restoreする。draw全体の既存save/restoreは維持する。雷のshadow・折線・色・時間は維持し、後続の使い魔・惑乱・文字・タグへshadowColor、shadowBlur、strokeStyle、lineWidth等を漏らさない。

### PERF-03 使い魔画像

`public/assets/effects/night-familiar.png`を惑乱と識別できる配色へ変更し、`drawNightFamiliar`の`grayscale(1) brightness(0.32)`指定を削除する。紫色案は却下済み。真っ黒や現行の白黒再現は必須ではない。具体色は未決定なので、実装時に画像案を提示してオーナー判断を得る。画像編集にはimagegenスキルを適用する。透過・輪郭・図柄位置を保ち、公転、羽ばたき、出現、飛行、被弾による減少を維持する。制作元がある場合は制作元と配信用の整合を保つ。新しい汎用画像キャッシュを作らない。

### PERF-04 盾・属性リング

`ChipRenderer`は既に`drawImageContain`から`drawScaledImage`を使う。対象画像を既存の`assets/image-sizes.json`と制作元管理へ追加し、既存の`npm.cmd run generate:image-levels`でPNG段階画像と`src/chips/image-levels.json`を生成する。対象の正確なパスと必要寸法は実装時に描画式・元画像を照合して決める。元の配信用画像の解像度を落とさず、段階画像を追加する。演出の枚数、付与値によるサイズ・透明度・揺れを変更しない。

既存の段階選択・24MiBキャッシュ・フレーム保護を利用する。要求解像度を満たす段階がない場合と段階読込失敗時は元画像を使う。読込中は既存の描画待機動作を維持し、初回の表示遅延とキャッシュ圧迫を確認する。今回の対象追加のためにキャッシュ方式を刷新しない。

## 対象外

- 戦闘計算、ゲーム進行、ゲーム内文言、ログ表示仕様の変更。
- HUD・背景の最適化、画面全体の解像度低下、演出の省略。
- 保存形式の変更、旧データ移行、URLへのバージョン付与。
- 共通GameWorksOAKリポジトリの変更。
- バックログの既存オーナー検証項目の再依頼。

## 完了条件

1. 雷単独の変更前後の画素が同一で、雷の描画状態が後続へ漏れない。混在時の意図した影の消失を確認する。
2. 完成した使い魔画像が惑乱と識別でき、透過・輪郭と既存の動きを維持し、描画時filterが不要になる。
3. 盾・属性リングに要求サイズを満たす段階が選択され、最大ズーム・高DPR・強い属性付与で画質と形状を維持する。元画像fallback、初回読み込み、キャッシュ容量と他画像への影響を確認する。
4. 各変更を分離した比較と、3変更を合わせた状態の確認を行い、条件・反復値・限界を実装報告へ記録する。完成使い魔画像で再計測し、filter省略だけの過去値を実装成果へ転用しない。
5. 対象テスト、全テスト、本番ビルド、必要な実ブラウザー確認を行い、コマンドと結果を記録する。失敗は原因と対応を記録する。
6. オーナー検証の判断・フィードバックと対応を実装報告へ記録する。未回答や未対応を残したまま終了草案へ進まない。明示保留だけを同じIDでバックログへ記録し、チャットで通知する。

## テスト・計測方針

- `CombatEffectSystem.test.js`へ描画状態の隔離と後続描画の回帰確認を追加する。複雑な状態処理を追加する場合はテストを先に作成する。
- `ChipRenderer.test.js`、`ScaledImage.test.js`、`ImageLevelCache.test.js`、`ImageConversion.test.js`で対象登録・段階選択・寸法とハッシュ・fallback・容量保護の関連契約を確認する。既存の動作と生成対象の変更に応じて意味のある検証を追加する。
- 実装中に対象テストを実行し、終了草案前に`npm.cmd test`と`npm.cmd run build`を実行する。主要フロー・本番起動は`npm.cmd run test:browser`で確認する。
- 画素比較は同じCanvas寸法・演出時刻・位置・画像decode状態で行う。雷単独と混在を分け、リングの縮小再サンプリング差を完全一致の条件にしない。
- 性能は同一ページで旧A1→変更B→旧A2、各10秒・ウォームアップ5秒・3反復を基本とする。雷単独／混在、完成使い魔、盾・リングを分ける。同期main、フレーム間隔p95/p99、CDP TaskDuration、対象数、画像読込、実行時エラーを記録する。測定中に別テストやビルドを並行実行しない。
- 過去の人工48枚や小さいChipの値を通常戦闘へ外挿しない。PCの人工比較をAndroid/Vivaldi実機の改善率・症状解消と扱わない。改善が確認できない場合は条件と結果を示して判断を求める。
- 確認用fixture・比較ビルド・PNG・生JSONは`tmp_`配下へ置く。計測専用経路を通常ビルドへ含めない。

## オーナー検証予定

実装が確認可能になった時点で、各IDに理由・操作手順・期待結果・実際の確認バージョンを添えて提示する。以下は予定であり、確認済みではない。

| ID | 判断対象 |
| --- | --- |
| PERF-02 | 雷の見た目を維持し、後続演出の紫色の影が消えること |
| PERF-03 | 完成使い魔画像の配色・輪郭・透過・惑乱との識別性 |
| OV-PERF-03-MOTION | 使い魔の公転・羽ばたき・出現・飛行・減少の動き |
| PERF-04 | 最大ズーム・高DPR・強い属性付与で盾・属性リングの画質が十分なこと |
| OV-PERF-04-MOTION | 盾・属性リングの枚数・付与値に伴うサイズ・透明度・揺れの維持 |
| OV-PERF-04-LOADING | 初回読み込みやズーム変更時の演出表示に支障がないこと |

タイトルと倉庫左下の表示がpackage.jsonの確認バージョンと一致することを確認する。実機の判断をPCの自動検証で代替しない。
