# v0.35 タイトル画面の修正計画

## 1. 目的と開発単位

バックログ「操作とゲーム画面を拡充する」の先頭3項目を対象に、タイトル画面の表示と設定操作を修正する。

- 開発ブランチ: `codex/v0.35-title-menu`
- 基点: `master` の `d916a6a`。
- 初回実装時のバージョン: `0.35.0`。
- バージョン設定は実装開始時に更新する。計画時点では `0.34.0` を維持する。
- 差し戻し時のPatch更新はブランチ作業フローに従う。
- 定期見直しはMinorの末尾が0のときだけ実施する。次回は `0.40.0`。
- オーナー指示で変更した定期見直し周期の文書差分を、このブランチで維持する。

## 2. 現状の確認

- `public/data/text/ui.json` の日本語 `challengeMode` は「無限挑戦モード」である。
- バックログの「無限朝鮮モード」は同じタイトル項目を指すものとして扱う。
- `TitleMenu` は試験クリアー後にチャレンジモードのメニューボタンを追加する。
- タイトルの設定は専用のインラインパネルであり、HUDの設定モーダルとは別実装になっている。
- HUDの設定モーダルには、言語、ゲーム進行（速度・自動停止・自動加速）、頭上ステータスの項目がある。
- 言語選択は共通i18nとゲーム側の `ModalSelect` を使用する。
- `ModalSelect.placeOptions()` は `.ModalDialog__Body` を必須の配置基準として参照する。
- タイトル設定のDOMにはその祖先がなく、選択肢を開く経路に構造の不整合がある。
- タイトルのレイアウトは固定の余白・ボタン寸法と全高中央配置を組み合わせている。
- チャレンジボタン追加後も含め、縦幅が狭い場合の収まりを確認する必要がある。

## 3. 実装スコープ

### モード名

- タイトルの日本語表示を「チャレンジモード」にする。
- 英語も対応する名称に揃え、既存の言語リソースで管理する。
- チャレンジモードの解放条件、開始経路、ゲームルールは維持する。

### メニューとHUDで共有する設定モーダル

- HUDの既存設定モーダルをメニューからも開く。画面の構成・DOM・開閉処理・設定値の管理を共通化する。
- `TitleMenu` の専用設定パネルと言語選択を撤去し、共通設定画面を開く処理へ委譲する。
- 起動元を明示して表示項目を切り替える。初期方針は、メニューからは言語のみ、HUDからは言語・ゲーム進行・頭上ステータスを表示する。
- 起動元による差は共通画面内の項目の表示／非表示で扱い、別の設定画面や別の保存処理を作らない。
- 言語選択も既存モーダル内の1つの実装を共有する。タイトル専用の配置基準を `ModalSelect` に追加する対応は行わない。
- 必要な責務分離として、モーダルの開閉・起動元・項目表示は共通の設定画面管理へ集約し、時間設定コントローラーは時間設定の処理を担当する。
- 言語変更直後にタイトルのメニュー・設定文言・選択中表示へ反映する。
- 設定を閉じて再度開く、試験開始後にタイトルへ戻る、ページを再読込する経路を確認する。
- 言語保存・解決・同期は共通i18nを利用し、ゲーム側で重複実装しない。
- 開いた選択肢の片付け、再表示時の起動元と表示項目の更新、閉じた際の起動ボタンへのフォーカス復帰を共通処理で扱う。
- タイトルより設定モーダルを前面に表示し、設定表示中は背面のメニューを操作できないようにする。
- HUDから開く間はゲームを停止し、閉じると設定表示による停止理由だけを解除する。手動停止などの他の停止理由を維持する。
- メニューから開いても試験を開始せず、閉じるとタイトルの操作へ戻る。
- 言語以外の既存設定やHero解放状態を初期化しない。

### 縦幅が狭い画面

- タイトルのロゴ、メニュー、クレジットに表示領域を割り当てる。設定は共有モーダル内で収める。
- 画面の高さに応じて余白・ロゴ・フォント・ボタン寸法を実値で調整する。
- `100dvh` とsafe areaを考慮し、ページ全体のスクロールを発生させない。
- UI全体の `transform: scale()` による縮小は使用しない。
- 通常の横長スマートフォン相当でも、設定を含む全メニューを画面内に収める。
- 極端に小さい表示領域で内部スクロールが必要なら、タイトルまたは共有モーダルの内部に限定し全操作へ到達可能にする。
- 言語選択肢の上下配置・高さ制限と、クレジットとの重なりを確認する。

## 4. 対象外と制約

- 新しい設定項目、記録画面の機能追加、チュートリアル、ドラッグ操作の拡張。
- カメラ、ピンチ、設定画面の共有に必要な部分以外のHUD、戦闘、数値調整、シナリオ、ラン結果の新規変更。
- 定期見直しとしての全体リファクタリング。
- GameWorksOAKのファイル変更。共通基盤の修正が必要なら問題と必要な変更を報告する。
- 要求仕様の独断変更、push、公開、オーナー検証の代理承認。

## 5. 変更対象と進め方

1. 実装開始時に `package.json` と `package-lock.json` を `0.35.0` へ更新する。
2. タイトルと言語選択の挙動を再現し、HUD設定の開閉・停止制御・設定値保存の接続を確認する。
3. `public/data/text/ui.json` のモード名を修正する。
4. `TitleMenu.js`、`GameApp.js`、`TimeSettingsController.js`、`index.html` を必要な範囲で調整し、共有の設定画面管理を接続する。起動元と項目表示の定義を一か所に集約する。
5. `src/styles/screens.css` と設定モーダルの関連CSSで、タイトルと共有設定画面の高さに応じたレイアウト・前後関係を調整する。
6. 動作と整合する範囲でローカライズ・UI仕様を更新する。
7. バックログの対象3項目を整理し、実装報告にオーナー検証候補を1件ずつ記録する。

## 6. テストと表示確認

- 起動元別の項目表示、開閉、フォーカス復帰、停止理由の解除、設定値の維持を共有設定画面のテストで検証する。
- 対象テスト: `node --test tests/implementation/TimeSettingsController.test.js tests/implementation/ModalSelect.test.js tests/implementation/LocalizedUI.test.js tests/implementation/TranslationIntegrity.test.js`。共有設定画面とタイトルの連携テストも追加・実行する。
- メニューとHUDが同じ設定画面を開き、メニュー専用の設定DOM・選択要素を生成しないことを確認する。
- ブラウザで設定を開き、日本語から英語、英語から日本語へ切り替え、エラーなく閉じられることを確認する。
- メニュー→試験開始→HUD→タイトル再表示の順で、表示項目の切替と言語・時間・頭上ステータスの設定値の維持を確認する。
- 再読込で選択言語が維持されることを確認する。
- 未クリアー／クリアー済みの両方で、メニュー表示と開始経路を確認する。
- 表示確認の基準viewport: PC `1280×720`、タブレット `768×1024`、スマートフォン縦 `390×844`、横 `844×390`、低い横画面 `667×280`。
- 日英両方でロゴ・全ボタン・設定選択肢・閉じるボタン・クレジットの収まりを確認する。
- レイアウトは実際のブラウザ描画で確認し、CSS文字列の一致だけを完了根拠にしない。
- 全テスト: `npm.cmd test`。本番ビルド: `npm.cmd run build`。
- 最後に `git diff --check`、変更ファイルとバージョン表示を確認する。
- 失敗時は原因を調査し、既存または範囲外の失敗は根拠と今回修正しない理由を報告する。
- テストと要求が矛盾する場合は、都合よくテストを変えずオーナーへ確認する。
