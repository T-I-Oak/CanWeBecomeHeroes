# Windowsのブラウザーテスト終了待ち

## 目的と合意内容

Windows環境でブラウザーテスト成功後にコマンドが終了しなかった記録について、
再現条件と原因を確認し、修正の要否を判断する。必要な修正と修正後の検証まで含める。

- ブランチ: `fix/v0.62-browser-test-shutdown`
- 予定バージョン: `0.62.0`。実装開始時にpackage.jsonとpackage-lock.jsonを更新する。
- バックログの事実・推測の区別と、過去の作業条件の削除を付随する文書整理として含める。

## 根拠の扱い

過去の記録では標準ブラウザーテスト3件の成功後にwebServerの終了処理が戻らず、
Viteをプロセス内で管理した同じテストは正常終了したとされる。
これは過去の観測であり、現行版での再現と原因は未確認である。
プロセス構成の違いだけで原因や採用する修正方式を確定しない。

## スコープ

1. 標準コマンドで現象の再現と終了状態を確認する。
2. テスト実行、ビルド、開発サーバー、preview、起動用シェルと子プロセスの終了を切り分ける。
3. 原因と修正要否を判断し、必要ならゲーム側の検証設定・実行補助を修正する。
4. 修正前後の条件と結果を比較し、標準コマンドの終了、サーバーの解放、再実行を確認する。
5. 必要なテスト手順とバックログを更新する。

## 対象外

- 情報ウィンドウと多数チップ時の性能調査・最適化。
- ゲームの挙動、画質、画像配信方式の変更。
- GameWorksOAKの変更。必要な場合は根拠と変更要求を報告する。
- マージ・push・公開。これらは後続のフェーズで扱う。

## 調査・実装方針

- Node、npm、Playwright、Vite、OS、ブラウザー、実行コマンドと環境変数を記録する。
- 調査開始前に4174・4175の利用状況を確認し、既存の別プロセスを調査対象と混同しない。
- 標準コマンドの実行開始、テスト完了、プロセス終了の時刻、終了コードを記録する。
- 外側に待機上限を設け、終了待ち時のプロセス・ポートとログを取得して切り分ける。
  調査で起動したプロセスだけを後処理し、待機上限による打ち切りを正常終了と扱わない。
- 必要な場合にサーバー別、起動方法別の比較を行う。観測・推測・未確認事項を分ける。
- 原因に対応する最小の修正を採用し、テストの削除、検証内容の弱体化、
  終了コードの上書きによって成功扱いにしない。
- ライフサイクル管理のロジックを追加する場合は、終了・失敗時の契約を先にテストで定義する。
- 再現しない場合も、確認条件と回数、残る不確実性、修正不要とする根拠を記録する。
  再現しないことだけを原因解明や解消の証拠にしない。

## 検証方針

- 修正前後で同じブラウザー・環境変数・標準コマンドを使う。
- `npm.cmd run test:browser` の全3件の成否とコマンドの終了を別々に記録する。
- 正常終了後に4174・4175と起動した子プロセスが残らず、続けて再実行できることを確認する。
- 起動・テスト失敗や中断の後処理は、変更した管理処理に関係する範囲で検証する。
- Windowsでの修正がCIの起動方法に及ぼす影響も確認する。
  他OSを実行できない場合は、確認できた範囲と未確認事項を区別する。
- 実装終了草案の前に `npm.cmd test`、`npm.cmd run test:browser`、
  `npm.cmd run build` を実行し、対象検証と合わせてコマンド・結果を実装報告に残す。
- 失敗は原因を調査し、今回の変更が原因なら修正する。範囲外なら根拠と未対応理由を記録する。
- オーナーの判断が必要な検証が生じた場合は、一意ID・理由・操作・期待結果・版を提示する。

## 完了条件

- 現行版の再現結果と、修正要否の判断根拠がある。
- 修正が必要な場合は実装し、修正前後の終了所要時間・終了コード・プロセス残存を比較している。
- 標準コマンドが全テストを実行し、後処理を終えて正常終了し、再実行できる。
  達成できない場合は未解決として報告し、修正完了と扱わない。
- 全テスト・ブラウザー検証・本番ビルドの結果と必要な判断を実装報告へ記録している。
- バックログから過去の作業条件を除き、性能の2件を未検証の調査候補として残している。
- 調査・修正結果を反映し、この終了待ち問題を未解決のまま誤って削除していない。
