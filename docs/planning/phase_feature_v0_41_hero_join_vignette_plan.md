# 開発計画: Hero加入寸劇の実装と会話設定整理

## 開発スコープ
バックログ「2. シナリオ演出とゲームランへの導入を整備する」のうち、以下の項目を対象とします。
1. `docs/content/hero_character_profiles.md` (Hero会話用設定資料) をレビューし、確定情報と会話用初稿を整理する。
2. Hero加入時の寸劇を実装する。
   - シナリオプレイヤーの役割: 定義済みのシナリオ再生のみを担当。
   - シナリオジェネレーターの役割: 出撃Party、加入Hero、事前に知り合いのHeroなどのコンテキストから、台詞・登場人物・特別演出を選択・構築する責務を担う。

## 対象外
- ゲームラン自体の記録・結果画面の実装（バックログの「3. ゲームランの記録と結果を設計する」以降の項目）は今回のスコープに含めません。
- 既存の開始劇（`08.start_vignette.md`）の基本的な再生ロジックそのものの大幅な改修は最小限にとどめ、ジェネレーターからの入力を受け取れるようにする範囲とします。

## 完了条件
- `hero_character_profiles.md` がレビュー・整理され、コミットされていること。
- シナリオジェネレーターの実装が完了し、状況（加入Hero、Party構成など）に応じた寸劇データを生成できること。
- 生成された寸劇データがシナリオプレイヤーで正しく再生され、Hero加入の演出として画面上で機能すること。
- 上記の実装に対応する自動テスト（対象テスト）が作成・合格し、全テスト・本番ビルドが成功すること。

## 実装・テスト方針
1. **文書更新**: `hero_character_profiles.md` を精査し、必要な情報を加筆・整理します。
2. **設計・実装**: 
   - 寸劇データを動的に生成するジェネレータークラス/関数を設計し、状態管理と統合します。
   - シナリオプレイヤーに対して、生成されたシナリオデータを渡して再生を開始するフローを構築します。
3. **テスト**: 
   - ジェネレーターが状況に応じて正しいシナリオオブジェクトを生成するかを単体テストで確認します。
