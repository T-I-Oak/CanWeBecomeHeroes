# タグスキル上限と実績・説明の整合計画

## 合意した開発内容

- ブランチ: `fix/v0.73-tag-skill-caps`
- 予定バージョン: `0.73.0`。計画中は設定を更新せず、初回実装開始時に更新する。
- タグスキルの上限を対応するステータス上限に依存させ、実際の発動段階、表示、アチーブメント、二つ名、説明を整合させる。

## 調査で確認した現状

- Hero・Enemyの `getTagSkillLevel()` は、ステータスMAXで制限した有効タグ数からLvを求めている。武勇7個でもパワーMAX3ならLv2となる。
- `StatisticsCollector` は装備込みの生タグ数を記録する。アチーブメントとタグスキル由来の二つ名は、その最高保持数を参照している。
- `docs/requirements/06.run_records.md`、`docs/specifications/14.achievements.md`、`docs/specifications/15.achievement_classes.md` は、タグ数について能力上限を適用しないと定めている。
- `docs/specifications/17.trial_result_screen.md` は最大保持数からタグスキル由来の二つ名を決める。実際に発動できる段階とずれる可能性がある。
- アチーブメントの所見はスキル習得を説明するため、生タグ数での判定では実際に使用できないスキルを習得済みと表現し得る。
- 「タグスキルはステータス上限に依存しない」という直接の記述は確認できなかった。ゲーム内のタグスキル説明には、ステータス上限による制限の説明がない。

## スコープ

1. Hero・Enemyの有効タグ数、スキルLv、戦闘・施設効果、情報表示の参照経路を照合し、不足を修正する。
2. アチーブメントの判定・所見とタグスキル由来の二つ名が、実際に到達した有効タグ数・スキル段階と整合するようにする。生タグ収集記録との役割を区別し、必要な記録・参照経路を整備する。
3. 装備変更と訓練によるMAX更新を含め、同じ時点のタグ数と上限を用いて実績を記録できることを確認する。過去の最高保持数へ現在の上限を後付けして、未到達の段階を合成しない。
4. 既存の保存記録について、新しい記録との互換性と扱いを設計し、テストする。過去に到達した有効タグ数を復元できない場合は推測で生成しない。既存実績の扱いなど利用者への影響がある選択は、実装中に具体案と根拠を提示して判断を得る。
5. 要求・仕様、タグスキル説明、アチーブメント所見、関連する日英文言を点検し、上限を適用しない説明や説明不足を今回の仕様に合わせる。
6. 完了したバックログ項目を整理する。

## 対象外

- スキル発動の必要タグ数（1・3・5・7）と各効果量の変更。
- Itemの重量・価値計算の変更。
- 生タグ数による収集履歴自体の廃止。
- ブラウザーテストの制限環境におけるサーバー終了待ちへの対応。
- GameWorksOAKの変更。

## 完了条件

- 対応するステータスMAX3〜7に応じて、タグスキルの発動段階と表示・効果が一致する。
- 上限を超える生タグ数だけで、未到達のスキル段階を示すアチーブメント・所見・二つ名が新規に生成されない。
- 装備変更・訓練後の記録が正しく更新され、異なる時点の保持数とMAXを組み合わせた誤判定がない。
- 既存保存記録の扱いが明文化され、互換性を検証している。
- 関連文書と日英説明が実装と一致する。
- 対象テスト、全テスト、本番ビルドを実施し、結果を実装報告に記録する。必要なオーナー検証はID・バージョンを付けて提示し、判断と対応を記録する。

## 実装・テスト方針

- 上限計算は既存の `TagCatalog` を起点に参照を確認し、重複した段階計算と情報源の食い違いを避ける。
- 実績の記録・保存・評価に関する変更は、先に仕様を表すテストを用意して実装する。
- 境界はタグ0・1・3・5・7・8個以上、MAX3〜7、対応する5ステータスと10スキルタグを対象にする。
- 生タグ収集と有効タグ実績、装備・解除、MAX更新、ラン・累積、保存・再読込、アチーブメント所見・二つ名の接続を検証する。
- 主な対象は `tests/spec/01.game_settings.test.js`、プレイ記録の仕様テスト、`StatisticsCollector`・`GameStatistics`・`Achievements`・`StatisticsHooks`・`TrainingSystem`・`HeroEpithets`・`EpithetTagSkill`・情報表示と翻訳の関連テストとする。実際の責務に合わせて追加・更新する。
- 最終検証は `npm.cmd test` と `npm.cmd run build`。ブラウザーでの主要フローは `npm.cmd run test:browser` を使用し、制限環境固有の終了待ちは既存手順に従って結果と原因を区別して記録する。
- オーナー検証が必要な説明・所見・二つ名・既存記録の扱いは、確認可能な実装を用意した時点で具体的に提示する。
