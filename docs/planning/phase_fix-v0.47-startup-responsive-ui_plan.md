# 起動時表示・画面サイズ追従の改善計画

## 合意した開発単位

- ブランチ: `fix/v0.47-startup-responsive-ui`
- 予定バージョン: `0.47.0`。初回実装開始時に `package.json` と `package-lock.json` を更新する。
- 対象バックログ: 「1. 起動時の表示と画面サイズへの追従を改善する」の3項目。
- オーナーは開発内容とブランチ名に合意済み。メニュー名は画面確認後に調整する可能性があり、その調整も今回の範囲に含める。

## 開発スコープ

1. アプリ起動時にロゴが一瞬大きく表示される現象を改善する。HTMLにあるHUDロゴと、JavaScript経由のCSS読み込み順を確認し、表示サイズが確定するまで表示を抑えるなど、初期描画から意図した寸法を維持する。
2. フロートログの文字サイズを画面サイズに応じて縮小する。本文とアイコンの比率、警告演出、ログの移動・寿命・一時停止への影響も確認する。
3. タイトル画面のメニュー名を、まず「勇者認定試験に挑む／実力判定試験／成績表／設定」に変更する。画面確認後の文言と収まりの調整を含め、オーナー確認の結果をもって名称を確定する。
4. オーナーの追加指示により、試験の残り期限が3・2・1日へ到達した瞬間に「試験の残り期限 あと○日」の警告ログを出す。期限延長後に同じ境界へ再到達した場合も再通知する。日英で意味を揃える。

## 対象外

- 試験内容、戦闘バランス、難易度、結果・記録機能の変更。
- 実力判定試験の解放条件変更。現行の試験クリア後に表示する条件を維持する。
- GameWorksOAK共通ライブラリ・共通ルールの変更。
- バックログの他の開発項目、および今回と無関係な保留中のオーナー検証。

## 完了条件

- 起動直後、CSSの読み込み前後を含めてロゴが意図しない大きさで表示されない。
- スマートフォン縦画面・横画面・PCで、フロートログの文字とアイコンが画面サイズに応じた読みやすい表示になる。リサイズ時も追従する。
- 日本語タイトルメニューに合意した名称を表示し、画面確認で必要となった名称・収まりの調整を反映する。言語切替と各メニューの遷移が機能する。
- 必要な画面確認項目を個別に提示し、オーナーの判断・フィードバックへの対応を記録する。未回答を保留と解釈しない。
- 関連する対象検証、全テスト、本番ビルドを実施し、コマンドと結果を実装報告へ記録する。失敗時は原因を調査し、範囲内の原因を修正する。
- 実装した挙動を必要な仕様書へ反映し、バックログを判断結果に合わせて更新する。

## 実装方針

- `index.html`、`src/app/GameApp.js`、`src/styles.css`、HUD・タイトルのCSSを確認し、初期描画のサイズ制御を行う。起動失敗時や画像読み込み中の表示も確認する。
- `src/styles/flow-log.css` の本文32px固定指定と既存の画面サイズ別指定、ログの寸法計測処理を確認する。CSSによる寸法・フォントサイズの調整を基本とし、可読性を確認して縮小の範囲を定める。
- タイトルメニューの文言は既存の `GameTextRepository` と `public/data/text/ui.json` を経由する。ラベルの他画面での使用箇所と英語表示への影響を確認し、必要ならタイトル専用のラベルを設ける。
- 既存の遷移先、解放判定、設定・成績表の動作を維持する。
- 共通のCSS・モバイル・多言語規定、およびゲーム固有のブランチ作業フローに従う。

## 検証方針

- 起動時は再読み込みと読み込み速度を落とした条件で、初期表示からロゴの寸法が安定することを確認する。
- PC、スマートフォン縦横の代表画面サイズで、ログ本文・アイコン・警告演出とタイトルの収まりを確認する。画面サイズ変更後も確認する。
- 通常試験の開始、解放条件前後の実力判定試験の表示、成績表・設定の開閉、日英切替を確認する。
- 既存の関連テストを確認し、今回の変更に必要な対象検証を実施する。初期描画や可読性はブラウザ表示でも確認する。
- 実装終了草案の提示前に `npm.cmd test` と `npm.cmd run build` を実行する。
- オーナー確認では実装時のバージョンを明記し、タイトルと倉庫左下の版表示の一致を確認条件とする。ロゴ初期表示、ログの縦横の見た目、メニュー名・収まりを必要な単位で個別に提示する。

## 計画時点の確認事項

- 計画段階ではアプリ実装とバージョン設定を変更しない。
- 計画承認後の引継ぎ書に、メニュー名は画面確認後に調整可能であることを明記する。
