# 延長申請書のファビコン設定計画

## 合意した開発内容

- ブランチ: `feature/v0.52-favicon`
- 予定バージョン: `0.52.0`
- バックログの「共有と公開を整備する」から、ファビコン設定だけを対象とする。
- オーナーが選んだ延長申請書の既存画像 `public/assets/items/hand-renewal-form.png` を使用する。

## 目的と範囲

ブラウザタブとブックマークでゲームを識別できるようにする。延長申請書の金縁の書類、羽根ペン、青い封蝋を識別の手掛かりとし、小さい表示では書類と羽根ペンの輪郭を中心に確認する。

既存画像を使用してファビコンを設定する。小サイズでの見え方を確認し、必要な場合はファビコン用画像を用意する。ゲーム内で使う元画像の見た目は維持する。画像の加工が必要なら、適用する画像関連スキルの指示に従う。

## 対象外

- シェア機能。
- `project_info.json` の紹介文・タグ・コンセプト画像。
- GitHub Pagesの公開フロー変更と主要フローの受入テスト整備。
- ゲームバランス、ゲーム内アイテムの表示や挙動の変更。
- GameWorksOAK側の変更。

## 完了条件

- 延長申請書を使ったファビコンがブラウザタブ・ブックマークで表示できる。
- 開発環境と本番ビルドの両方で、画像が読み込める。
- 本番のベースパス `/CanWeBecomeHeroes/` で参照が解決できる。
- 小さい表示で書類と羽根ペンの輪郭を確認し、必要な見た目のオーナー検証を提示して判断を記録する。
- 全テストと本番ビルドが成功する。

## 実装方針

1. 実装開始時に `package.json` と `package-lock.json` を `0.52.0` に更新する。
2. 既存PNGと小サイズでの表示を確認し、必要な画像形式・サイズを選ぶ。文字の可読性をアイコンの識別条件にはしない。
3. `index.html` にアイコン参照を追加する。Viteのベースパスを考慮し、開発時と本番成果物で参照先を確認する。
4. 確定した構成を必要な文書へ記録し、バックログではファビコンの項目だけを整理する。共有と公開の残りの項目を完了扱いにしない。
5. 実装結果、検証結果、オーナー検証の判断を実装報告へ記録する。

## 検証方針

- 開発サーバーと本番ビルドの配信でアイコン参照・画像取得を確認する。
- 小サイズ（16px・32pxを目安）の見え方と、ブラウザタブ・ブックマークでの表示を確認する。
- 静的な参照追加に対し、実装を写すだけの単体テストは追加しない。画像取得と本番成果物を直接確認する。
- `npm.cmd test` と `npm.cmd run build` を実装フェーズの終了草案提示前に実行する。
- 見た目のオーナー検証では `0.52.0`（再実装時は更新後のPatch）を示し、タイトルと倉庫左下のバージョン一致を確認条件とする。タブとブックマークはそれぞれ1件の検証として、操作手順・期待結果とともに提示する。
- 未回答のオーナー検証を独断で保留にせず、プロジェクトのブランチ作業フローに従う。
