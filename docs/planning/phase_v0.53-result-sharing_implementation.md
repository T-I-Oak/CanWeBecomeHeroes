## 実装内容

- TrialResultPaperへ通知・成績表の描画と文字組みを抽出。終了画面と画像生成で同じ終了情報、言語リソース、CSSを使用。
- TrialResultShareImageは画面外の固定サイズDOMでタイトル画像、表裏、AppMetadataのcopyrightを構成。画像とフォントの読み込み後、computed styleと画像データを埋め込んだSVG foreignObjectからCanvasへ描画してPNGを生成。論理888×1340、出力1776×2680。操作ボタンと紙吹雪を含めない。
- 既存の紙のグラデーション・罫線・文字色・赤い更新判定・署名・印影を維持。長い二つ名で名前が欠けることを検出し、折り返しと本文の下余白24pxを共通CSSで修正。
- 表示時に画像を先行生成し、共有操作時は同じ画像を利用。画像生成・共有中の多重実行を防止。閉じた後の生成完了で共有を開かない。表示面や記録の選定・集計・保存には触れない。
- TrialResultShareServiceはPCとモバイルで分岐。PCはPNGのクリップボードコピー後にTrialResultShareConfirmを表示し、「Xを開く」で本文入りの投稿画面を開く。画像はユーザーが貼り付ける。「閉じる」・EscapeではXを開かない。ネイティブdialogでフォーカスを制御。PC表示のiPadもモバイルとして扱い、モバイルではPNGと本文を端末共有へ渡す。AbortErrorはキャンセル。非対応・権限不足・その他の失敗は再試行案内を表示。
- ボタン順は裏返し→結果をシェアする→タイトル復帰。日本語・英語の操作・状態表示を追加。モバイルの操作高と画面内の配置を維持。
- 終了画面仕様、バックログ、手動確認手順を更新。合意内容を計画書へ記録。

## 共有フローのフィードバック対応

オーナーからPCとモバイルのフローを問われた際、初回実装はAPI対応状況だけで共有とPNG保存を分岐していると説明した。「それは計画が間違っています」との指摘に基づき、他ゲームのPC画像コピー→確認→X投稿画面、モバイル端末共有へ計画・実装・検証手順を修正。先のPNG保存のオーナー検証依頼は取り下げた。画像の構成・共有文は維持。
