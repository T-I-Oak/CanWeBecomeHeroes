# タッチドラッグ中のルーペ表示計画

## 開発内容

- ブランチ: `feature/v0.71-touch-drag-loupe`
- 予定バージョン: `0.71.0`
- 対象バックログ: モバイルでHeroをItemへドラッグすると、対象Itemが指に隠れて狙いにくい問題。
- 指の周辺を別枠に拡大表示し、対象に重なる前から、目当てのItemとの位置関係を確認できるようにする。

## 合意した範囲

- タッチでChipのドラッグ選択が始まった時点からルーペを表示する。対象への重なりを表示条件にしない。
- ルーペには実際の指の位置を中心として周辺の盤面とChipを拡大表示する。中央の印で、指の位置と対象判定位置が一致することを示す。
- ルーペを指から離して配置し、画面端でも表示枠に収める。表示位置の調整で実際の対象判定位置を変えない。
- 指の位置で対象を判定し、指を離したときに確定する。既存の対象枠・点線とルーペの表示内容を一致させる。
- 対象がない位置でも周囲を表示し続け、ドラッグ終了、キャンセル、ピンチ開始で消す。
- ドラッグ選択、端での自動スクロール、ズーム、タップ詳細表示を維持する。マウス操作ではルーペを表示しない。
- 実装に対応する要求・仕様・テスト文書とバックログを更新する。

## 対象外

- レコード画面の既知項目管理、タグスキル上限、テストサーバー終了待ちへの対応。
- タップによる対象選択への変更。オーナーより、初期に採用した後にやめた方式であると説明されているため、再導入しない。
- 指から対象判定位置をずらす照準方式、対象に重なったときだけ表示する確認カード。
- GameWorksOAKの変更。

## 完了条件

1. 有効なタッチドラッグ選択の開始後、対象のない場所でもルーペが表示され、指の周囲のItemへ狙いを合わせられる。
2. ルーペ中央と実際の指の位置が一致し、拡大率・カメラ位置・画素密度によって対象判定とのずれが発生しない。
3. 対象切替、対象のない位置、有効・無効な組み合わせで、既存の選択表示と確定結果が一致する。
4. 画面端でもルーペの枠が画面内に収まり、端の自動スクロール中も内容が追従する。
5. 終了・キャンセル・キャプチャ喪失・ピンチ開始時に残像や選択の誤確定がなく、次の操作を再開できる。
6. マウス、タップ詳細表示、空白からのパン、方向表示からの選択、ピンチズームの既存操作が維持される。
7. 対象テスト、全テスト、本番ビルドの実行結果を記録し、失敗があれば共通手順に沿って調査・対応する。
8. モバイル実機で、拡大率、表示位置、対象の狙いやすさについてオーナーの判断を得る。明示的に確認を保留する場合は、検証IDと判断を実装報告・バックログへ記録する。

## 実装方針

- 初回実装開始時に `package.json` と `package-lock.json` を `0.71.0` へ更新する。計画時点では更新しない。
- `GameCanvasInput` のドラッグ開始・移動・終了処理を基点とし、Pointer Eventsの入力種別と選択状態からルーペの表示状態を管理する。
- `TrialSession` の描画処理と `SelectionGuideRenderer` を確認し、盤面と選択ガイドを反映した拡大表示を専用の描画責務へ分離する。
- ルーペ自身を再び取り込まない描画順序とし、表示用の追加描画でゲーム状態・演出時間を進めない。
- CSS px、Canvas内部解像度、カメラ座標の変換を明示し、拡大表示だけに倍率を適用する。入力・対象判定には適用しない。
- DOMまたはCanvasのルーペが入力や対象判定を遮らない構成とする。
- 大きさ・拡大率・指との距離は実装時に調整する。表示枠の画面内配置と指から離す配置の両立を検証し、位置切替のちらつきを避ける。
- 複雑な座標変換・状態管理はテストを先に作成する。画面全体の不要な再描画や毎フレームのCanvas生成を避ける。

## 検証方針

- 入力・状態: `GameCanvasInput`、`DragControls` の既存テストを拡張し、タッチ限定の表示開始、空白での継続、終了・キャンセル・ピンチによる解除を検証する。
- 座標・描画: 新設モジュールに対応する実装テストで、ズーム・パン・画素密度・画面端の座標変換と、ルーペ自身を含まない描画を検証する。
- 要求仕様: `tests/spec/02.hero_item_interaction.test.js` へルーペ表示と指位置での対象確定の契約を追加する。
- ブラウザー: 対象への重なり前、対象切替、画面端、スクロール、ズーム後、マウス非表示を確認する。エミュレーションと実機での確認を区別して記録する。
- 全テスト: `npm.cmd test`。本番ビルド: `npm.cmd run build`。ブラウザー検証の起動・終了は `tests/02.browser_verification.md` に従う。
- オーナー検証は拡大率、表示位置、狙いやすさをそれぞれ独立した一意IDで提示し、確認理由・操作手順・期待結果・確認バージョンを記載する。
- 確認バージョンはタイトル・倉庫左下の表示と設定を照合する。URLへのバージョン番号追加は禁止する。
