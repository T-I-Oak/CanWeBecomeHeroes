# v0.80 定期見直し計画

## 合意内容

- 対象プロジェクト: CanWeBecomeHeroes。
- 作業ブランチ: `refactor/v0.80-periodic-review`。
- 予定バージョン: `0.80.0`。計画中は現在の `0.79.0` を維持し、初回の実装開始時に `package.json` と `package-lock.json` を更新する。
- 目的: Minorの下1桁が0になる開発として、共通ルールに従い文書とソースを定期点検する。
- バックログの要望・バグ指摘、オーナー検証は計画時点でいずれも「なし」。

## 開発スコープ

| 点検対象 | 確認と整理の内容 |
| --- | --- |
| 開発ルール | 共通ルールとプロジェクト固有規定を読み直し、適用範囲を確認する。共通側の未コミット変更を正式な規定として扱わない。 |
| 文書 | `docs/`、`tests/` の説明文書、関連するREADMEの記述と現行実装、章構成、参照先を照合する。古い記述や参照切れを修正し、必要な分割を行う。 |
| テスト | `docs/requirements/` と `tests/spec/`、実装モジュールと `tests/implementation/` の責務・配置を照合する。対応表が実際の検証範囲を表すことを確認する。 |
| ソース | `src/`、`scripts/`、エントリーポイントと設定を対象に、未使用コード、文書との整合、ファイルサイズ、責務分担を点検する。参照元と実行経路を確認した上で、挙動を維持する整理を行う。 |
| バックログ | 要望・バグ指摘の依存関係と優先順、オーナー検証の判断単位を確認する。範囲外の発見事項は要望・バグ指摘へ記録する。 |

依存物、生成物、Git管理領域を自作ソースの整理対象に含めない。共通ライブラリは参照先と契約を確認するが、GameWorksOAKは変更しない。

## 対象外

- 新規機能、ゲーム仕様・バランスの変更。
- 定期見直しの範囲を外れる不具合修正。発見時は根拠とともにバックログへ記録する。
- 共通基盤の修正。必要な場合は問題と必要な変更をオーナーへ報告する。
- v0系の旧保存データの移行・補正・旧評価維持の追加。

## 実装方針

1. 共通の文書・コーディング・CSS・モバイル規定と準拠チェックリストを読み、対象ファイルを列挙する。
2. 文書の参照・実装記述、ソースの行数と参照関係、テストの責務対応を点検し、結果を実装報告へ記録する。コードは1ファイル500行の規定、文書は意味の区切りと100～300行程度の目安に照らして判断する。
3. 未使用と確認できたコードの削除、責務に沿った分割、現状に合わせた文書修正を行う。見た目・入力・状態遷移・計算結果を維持し、推測だけで動的参照や外部契約を削除しない。
4. 分割・移動時はimport、テスト配置、文書の構成説明と参照を合わせる。必要なテストは挙動と契約を検証し、実装の写しとなるテストは追加しない。
5. ゲーム内文言の変更が必要になった場合は、修正箇所と修正前後の全文をチャットへ提示し、合意後に反映する。URLへのバージョン番号付加は行わない。
6. 点検結果、変更ファイル、範囲外の発見、検証結果を `phase_refactor_v0.80-periodic-review_implementation.md` へ記録する。

## テスト方針

- 実行方法と検証範囲は `tests/README.md` と `tests/02.browser_verification.md` に従う。
- 整理したモジュールに対応する対象テストを随時実行する。複雑なロジックに触れる必要がある場合は、変更前に期待する挙動をテストで固定する。
- 実装終了草案の提示前に `npm.cmd test` と `npm.cmd run build` を実行する。文書・設定だけの変更でも省略しない。
- 起動、描画、入力、画面遷移、アセット読込に影響する整理を行った場合は、対応するブラウザー検証を実施する。実行条件と正常終了を記録する。
- 失敗時は原因を調査し、今回の範囲または変更が原因なら修正して再実行する。既存・範囲外の失敗は内容、調査根拠、今回修正しない理由を報告する。仕様とテストが矛盾する場合はオーナーへ確認する。
- オーナー判断が必要な項目が生じたら、実装中に一意ID、理由、操作、期待結果、設定と一致する確認バージョンを提示する。タイトルと倉庫左下のバージョン一致も確認条件とする。未回答を保留扱いにしない。

## 完了条件

- 上記の各点検対象について、確認範囲と結果が実装報告に記録されている。
- 必要な整理と文書修正が完了し、変更によるゲーム仕様の変更がない。
- 分割・移動した場合は参照、テストの責務・配置、文書が整合している。
- 範囲外の発見事項はバックログに記録され、追加内容がチャットで通知されている。
- 対象テスト、全テスト、本番ビルドのコマンドと結果、および必要なブラウザー検証の結果が記録されている。失敗には調査結果と対応方針がある。
- 必要なオーナー検証の判断・対応が記録され、未回答や未対応のフィードバックが残っていない。明示的な保留はバックログへ反映されている。
