# 固有スキルの仕様受入テスト整備

## 合意内容

- 開発ブランチ: `test/v0.57-unique-skills-acceptance`
- 予定バージョン: `0.57.0`。初回の実装開始時に `package.json` と `package-lock.json` を更新する。
- 対象要求: [固有スキル](../requirements/03.unique_skills.md)。要求文書の変更は、オーナー指定の暴風の翼の対象・演出に限定する。
- 目的: 発動条件からゲーム上の結果までを接続して検証し、既存の内部処理テストと役割を分ける。
- オーナー合意による追加範囲: 暴風の翼の演出を、等倍のHeroが上へ飛ばされた後、倉庫でHeroと周囲の装備Itemが同時に落下する順序へ修正する。
- 暴風の翼はEnemyには発動しないというオーナー指定を要求03へ反映する。
- 演出確認でのオーナー指定: 上昇中に着地点へ移動し、影をその場に残さず追従させる。上昇から落下への切替時に地上座標を変えない。
- 確認用Heroには頭・胴・両手・足の全5装備を持たせる。装備はHeroから離して、方向と距離にばらつきを持たせて散らばらせる。
- 演出の連続性を保つため、装備はHeroと同じ位置から離れる過程を表示する。Heroの上昇高さは既存の登場時の落下開始高さに合わせ、Hero・装備とも上昇と落下の間で地上位置・高さを切り替えない。

## 開発範囲

- `tests/spec/03.unique_skills.test.js` を追加する。
- Enemy専用・中ボスEx1・ボスEx2の共通規則と、全15種の固有スキルを対象とする。
- 実際の戦闘処理とFactoryで生成したキャラクターを接続し、発動後の状態・ダメージ・召喚・装備・移動先などを確認する。
- Ex1・Ex2の差、主要な不発条件、解除条件を確認する。
- [テスト構成](../../tests/README.md)の要求対応表と検証範囲を更新する。
- [バックログ](backlog.md)の対応項目を実装結果に合わせて整理する。

## 実装・検証方針

1. 要求03と既存の実装・結合テストを照合し、戦闘の入口から結果までを検証するシナリオを設計する。
2. 内部の効果定義・フック名・中間データだけを確認するテストの重複追加を避ける。乱数と時間は制御し、期待値を本番カタログから転載して計算しない。
3. 本番処理の接続を残し、効果そのものをスタブで置き換えない。本番コードへテスト専用フックを追加しない。
4. テスト用補助コードが必要な場合はテスト側へ置き、各ファイルを共通の500行制限内に収める。
5. 仕様との矛盾を発見した場合は、要求や期待値を独断で変更しない。内容を報告し、修正の扱いをオーナーへ確認する。
6. 対象テスト `node --test tests/spec/03.unique_skills.test.js`、要求仕様テスト `node --test "tests/spec/*.test.js"`、全テスト `npm.cmd test`、本番ビルド `npm.cmd run build` を実行し、結果を実装報告へ記録する。
