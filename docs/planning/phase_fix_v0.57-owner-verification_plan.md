### テストスクリプトによる確認

オーナー指定により以下20項目を自動検証へ移す。未実行の項目を確認済みにしない。各IDとテスト名・検証内容・結果を実装報告へ対応付け、成功後にバックログの該当オーナー検証項目を削除する。

| --- | --- |
| OV-FORTUNE-03/12/14 | Ex1の双方への会心分配、Ex2の自傷のみ、行動後の呪い解除・アイコン消去 |
| OV-ARCANE-03/13/14 | 炎水雷の減衰と反射の表示同期、既存の強い属性の維持、反射の再帰と追加演出の防止 |

### 実装中に追加で届くオーナー検証結果

今回列挙された項目だけで受付を締め切らない。実装フェーズ中も、バックログに残る既存オーナー検証項目についてオーナーから結果が届く前提で進め、以下を実装作業に含める。

- 受領の都度、項目ID、判断、指摘内容、対応結果を実装報告へ追記する。
- 「項目確認済み」「項目却下」は該当項目をバックログから削除し、再検証を依頼しない。「現時点で確認しない」は指定された確認時期・条件とともにオーナー検証欄へ反映する。
- 既存オーナー検証項目への文言・表示・演出・動作の修正、およびテストスクリプトによる確認依頼は、このブランチの追加対応に含める。必要な対象テストを追加・実行し、修正後に必要な再確認を提示する。
- 新機能や要求仕様そのものの変更が必要な場合は、変更案と影響を示し、スコープ変更への合意を得てから着手する。無関係な新規要望・不具合はバックログの「要望・バグ指摘」へ記録する。オーナーが修正を指示したブロッキングバグは作業フローに従って対応する。
- 終了草案は、その時点までに受領した結果をすべて整理し、必要な修正・再検証・オーナー判断が完了してから提示する。未回答を担当者判断で保留にしない。今後届く可能性があるという理由だけで、未受領の結果を待ち続けることもしない。
- バージョンは初回実装開始時に0.57.1とする。同じ修正版の実装途中に追加結果が届いても項目ごとにPatchを上げない。終了草案の差し戻しなど、作業フローが定める再修正開始時にPatchを上げる。

## 対象外

- 新機能、追加のフィードバックを受けていない指定外のオーナー検証項目の自発的な消化、合意していない戦闘仕様の変更。
- 共通ルールの正式採用判定、GameWorksOAK側の変更。
- 今回の指摘と無関係な不具合修正。発見時はバックログへ記録する。

## 実装・検証方針

1. オーナー判断をバックログへ反映し、文言を修正する。
2. `tests/spec/03.unique_skills.test.js` と関連する実装テストを各IDへ照合する。数値の成功だけで表示・演出の検証完了とせず、状態同期、イベント、演出の対象や回数、復帰経路まで必要な根拠を確認する。
3. 不足する検証は既存の責務に適したテストへ追加する。必要ならブラウザテストを使う。表示を単にテスト名で主張するだけの検証にしない。
4. 対象テスト、`npm.cmd test`、`npm.cmd run build` を実行し、コマンドと結果を実装報告へ記録する。失敗時はブランチ作業フローに従って原因を調査する。
5. 文言修正の結果を提示し、追加のオーナー判断が必要なら実装中に取得する。テスト確認を依頼された20項目を一律に手動検証へ戻さない。
6. 実装中に届く追加結果を上記の方針で随時取り込み、必要な修正・対象テスト・記録を更新する。全テストと本番ビルドの後に変更が生じた場合は、最終変更を含む状態で再実行してから終了草案を提示する。

計画時の予備確認として `node --test tests/spec/03.unique_skills.test.js` は36件成功した。この結果だけを指定20項目の完了根拠にはしない。
