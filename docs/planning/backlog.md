# 開発バックログ

この文書は、次に着手する新規開発と、実装済みでオーナー確認を待つ作業だけを管理する。`要望・バグ指摘` は上から依存関係と優先順に並べる、全体作業計画の唯一の台帳とする。新しい要望は該当する段階の適切な位置へ追加し、必要に応じて全体の順序を見直す。開発ブランチの開始・検証・終了の運用は[ブランチ作業フロー](01.branch_workflow.md)を参照する。確定済みの仕様は `docs/requirements/`、実装済みの構造は `docs/specifications/` を参照する。

## 要望・バグ指摘

### 0. バックログの完全性を確認する
- オーナーからの要望、過去のバックログ、要件、実装済み仕様を照合し、各項目を「未完了」「オーナー検証」「完了」「廃止・統合」に分類する。
- 未完了の要望だけを、このバックログの依存関係順に残す。完了・廃止・統合済みの項目を推測で復元しない。
- 寸劇システム、物理防御エフェクト、固有スキル、記録・結果、UI、公開準備の各領域について、要望の漏れがないことを確認する。

### 1. 戦闘基盤とEnemyコンテンツを整備する

- Enemy Chip中央絵を共通アセット契約へ移行する。全Enemyアセットを、正方形キャンバス、共通の安全余白、視覚中心、最小Chipでの判読性、同系統内の表現方針で監査し、契約外アセットを置換する。ランク差の主表現はChip径とし、アセットの専有面積も雑魚＜中ボス＜ボスとなる共通のランク別契約で整える。実行時の個別倍率・位置・構図の特別扱いは設けない。
- 要件で確定したEnemyへの割当と固有スキルを実装する。現在の対象は、未実装の中・大Enemyと、活力・宝石・範囲・武勇を含む全固有スキルの実装確認である。固有スキルによるダメージ・被弾時の属性付与も、共通の耐久値丸め後に0となったダメージを後処理しない規則に従う。確定済みの名称・情報ウィンドウ文言を実装の前提とする。新規追加・変更時だけは、名称・アセット・情報ウィンドウ文言を、対応するEnemyのモチーフと既存表現の調子を確認したうえでオーナー承認を得る。ゲーム上の効果は[固有スキル要件](../requirements/03.unique_skills.md)を参照する。
- 実装済みの活力・宝石・範囲を含むすべてのExスキルについて、発動時のエフェクトとログを横断的にレビューし、表示内容・ログを出さない条件を仕様化する。新規実装分と既存実装分の両方を、この仕様に従ってエフェクトとログを整備する。
- 軽業のウェアウルフ・天狗と[影の指先]は、Enemyカタログ、静的情報、アセット、Ex1／Ex2の処理まで実装済みである。試験課題へ出現させる前に、支援Enemyの編成を確定する。
- 残る中・大Enemyについて、要件で確定した名称に対応するEnemyカタログ、静的情報、アセットを整備する。
- 物理防御のエフェクトを属性付与と区別できる見た目へ修正する。水付与と同系色で判別しづらいため、属性付与とは別系統の色・アニメーションにする。見た目は縁を濃く中央を薄くした盾状オーバーレイ、アニメーションは魔法陣が回転する表現を検討する。
- タグ相性シミュレーションを基準に、アクションゲージ、ダメージ、敵HP、貢献ポイント、報酬、敵編成を調整する。

### 2. シナリオ演出とゲームランへの導入を整備する

- ゲーム開始時・Hero加入時などに、背景、Hero Chip、台詞、エフェクトを時間順に再生する寸劇システムを実装する。モーダル上で紙芝居のような背景を表示し、背景の横スクロール、Chipの移動・スイング・跳躍、左右反転、開始・終了演出、台詞表示を扱えるようにする。
- シナリオプレイヤーは定義済みのシナリオ再生だけを担い、出撃Party、加入Hero、事前に知り合いのHeroなどから台詞・登場人物・特別演出を選ぶ責務はシナリオジェネレーターへ分離する。将来のパラメーター追加を妨げないシナリオ定義とする。
- [Hero会話用設定資料](../content/hero_character_profiles.md) をレビューして確定情報と会話用初稿を整理し、開始時・加入時のシナリオを実装する。
- シナリオモーダルの小さいviewportでの表示、ゲーム時計の停止・再開、Chip表示の共通性を確認する。

### 3. ゲームランの記録と結果を設計する

- 解放状況、統計、ラン結果、クリアー記録を永続化・表示する。途中セーブ・途中再開はゲーム仕様として想定しない。
- チャレンジモード（エンドレス）には合格／不合格を設けず、終了時は成績を示す結果表示画面へ遷移する。
- `GameLog` のメモリ記録と画面を横断する `FlowLog` は実装済みである。過去ログを閲覧するログ履歴パネルと、アチーブメントを実装する。ログ履歴パネルではタグ・ステータス・用語・Enemyなどをアイコン付き情報ウィンドウリンクとして表示できるようにし、フローログは非操作の通知表示のままとする。

### 4. 操作とゲーム画面を拡充する

- ギルドのパネルに、現在の進行を表す「第N試験」を表示する。
- ショップの交換説明を「そのアイテムの[価値][交渉力]に応じた～」から「そのアイテムの[価値]と[交渉力]に応じた～」へ修正する。日英の対応する文言をともに確認する。
- 情報ウィンドウで「アクションゲージ」と記載している箇所を確認する。使用箇所が少なければ用語を避ける方針を維持し、多ければ用語説明を追加する。
- ピン止めした情報ウィンドウのサイズ切替、モバイル操作・カメラ、各エリアのビューを調整する。
- タイトル、説明書、チュートリアルを実装する。

### 5. 共有と公開を整備する

- ブラウザタブとブックマークでゲームを識別できるファビコンを設定する。
- シェア機能を実装する。共有する内容は別途検討するが、シェア機能自体は必須とする。
- `project_info.json` の紹介文・タグ・コンセプト画像を整備する。
- GitHub Pagesのビルド・デプロイ手順または自動化と、主要フローの受入テストを整備する。


## オーナー検証

### 試験ゲームランの完了状態

- `OV-RUN-01` 期限切れでゲームオーバー、7ステージ目のボス勝利でクリアーが確定し、終了後に次の試験課題選択が開かないことを確認する。

### 通常試験の結果画面

- `OV-RESULT-01` 合格・不合格の表示遷移、合格時の紙吹雪、合格証明書・不合格通知の表示内容を確認する。

### Enemy Chipアセット契約

- `OV-ENEMY-ART-01` 試験課題選択と戦闘エリアで、全Enemyの中心絵がチップの内側に収まり、雑魚＜中ボス＜ボスの専有面積とChip径の差が読めることを確認する。固有タグとの重なりは許容する。ゴブリンとリビングアーマーは既存の見た目を保つことを確認する。

### 鉄の中ボス・ボス

- `OV-IRON-01` ゴーレム／タロスのChip画像、名称、鉄タグ、[巨像の反撃]の情報ウィンドウ文言を確認する。
- `OV-IRON-02` ゴーレムを主敵とするエリート課題、タロスを主敵とするボス課題が、通常の鉄・炎・活力編成に対応する支援Enemyを伴って表示・開始できることを確認する。
- `OV-IRON-03` 巨像の反撃で、攻撃者が行動完了後に倉庫側へ一度で吹き飛び、元の戦闘スロットへ重量に応じた通常の歩行で戻ることを確認する。

### 魔導の中ボス・ボス

- `OV-ARCANE-01` リッチ／メデューサのChip画像、名称、魔導タグ、[反照の呪術]の情報ウィンドウ文言を確認する。
- `OV-ARCANE-02` リッチを主敵とするエリート課題、メデューサを主敵とするボス課題が、通常の魔導・範囲・鉄編成に対応する支援Enemyを伴って表示・開始できることを確認する。
- `OV-ARCANE-03` 炎・水・雷属性を受けたとき、リッチは一部、メデューサはより多くを軽減し、軽減量が攻撃者へ返ることを確認する。既存の属性値より低い軽減後の値で受け手の属性値が下がらず、返した属性で反照が連鎖しないことを確認する。

### 布の中ボス・ボス

- `OV-CLOTH-01` レイス／ドラキュラのChip画像、名称、布タグ、[夜の使い魔]の情報ウィンドウ文言を確認する。
- `OV-CLOTH-02` レイスを主敵とするエリート課題、ドラキュラを主敵とするボス課題が、通常の布・魔導・羽編成に対応する支援Enemyを伴って表示・開始できることを確認する。
- `OV-CLOTH-03` 攻撃後に使い魔が召喚元の周囲を周回し、被ダメージごとに1体が消え、次の攻撃時に残った使い魔がランダムな相手へ飛びかかって消えることを確認する。

### 水の中ボス・ボス

- `OV-WATER-01` 半魚人・クラーケン・リヴァイアサンのChip画像が、同じ水系Enemyとして共通のデフォルメ・輪郭・陰影・余白の方針に従い、ランク差はChip径として読めることを確認する。
- `OV-WATER-02` クラーケンを主敵とするエリート課題、リヴァイアサンを主敵とするボス課題が、通常の水・幸運・布編成に対応する支援Enemyを伴って表示・開始できることを確認する。
- `OV-WATER-03` [深海のうねり]の情報ウィンドウ文言と、攻撃時の水属性付与、付与済み水属性量に応じた会心表示・ダメージ増加を確認する。

### 炎の中ボス・ボス

- `OV-FIRE-01` ヘルハウンド／フェニックスのChip画像、名称、炎タグ、[報復の火種]の情報ウィンドウ文言を確認する。
- `OV-FIRE-02` ヘルハウンド／フェニックスへ物理・魔法ダメージを与えたとき、攻撃者へEx1／Ex2に応じた炎属性が付与されることを確認する。属性・反射ダメージでは発動しないこと、既存の炎属性より低い値で攻撃者の属性値が下がらないことも確認する。

### 雷の中ボス・ボス

- `OV-LIGHTNING-01` サンダーバード／雷龍のChip画像、名称、雷タグ、[雷鳴の収奪]の情報ウィンドウ文言を確認する。
- `OV-LIGHTNING-02` 雷属性が付与されたHeroからサンダーバード／雷龍へ物理・魔法ダメージを与えたとき、戦闘参加中のHero全員から現在たまっている量に応じてゲージが奪われることを確認する。Ex2の奪取量がEx1より大きいこと、属性・反射ダメージと戦闘参加外の実体が対象にならないことも確認する。

### 情報ウィンドウの対象モデル

- `OV-INFO-01` 静的情報と実体情報の表示内容、実体を破棄した時の情報ウィンドウの扱いを確認する。
- `OV-INFO-02` 情報ウィンドウのHero・Enemy・Item Chipがゲーム中と同じ`ChipRenderer`で描画され、最小のEnemyを他の見出しアイコンと同じ基準サイズとして、Chipの実際のサイズ比・背景・枠・中心画像・固有タグを保つことを確認する。試験課題選択のEnemyは、その候補個体の情報を開く。
- `OV-INFO-03` 情報ウィンドウを見出しからドラッグでき、ピン止め・サイズ切替の状態とホバーの見た目が区別できることを確認する。

### 本番開始状態

- `OV-START-01` デスクトップとモバイルで、4×2のHeroリスト、選択状態のスイング、出発、複数サイズの敵を含む試験課題選択の表示と用語を確認する。

### 設定モーダル

- `OV-SETTINGS-02` デスクトップと小さい表示領域で、設定の入力群、パーティー選択の出発操作、試験課題選択の課題操作が画面内で操作できることを確認する。
