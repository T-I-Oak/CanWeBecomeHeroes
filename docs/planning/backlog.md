# 開発バックログ

この文書は、次に着手する新規開発と、実装済みでオーナー確認を待つ作業だけを管理する。`要望・バグ指摘` は上から依存関係と優先順に並べる、全体作業計画の唯一の台帳とする。新しい要望は該当する段階の適切な位置へ追加し、必要に応じて全体の順序を見直す。開発ブランチの開始・検証・終了の運用は[ブランチ作業フロー](01.branch_workflow.md)を参照する。確定済みの仕様は `docs/requirements/`、実装済みの構造は `docs/specifications/` を参照する。

## 要望・バグ指摘

### 1. 操作とゲーム画面を拡充する

今の試験を止めている操作と、そのあとに文書へ書く操作を先に揃える。

- ゲームオーバー画面が情報ウィンドウの裏に隠れる。情報ウィンドウは、暗転する範囲の重なり順に入れる。結果画面の暗転とダイアログは、その手前に出す。
- 情報ウィンドウに明示的な閉じるボタンを付ける。情報ウィンドウは停止理由なので、閉じる操作を先に決める。
- 情報ウィンドウのサイズを2段階でなく段階を増やすか、自由サイズにする。閉じるボタンのあと、同じウィンドウの枠で扱う。
- 自動一時停止からの復帰方法を再検討する。説明書へ書く前に、復帰の操作を決める。
- Heroがウィンドウ外にいるときに、Heroの方向を示すアイコンをウィンドウの縁付近に表示する。
- ショップの交換説明を「そのアイテムの[価値][交渉力]に応じた～」から「そのアイテムの[価値]と[交渉力]に応じた～」へ修正する。日英の対応する文言をともに確認する。
- 情報ウィンドウで「アクションゲージ」と記載している箇所を確認する。使用箇所が少なければ用語を避ける方針を維持し、多ければ用語説明を追加する。
- ギルドのパネルに、現在の進行を表す「第N試験」を表示する。
- モバイル操作、カメラ、各エリアのビューを調整する。ピン止めの確認はオーナー検証へ置いている。
- 説明書、チュートリアルを実装する。ここまでの操作が決まってから書く。

### 2. タグ相性に基づいて数値を調整する

- 聖印の効果量を見直す。聖印は、自分以外の仲間のスタミナ（EnemyはHP）を、加護タグ数 × 0.05 + 0.05だけ最大値まで回復する。
- タグ相性シミュレーションを基準に、アクションゲージ、ダメージ、敵HP、貢献ポイント、報酬、敵編成を調整する。聖印の見直しより後にする。

### 3. シナリオ演出とゲームランへの導入を整備する

開始劇は完成している。内容は[開始劇](../specifications/08.start_vignette.md)、再生は[寸劇](../specifications/07.vignette.md)にある。

- Hero加入時の寸劇を実装する。シナリオプレイヤーは定義済みのシナリオ再生だけを担い、出撃Party、加入Hero、事前に知り合いのHeroなどから台詞・登場人物・特別演出を選ぶ責務はシナリオジェネレーターへ分離する。
- [Hero会話用設定資料](../content/hero_character_profiles.md) をレビューして確定情報と会話用初稿を整理し、加入時のシナリオを実装する。

### 4. ゲームランの記録と結果を設計する

- 解放状況、統計、ラン結果、クリアー記録を永続化・表示する。途中セーブ・途中再開はゲーム仕様として想定しない。
- チャレンジモード（エンドレス）には合格／不合格を設けず、終了時は成績を示す結果表示画面へ遷移する。
- `GameLog` のメモリ記録と画面を横断する `FlowLog` は実装済みである。過去ログを閲覧するログ履歴パネルと、アチーブメントを実装する。ログ履歴パネルではタグ・ステータス・用語・Enemyなどをアイコン付き情報ウィンドウリンクとして表示できるようにし、フローログは非操作の通知表示のままとする。情報ウィンドウの閉じる操作とサイズが決まってから着手する。

### 5. 共有と公開を整備する

- ブラウザタブとブックマークでゲームを識別できるファビコンを設定する。
- シェア機能を実装する。共有する内容は別途検討するが、シェア機能自体は必須とする。
- `project_info.json` の紹介文・タグ・コンセプト画像を整備する。
- GitHub Pagesのデプロイ手順はある。リモートbuildでGameWorks OAKの共通ライブラリを解決する手順と、主要フローの受入テストを整備する。


## オーナー検証

### タイトルと試験のやり直し

- `OV-TITLE-01` 起動時にタイトルが表示され、「ゲーム開始」からパーティー選択へ進めることを確認する。
- `OV-TITLE-02` 合格とゲームオーバーのどちらからもタイトルへ戻り、そこから次の試験を始められることを確認する。

### 武勇・軽業・加護の試験課題

- `OV-VALOR-01` オーガを主敵とするエリート課題、サイクロプスを主敵とするボス課題が、通常の武勇・雷・魔導編成に対応する支援Enemyを伴って表示・開始できることを確認する。
- `OV-DEXTERITY-01` ウェアウルフを主敵とするエリート課題、天狗を主敵とするボス課題が、通常の軽業・水・加護編成に対応する支援Enemyを伴って表示・開始できることを確認する。
- `OV-BLESSING-01` デーモン／堕天使のChip画像、名称、加護タグ、[堕ちた加護]の情報ウィンドウ文言を確認する。
- `OV-BLESSING-02` デーモンを主敵とするエリート課題、堕天使を主敵とするボス課題が、通常の加護・羽・水編成に対応する支援Enemyを伴って表示・開始できることを確認する。
- `OV-BLESSING-03` 戦闘開始時、自身の行動終了時、自身がダメージを受けた後に、加護以外の固有スキルを独立に7%で再抽選し、授かったスキルだけがExレベルで一時的に発動することを確認する。

### 試験ゲームランの完了状態

- `OV-RUN-01` 期限切れでゲームオーバー、7ステージ目のボス勝利でクリアーが確定し、終了後に次の試験課題選択が開かないことを確認する。

### 通常試験の結果画面

- `OV-RESULT-01` 合格・不合格の表示遷移、合格時の紙吹雪、合格証明書・不合格通知の表示内容を確認する。

### Enemy Chipアセット契約

- `OV-ENEMY-ART-01` 試験課題選択と戦闘エリアで、全Enemyの中心絵がチップの内側に収まり、雑魚＜中ボス＜ボスの専有面積とChip径の差が読めることを確認する。固有タグとの重なりは許容する。ゴブリンとリビングアーマーは既存の見た目を保つことを確認する。

### 鉄の中ボス・ボス

- `OV-IRON-01` ゴーレム／タロスのChip画像、名称、鉄タグ、[巨像の反撃]の情報ウィンドウ文言を確認する。
- `OV-IRON-02` ゴーレムを主敵とするエリート課題、タロスを主敵とするボス課題が、通常の鉄・炎・活力編成に対応する支援Enemyを伴って表示・開始できることを確認する。
- `OV-IRON-03` 巨像の反撃で、攻撃者が行動完了後に倉庫側へ一度で吹き飛び、元の戦闘スロットへ重量に応じた通常の歩行で戻ることを確認する。

### 魔導の中ボス・ボス

- `OV-ARCANE-01` リッチ／メデューサのChip画像、名称、魔導タグ、[反照の呪術]の情報ウィンドウ文言を確認する。
- `OV-ARCANE-02` リッチを主敵とするエリート課題、メデューサを主敵とするボス課題が、通常の魔導・範囲・鉄編成に対応する支援Enemyを伴って表示・開始できることを確認する。
- `OV-ARCANE-03` 炎・水・雷属性を受けたとき、リッチは一部、メデューサはより多くを軽減し、軽減量が攻撃者へ返ることを確認する。既存の属性値より低い軽減後の値で受け手の属性値が下がらず、返した属性で反照が連鎖しないことを確認する。

### 布の中ボス・ボス

- `OV-CLOTH-01` レイス／ドラキュラのChip画像、名称、布タグ、[夜の使い魔]の情報ウィンドウ文言を確認する。
- `OV-CLOTH-02` レイスを主敵とするエリート課題、ドラキュラを主敵とするボス課題が、通常の布・魔導・羽編成に対応する支援Enemyを伴って表示・開始できることを確認する。
- `OV-CLOTH-03` 攻撃後に使い魔が召喚元の周囲を周回し、被ダメージごとに1体が消え、次の攻撃時に残った使い魔がランダムな相手へ飛びかかって消えることを確認する。

### 水の中ボス・ボス

- `OV-WATER-01` 半魚人・クラーケン・リヴァイアサンのChip画像が、同じ水系Enemyとして共通のデフォルメ・輪郭・陰影・余白の方針に従い、ランク差はChip径として読めることを確認する。
- `OV-WATER-02` クラーケンを主敵とするエリート課題、リヴァイアサンを主敵とするボス課題が、通常の水・幸運・布編成に対応する支援Enemyを伴って表示・開始できることを確認する。
- `OV-WATER-03` [深海のうねり]の情報ウィンドウ文言と、攻撃時の水属性付与、付与済み水属性量に応じた会心表示・ダメージ増加を確認する。

### 炎の中ボス・ボス

- `OV-FIRE-01` ヘルハウンド／フェニックスのChip画像、名称、炎タグ、[報復の火種]の情報ウィンドウ文言を確認する。
- `OV-FIRE-02` ヘルハウンド／フェニックスへ物理・魔法ダメージを与えたとき、攻撃者へEx1／Ex2に応じた炎属性が付与されることを確認する。属性・反射ダメージでは発動しないこと、既存の炎属性より低い値で攻撃者の属性値が下がらないことも確認する。

### 雷の中ボス・ボス

- `OV-LIGHTNING-01` サンダーバード／雷龍のChip画像、名称、雷タグ、[雷鳴の収奪]の情報ウィンドウ文言を確認する。
- `OV-LIGHTNING-02` 雷属性が付与されたHeroからサンダーバード／雷龍へ物理・魔法ダメージを与えたとき、戦闘参加中のHero全員から現在たまっている量に応じてゲージが奪われることを確認する。Ex2の奪取量がEx1より大きいこと、属性・反射ダメージと戦闘参加外の実体が対象にならないことも確認する。

### 信用の中ボス・ボス

- `OV-REPUTATION-01` ホブゴブリン／スフィンクスのChip画像、名称、信用タグ、[惑いの言葉]の情報ウィンドウ文言を確認する。
- `OV-REPUTATION-02` ホブゴブリン／スフィンクスを主敵とする課題が、通常の信用・軽業・宝石編成に対応する支援Enemyを伴って表示・開始できることを確認する。
- `OV-REPUTATION-03` 惑乱状態のHero／Enemyが次の行動で自分以外の自陣営だけを通常の武器優先則で攻撃し、行動後に通常の対象選択へ戻ることを確認する。自陣営に他の対象がいない場合は攻撃せず、状態が解除されることも確認する。

### 幸運の中ボス・ボス

- `OV-FORTUNE-01` レプラコーン／麒麟のChip画像、名称、幸運タグ、[逆運の呪い]の情報ウィンドウ文言を確認する。
- `OV-FORTUNE-02` レプラコーン／麒麟を主敵とする課題が、通常の幸運・宝石・軽業編成に対応する支援Enemyを伴って表示・開始できることを確認する。
- `OV-FORTUNE-03` 不運状態のHero／Enemyが会心を与えたとき、Ex1は半分、Ex2は全量が自身へ跳ね返り、Ex1の残りだけが本来の対象の防御・反射を通ることを確認する。行動後に不運状態が解除されることも確認する。

### 羽の中ボス・ボス

- `OV-FEATHER-01` グリフォン／ワイバーンのChip画像、名称、羽タグ、[暴風の翼]の情報ウィンドウ文言を確認する。
- `OV-FEATHER-02` グリフォンを主敵とするエリート課題、ワイバーンを主敵とするボス課題が、通常の羽・布・炎編成に対応する支援Enemyを伴って表示・開始できることを確認する。
- `OV-FEATHER-03` 暴風の翼が全武器攻撃の完了後にHeroだけを倉庫へ一度で運び、全装備を周囲へ落とすことを確認する。スタミナ3未満では通常帰還を開始し、3以上では吹き飛ばされる前の第1武器から通常の再装備・行き先判定を続けることを確認する。

### 情報ウィンドウの対象モデル

- `OV-INFO-01` 静的情報と実体情報の表示内容、実体を破棄した時の情報ウィンドウの扱いを確認する。
- `OV-INFO-02` 情報ウィンドウのHero・Enemy・Item Chipがゲーム中と同じ`ChipRenderer`で描画され、最小のEnemyを他の見出しアイコンと同じ基準サイズとして、Chipの実際のサイズ比・背景・枠・中心画像・固有タグを保つことを確認する。試験課題選択のEnemyは、その候補個体の情報を開く。
- `OV-INFO-03` 情報ウィンドウを見出しからドラッグでき、ピン止めの状態とホバーの見た目が区別できることを確認する。サイズの段階は、段階数または自由サイズへの変更後に確認する。

### 本番開始状態

- `OV-START-01` デスクトップとモバイルで、4×2のHeroリスト、選択状態のスイング、出発、複数サイズの敵を含む試験課題選択の表示と用語を確認する。

### 設定モーダル

- `OV-SETTINGS-02` デスクトップと小さい表示領域で、設定の入力群、パーティー選択の出発操作、試験課題選択の課題操作が画面内で操作できることを確認する。
