# 開発バックログ

この文書は、次に着手する新規開発と、実装済みでオーナー確認を待つ作業だけを管理する。`要望・バグ指摘` は上から依存関係と優先順に並べる、全体作業計画の唯一の台帳とする。新しい要望は該当する段階の適切な位置へ追加し、必要に応じて全体の順序を見直す。開発ブランチの開始・検証・終了の運用は[ブランチ作業フロー](01.branch_workflow.md)を参照する。確定済みの仕様は `docs/requirements/`、実装済みの構造は `docs/specifications/` を参照する。

## 要望・バグ指摘

### 1. 操作とゲーム画面を拡充する

チュートリアルと設定画面のリセット機能は実装済み。内容は[チュートリアル](../specifications/10.tutorial.md)に記録している。

- 使い魔の色を変更する。現在は惑乱と色・アニメーションが似ているため、コウモリらしい黒い色合いへ変更する。アニメーションの見直しも検討する。

### 2. タグ相性に基づいて数値を調整する

- 聖印の回復量と武器の攻撃倍率を見直した。聖印は有効加護タグ数 × 0.01 + 0.01の確定回復、武器の中・小・微小は2/3・1/2・1/3とする。詳細は[戦闘](../requirements/04.combat.md)に記録する。
- タグ相性とExスキルの調整により、タグ・属性間の格差を小さくする今回の目的は達成した。攻撃側を有利にして引分けを減らした結果、戦闘が短くなり、試験期限内にクリアーしやすくなった点は、末尾のゲームバランス調整で扱う。

### 3. シナリオ演出とゲームランへの導入を整備する

開始劇は完成している。内容は[開始劇](../specifications/08.start_vignette.md)、再生は[寸劇](../specifications/07.vignette.md)にある。

- Hero加入時の寸劇を実装する。シナリオプレイヤーは定義済みのシナリオ再生だけを担い、出撃Party、加入Hero、事前に知り合いのHeroなどから台詞・登場人物・特別演出を選ぶ責務はシナリオジェネレーターへ分離する。
- [Hero会話用設定資料](../content/hero_character_profiles.md) をレビューして確定情報と会話用初稿を整理し、加入時のシナリオを実装する。

### 4. ゲームランの記録と結果を設計する

- 解放状況、統計、ラン結果、クリアー記録を永続化・表示する。途中セーブ・途中再開はゲーム仕様として想定しない。
- チャレンジモード（エンドレス）には合格／不合格を設けず、終了時は成績を示す結果表示画面へ遷移する。
- `GameLog` のメモリ記録と画面を横断する `FlowLog` は実装済みである。過去ログを閲覧するログ履歴パネルと、アチーブメントを実装する。ログ履歴パネルではタグ・ステータス・用語・Enemyなどをアイコン付き情報ウィンドウリンクとして表示できるようにし、フローログは非操作の通知表示のままとする。情報ウィンドウの閉じる操作とサイズが決まってから着手する。
- 現在の合格画面と不合格画面は仮画面である。アチーブメントの実装後に、正式画面へ差し替える。

### 5. 共有と公開を整備する

- ブラウザタブとブックマークでゲームを識別できるファビコンを設定する。
- シェア機能を実装する。共有する内容は別途検討するが、シェア機能自体は必須とする。
- `project_info.json` の紹介文・タグ・コンセプト画像を整備する。
- GitHub Pagesのデプロイ手順はある。リモートbuildでGameWorks OAKの共通ライブラリを解決する手順と、主要フローの受入テストを整備する。


### 6. 戦闘時間と試験難易度のゲームバランスを調整する

- タグ・属性間の格差を縮める調整は完了した。今回の調整は主に攻撃側を有利にし、引分けと戦闘時間を減らす方向だったため、試験期限内にクリアーしやすくなった。
- 戦闘時間の短縮と試験の易化への対応は今回のスコープ外とし、別途調整する。実プレイを基準に、戦闘時間と試験期限の余裕を確認し、アクションゲージ、ダメージ、敵HP・編成、貢献ポイント、報酬などから必要な項目を見直す。具体的な調整値は別途決める。

## オーナー検証

各項目は確認1件である。複数の確認を1件にまとめない。

### ドラッグ操作とモバイル表示

- `OV-CONTROLS-01` スマートフォンでチップをタップして情報ウィンドウを開けることを確認する。
- `OV-CONTROLS-02` スマートフォンで情報ウィンドウの閉じるボタンをタップして閉じられることを確認する。
- `OV-CONTROLS-03` スマートフォンで準備エリアのスタミナ3以上のHeroから倉庫Itemへドラッグし、Heroが出発することを確認する。
- `OV-CONTROLS-04` スマートフォンで倉庫Itemから買い物袋へドラッグし、格納できることを確認する。
- `OV-CONTROLS-05` スマートフォンでチップを画面内の端へドラッグして保持し、カメラがスクロールすることを確認する。
- `OV-CONTROLS-06` ドラッグ中にポインタを画面外へ出すと、自動スクロールが止まることを確認する。
- `OV-CONTROLS-08` スマートフォンで準備エリアのHeroの水滴から倉庫Itemへドラッグし、Heroが出発することを確認する。
- `OV-CONTROLS-10` スマートフォン横画面で設定ダイアログの閉じるボタンが画面内に収まることを確認する。

操作一覧と想定結果は [操作・モバイル表示の確認](../../tests/manual/controls.md) にある。ピン止めは検証済みであり、再依頼しない。

### スマートフォン実機検証：マップ全体表示とピンチズーム

- `OV-MAP-ZOOM-01` スマートフォン縦画面で試験開始時に、マップ全体が表示範囲内に収まって見えることを確認する。
- `OV-MAP-ZOOM-06` 2本指のピンチでマップを拡大できることを確認する。
- `OV-MAP-ZOOM-07` 2本指のピンチでマップ全体が見える倍率まで縮小できることを確認する。
- `OV-MAP-ZOOM-08` ピンチ中にブラウザのページ倍率が変わらないことを確認する。
- `OV-MAP-ZOOM-09` ピンチ中にページ全体がスクロールしないことを確認する。
- `OV-MAP-ZOOM-10` チップ上からピンチを始めても、情報ウィンドウが開かないことを確認する。
- `OV-MAP-ZOOM-11` チップ上からピンチを始めても、チップの移動先が確定しないことを確認する。
- `OV-MAP-ZOOM-12` ピンチ終了後にすべての指を離すと、新たな1本指タップでチップの情報ウィンドウを開けることを確認する。
- `OV-MAP-ZOOM-13` ピンチ終了後にすべての指を離すと、新たな1本指操作でチップをドラッグできることを確認する。
