# 開発バックログ

この文書は、次に着手する新規開発と、実装済みでオーナー確認を待つ作業だけを管理する。`要望・バグ指摘` は上から依存関係と優先順に並べる、全体作業計画の唯一の台帳とする。新しい要望は該当する段階の適切な位置へ追加し、必要に応じて全体の順序を見直す。開発ブランチの開始・検証・終了の運用は[ブランチ作業フロー](01.branch_workflow.md)を参照する。確定済みの仕様は `docs/requirements/`、実装済みの構造は `docs/specifications/` を参照する。

## 要望・バグ指摘

### ゲーム中の性能改善（調査後の実装候補）

PERF-02〜04は通常ソースへ未反映であり、採否と実装範囲を次の計画で判断する。番号は調査時の候補番号。第2〜4候補は独立して判断できる。

- `PERF-02` 雷の描画状態の復元漏れを修正する。雷ループ前後のsave/restoreで後続演出へのshadow等の漏れを止める。雷自体を維持し、後続演出の紫色の影が消える見た目を確認する。人工混在条件でp95短縮を確認済みだが、通常戦闘全体への効果は未確定。
- `PERF-03` 使い魔画像を惑乱と見分けられる配色へ修正し、描画時filterを削除する。配色を決め、輪郭・透過・識別性と公転・羽ばたき・飛行を確認する。紫色案は却下済み、真っ黒や現状の白黒再現は必須ではない。完成画像は未制作・未計測のため、完成画像で効果を再確認する。新しい汎用キャッシュは不要。
- `PERF-04` 盾・属性リングの縮小画像を既存の画像段階選択へ登録する。既存生成スクリプトでPNG段階画像とmanifestを作成し、枚数・付与値に伴う大きさ・透明度・揺れを維持する。小さい人工48枚条件で同期main平均76.5〜79.1％削減。最大ズーム・高DPR・強い属性付与時の画質、元画像fallback、初回読み込みとキャッシュへの影響を確認する。

上記の数値はPC/Chromeの計測専用試作による。第4候補で継続区間p95の一貫した改善は未確認。Android/Vivaldiの症状の直接原因・改善率は未確定であり、CPU削減を症状解消と扱わない。解像度低下は不採用。HUD・背景は今回の症状対応の主候補に含めない。

詳細な反復値・条件・受入条件・撤回方法は、Gitコミット`8615200`の`docs/planning/phase_perf_v0.75-mobile-performance-investigation_v1.md`、レビューは同コミットの`phase_perf_v0.75-mobile-performance-investigation_review.md`を参照する（`git show 8615200:docs/planning/phase_perf_v0.75-mobile-performance-investigation_v1.md`）。

各項目は確認1件である。複数の確認を1件にまとめない。
