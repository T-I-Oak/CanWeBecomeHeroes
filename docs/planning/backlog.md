# 開発バックログ

この文書は、次に着手する新規開発と、実装済みでオーナー確認を待つ作業だけを管理する。`要望・バグ指摘` は上から依存関係と優先順に並べる、全体作業計画の唯一の台帳とする。新しい要望は該当する段階の適切な位置へ追加し、必要に応じて全体の順序を見直す。確定済みの仕様は `docs/requirements/`、実装済みの構造は `docs/specifications/` を参照する。

## 要望・バグ指摘

### 0. バックログの完全性を確認する

- オーナーからの要望、過去のバックログ、要件、実装済み仕様を照合し、各項目を「未完了」「オーナー検証」「完了」「廃止・統合」に分類する。
- 未完了の要望だけを、このバックログの依存関係順に残す。完了・廃止・統合済みの項目を推測で復元しない。
- 寸劇システム、物理防御エフェクト、固有スキル、記録・結果、UI、公開準備の各領域について、要望の漏れがないことを確認する。

### 1. 戦闘基盤とEnemyコンテンツを整備する

- 未実装のelite・bossについて、要件で確定したEnemyへの割当に沿って、固有スキルとアセットを実装する。新規に実装するすべてのExスキルは、Exスキル名称・アセット・情報ウィンドウの文言を先に提案し、オーナー承認を得てから実装する。提案時は既存Exスキルの名称・フレーバー・説明との調子を確認し、対応する中ボス・ボスのモチーフに合うか、両者のモチーフが異なる場合は一方へ偏らないかをレビューする。現在実装済みの活力・宝石・範囲に加え、以下の固有スキル候補を設計する。
  - 武勇: 諸刃の剣。攻撃時、敵・味方全員へ諸刃の剣状態を付与する。諸刃の剣状態のキャラクターが会心を与える、または受けるとき、会心ダメージをEx1は2倍、Ex2は4倍にする。重複時は倍率の高い方を保持する。諸刃の剣状態は、会心の有無にかかわらず攻撃を受けたとき、または攻撃を終えたときに解除する。
  - 鉄: 物理攻撃の強力ノックバック。物理ダメージを受けると、ダメージ量に応じて攻撃者を倉庫側へ吹き飛ばす。Ex1は中、Ex2は大の距離とし、吹き飛ばされた攻撃者はアクションゲージを維持したまま戦闘エリアへ歩いて戻る。
  - 魔導: 属性反射。炎・水・雷の属性を受けると、その属性を軽減し、軽減した分を攻撃者へ付与する。Ex1は50%、Ex2は75%とする。
  - 布: 手下召喚。行動終了時に周囲へ手下を、Ex1は3体、Ex2は6体召喚する。次の自身の行動時、各手下はランダムな相手へ飛び掛かり物理ダメージ（極小）を与えて消える。被ダメージ時には手下が1体消える。
  - 炎: 炎属性付与（パッシブ）。物理・魔法ダメージを受けると、通常の炎付与と同じ規則で攻撃者へ炎を付与し、炎付与値を `max(Exで求めた炎付与値, 現在炎付与値)` にする。Ex1は炎タグ数の50%、Ex2は炎タグ数とする。
  - 水: 水属性会心。攻撃時に通常の水付与と同じ規則で自身へ水を付与し、水付与値を `max(水タグ数, 現在水付与値)` にする。攻撃が成功したとき、自身の水付与値が1以上ならCritical表示にする。元ダメージへ、元ダメージに水付与値を乗じた値を加算する。Ex1は加算する水付与値を半分にする。水付与1ならEx1は1.5倍相当、Ex2は2倍相当となり、水付与7のEx2は最大8倍となる。水属性による命中低下が大ダメージへのリスクになる。ランダムスキルが代理発動する場合は、行動フックで7%抽選に成功してから水属性を付与し、その行動中の後続ダメージ判定すべてへ会心効果を渡す。水タグ0なら新たな水付与は起きないが、すでに水が付与されていればその値でCriticalになる。
  - 雷: アクションゲージ吸収。雷が付与された相手を攻撃すると、その雷が届く範囲からアクションゲージを奪う。Ex1は相手のアクションゲージ最大値の5%、Ex2は10%を奪取する。
  - 加護: ランダムスキル。様々なボスが加護を受けている表現として、自身以外の固有スキルを一時的に保有する。通常の固有スキルは常時保有する。加護持ちは戦闘開始時、アクション終了時、ダメージを受けた後に、各ほかの固有スキルを独立に7%で保有するか再抽選する。保有した代理スキルは加護持ち自身のExレベルで扱い、対応するフックでは通常Exと同じく100%入る。宝珠の雨の50%など、効果に定義された確率はその後に抽選する。加護自身は代理候補に含めない。加護による一時保有は戦闘中だけの状態であり、永続データには保存しない。パッシブ・アクティブを分けず、再抽選時には保有スキル全体を更新する。
  - 軽業: タグ抜き取り。主ターゲット決定後、命中判定前に1アクションにつき1回、運判定に成功した場合だけターゲット装備に付いたタグからランダムに1つを選ぶ。Ex1はそのタグを消す。Ex2は自分のタグ数3未満の装備をランダムに1つ選べる場合はその装備へタグを移し、選べない場合は消す。
  - 信用: （名称未確定）攻撃時、運判定に成功した場合にターゲットへマインドコントロール状態（名称はマインドコントロール／混乱などから検討）を付与する。発動判定はEx1では`運判定（=幸運度 × 50%）`、Ex2では運判定とする。状態中のキャラクターは、攻撃時に自分以外の自陣営だけを候補にして、通常と同じ武器順の候補絞り込みで攻撃対象を決める。自陣営の候補がいなければ攻撃に失敗し、行動終了時に状態を解除する。攻撃対象がある場合も行動終了時に状態を解除する。
  - 幸運: （名称未確定）攻撃時、運判定に成功した場合にターゲットへ不運状態を付与する。不運状態のキャラクターは、攻撃でCryticalが発生した場合にダメージの一部またはすべてを自身へ与える。Ex1は50%を自身へ与え、残る50%を元のターゲットへ与える（元のターゲットへのダメージには盾スキルなど通常の防御処理を適用する）。Ex2は100%を自身へ与え、元のターゲットにはダメージを与えない。不運状態は、そのキャラクターの攻撃終了時に解除する。
  - 羽: （名称未確定）攻撃時、Ex1は`運判定（=幸運度 × 25%）`、Ex2は`運判定（=幸運度 × 50%）`に成功すると、ターゲットへ突風を発生させる。対象を倉庫のランダム位置へ飛ばし、周囲に装備Itemを落下させて戦闘状態から離脱させる。対象のスタミナ（EnemyはHP）が3未満なら準備エリアへ歩いて戻る。3以上なら、吹き飛ばされる前の第1武器だったItemを行き先として通常どおり移動・再装備する。行き先Itemを再装備した場合は通常の行き先処理へ進むため、戦闘エリアへ戻るとは限らない。
- 実装済みの活力・宝石・範囲を含むすべてのExスキルについて、発動時のエフェクトとログを横断的にレビューし、表示内容・ログを出さない条件を仕様化する。新規実装分と既存実装分の両方を、この仕様に従ってエフェクトとログを整備する。
- 中・大Enemyのカタログ、名称、アセットを整備する。
- 物理防御のエフェクトを属性付与と区別できる見た目へ修正する。水付与と同系色で判別しづらいため、属性付与とは別系統の色・アニメーションにする。見た目は縁を濃く中央を薄くした盾状オーバーレイ、アニメーションは魔法陣が回転する表現を検討する。
- タグ相性シミュレーションを基準に、アクションゲージ、ダメージ、敵HP、貢献ポイント、報酬、敵編成を調整する。

### 2. シナリオ演出とゲームランへの導入を整備する

- ゲーム開始時・Hero加入時などに、背景、Hero Chip、台詞、エフェクトを時間順に再生する寸劇システムを実装する。モーダル上で紙芝居のような背景を表示し、背景の横スクロール、Chipの移動・スイング・跳躍、左右反転、開始・終了演出、台詞表示を扱えるようにする。
- シナリオプレイヤーは定義済みのシナリオ再生だけを担い、出撃Party、加入Hero、事前に知り合いのHeroなどから台詞・登場人物・特別演出を選ぶ責務はシナリオジェネレーターへ分離する。将来のパラメーター追加を妨げないシナリオ定義とする。
- [Hero会話用設定資料](../content/hero_character_profiles.md) をレビューして確定情報と会話用初稿を整理し、開始時・加入時のシナリオを実装する。
- シナリオモーダルの小さいviewportでの表示、ゲーム時計の停止・再開、Chip表示の共通性を確認する。

### 3. ゲームランの記録と結果を設計する

- 解放状況、統計、ラン結果、クリアー記録を永続化・表示する。途中セーブ・途中再開はゲーム仕様として想定しない。
- チャレンジモード（エンドレス）には合格／不合格を設けず、終了時は成績を示す結果表示画面へ遷移する。
- `GameLog` のメモリ記録と画面を横断する `FlowLog` は実装済みである。過去ログを閲覧するログ履歴パネルと、アチーブメントを実装する。ログ履歴パネルではタグ・ステータス・用語・Enemyなどをアイコン付き情報ウィンドウリンクとして表示できるようにし、フローログは非操作の通知表示のままとする。

### 4. 操作とゲーム画面を拡充する

- 進路を「課題」または「試験課題」へ変更し、進路選択のヘッダー表現も見直す。
- ピン止めした情報ウィンドウのサイズ切替、モバイル操作・カメラ、各エリアのビューを調整する。
- タイトル、説明書、チュートリアルを実装する。

### 5. 共有と公開を整備する

- シェア機能を実装する。共有する内容は別途検討するが、シェア機能自体は必須とする。
- `project_info.json` の紹介文・タグ・コンセプト画像を整備する。
- GitHub Pagesのビルド・デプロイ手順または自動化と、主要フローの受入テストを整備する。


## オーナー検証

### 開発資料の整理

- 完了済みの `dev_` 文書を削除し、`dev_` 接頭辞はコミット前の検討・実装メモだけに使う運用へ整理した。以後、不要になった `dev_` 文書の削除は、各作業のバックログ完了条件として記録する。
- Hero会話用設定資料を、要求仕様とは分離した [コンテンツ設計資料](../content/hero_character_profiles.md) へ移した。
- `planning` に残る資料が、バックログまたは継続作業計画だけであることをオーナーが確認する。

### Itemの価値とショップ交換

- Itemのタグ由来データを `value` として一元化し、情報ウィンドウで重量と並べて表示する。`[価値]` はタグスキルと同じ用語説明を開くリンクとする。
- ショップの説明を「そのアイテムの[価値]」へ改め、価値合計と交渉力で受取装備のタグ数が決まることを用語説明に記載する。
- Item情報からの価値表示・用語リンク、ショップ情報の表現、日英表示をオーナーが確認する。

### i18nと戦闘ターゲット選択

- 日英リソース、言語選択、情報ウィンドウ、ログ、戦闘ポップアップ、施設・進路表示をローカルで確認済み。
- 複数武器の順次候補絞り込み、宝珠の微小物理攻撃、旗の微小魔法攻撃、武器説明を実装済み。
- 公開先で `/data/game_text.json` の取得、言語切替、表示崩れのないことをオーナーが確認する。

### 試験ゲームランの完了状態

- 期限切れでゲームオーバー、7ステージ目のボス勝利でクリアーを確定し、終了後に次の進路選択が開かないことをオーナーが確認する。

### 通常試験の結果画面

- 通常試験の終了時は画面を暗転させ、合格時は合格証明書、不合格時は不合格通知を上から表示する。
- 合格証明書には被証明者、本文、認定日、認定者・発行元、印を表示する。アチーブメントは今後追加できる領域として結果データに含める。
- 合格・不合格の表示遷移、合格時の紙吹雪、表示内容をオーナーが確認する。

### 敵詳細の情報列

- 装備一覧が想定行数を超えても、タグ数一覧の行高が引き伸ばされないことをオーナーが確認する。

### 本番開始状態

- 解放済みHeroから出撃する2名を選び、選択した2名と対応装備でゲームランを開始する実装へデモシナリオを置き換えた。
- 加入Heroはそのランだけの仲間とし、第7試験をクリアーした時点の全メンバーだけを次回開始時の解放済みHeroとして保存する。
- デスクトップとモバイルで、4×2のHeroリスト、選択状態のスイング、出発、複数サイズの敵を含む試験課題選択の表示をオーナーが確認する。

### GameAppの責務分割

- `GameApp` から時間設定、Canvas入力、試験ゲームラン、ワールド面、準備パネル・店パネルの描画と入力判定を責務ごとのモジュールへ分離した。
- 準備パネルの装備配置と入力判定、店・準備で共通の装備スロット判定は、同じ意味のレイアウトと部品を共有する。
- 情報表示、ドラッグ、ポインター中心ズーム、試験課題選択、準備・店パネルの情報表示をオーナーが確認する。

### 自動一時停止中の袋格納

- 停止中の例外操作を調査し、袋格納だけが停止解除を抑制する例外であることを確認した。
- 袋格納の例外処理を削除し、すべてのCanvas操作終了時に既存の自動一時停止解除経路を使うよう統一した。
- 自動一時停止中に袋へItemを格納したとき、停止が解除されることをオーナーが確認する。

### 重量ゲージ

- 重量ゲージの表示上限を20から30へ引き上げた。重量24は80%表示、重量30で満タンとなる。
- 準備エリアと情報ウィンドウで、重量ゲージの表示量・色が意図どおりであることをオーナーが確認する。

### 設定モーダル

- HUDの操作を `⚙ 設定` に変更し、設定項目をモーダルダイアログに表示する。
- 速度バーの[標準]を1.0倍の位置に配置する。
- `ModalLayer`と`ModalDialog`で、設定、出撃パーティー選択、試験課題選択の外観、画面内での収まり、タイトル、本文、全体操作の構造を共有する。設定の言語、ゲーム進行、頭上表示は`fieldset`と`legend`の入力群で表す。
- 設定モーダルの開閉、速度設定、言語切替、自動停止設定をオーナーが確認する。
- デスクトップと小さい表示領域で、設定の入力群、パーティー選択の出発操作、試験課題選択の課題操作が画面内で操作できることをオーナーが確認する。

### 試験場の頭上情報

- 試験場に、ボス・ダメージ表示・頭上情報のための70pxの専用上部余白を追加し、敵・味方のスロットをその余白の下へ配置した。
- 設定でパワー、魔力、スピード、交渉力、運、耐久値、重量を複数選択できる。未選択時は非表示とし、選択済み項目は1秒間隔で「ステータス名 値」として切替表示する。
- 耐久値はHeroのスタミナ／EnemyのHPを100倍した整数、パワー、魔力、スピード、交渉力、運はそのままの整数、重量は所持重量を表示する。文字色はステータスの視覚定義を使い、濃いアウトラインで背景との判別性を確保する。
- 表示タイミングは常時または戦闘中から選べる。選択内容、切替、Hero・各Enemyサイズ、ダメージ表示との重なりをオーナーが確認する。
