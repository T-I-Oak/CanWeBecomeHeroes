# 二つ名の語句定義

## 用語

- 情報カテゴリー：タグ／武器／施設／敵の4区分。
- 情報種別：各カテゴリー内の対象・収集項目。例：炎タグ、盾、ギルドへの出発回数。
- 語句カテゴリー：展開指定で参照する区分。例：人、修飾人、形容詞、行動。
- 情報共通：個別の情報種別に依存しない語句定義。
- 使用区分：味方／敵／共通。情報共通とは別の概念。

## 現在の状態

## 実績からの情報種別選定（オーナー合意）

1. 今回ランのキャラクター別実数から、情報種別ごとに各Heroの獲得率（本人の値÷全Heroの合計）を求める。
2. 各Heroについて、各情報カテゴリー内で獲得率が最大の情報種別を選ぶ。
3. 選択した情報種別の語句定義と情報共通の定義を集約し、二つ名を生成する。

全Hero間で獲得率1位の情報種別だけへ絞る前処理は行わない。同じ情報種別が複数Heroに選ばれることも、生成された二つ名が重複することも許容し、強制的な重複回避は追加しない。

全員合計0、カテゴリー内の最大獲得率が同率の場合、比較対象のHeroの範囲はまだ未確定。この合意だけで境界条件を推測して確定しない。

## 語句定義の扱い

合格通知では、二つ名のフォントサイズをHero名のフォントサイズより小さくする（オーナー指定）。具体的なサイズ・比率はモックアップで調整する。

二つ名の語句には、ゲーム中で使用している職業名を使わない（オーナー指定）。別の職業のHeroにも与えられるため、職業と二つ名が矛盾することを避ける。語句案の作成時には実際の職業名一覧と照合する。参考資料の職業名に該当する候補は新しい定義へ引き継がない。

語句定義の単位はタグ15・武器10・施設7・敵共通1の計33種とし、それとは別に情報共通（汎用）の定義を用意する。

語句定義とは別に「二つ名の構成データ」を用意し、生成の起点とする。現在の起点は`[person(ally)]`。personは構成、person_baseは呼び名を定義し、味方・敵とも修飾なしまたはmodifierを1つ付ける構成から展開する。qualifiedPersonを修飾付きで使う構成も維持する。英語の空白・語順等は言語別リソースで定義する。

情報カテゴリー・情報種別ごとの語句定義はいったん白紙とする。新しい定義はオーナーと相談し、合意したものを徐々に追加する。

これまでの語句リストは参考資料であり、本書へ自動的に引き継がない。対象一覧や収集情報そのものを削除・変更する指示ではない。

合意した展開の仕組みは`phase_feature_v0.44-epithet_expansion.md`に保持する。情報共通の既存定義は対象別定義と区別し、今回の対象別定義の白紙化だけで削除したとは扱わない。

## 情報種別：敵（共通定義）

オーナー提示の定義として登録する。敵名は選択された敵の名称を使用する。

| 語句カテゴリー・使用区分 | 候補 |
| --- | --- |
| person(ally) | `[person_base(enemy)][actionPerson(enemy)]` |
| person_base(enemy) | 敵名 |

構成と語句のテンプレートを言語別リソースとして定義し、空白・接続語・語順を各言語で指定する。展開処理が空白や接続語を自動挿入しない。

| 言語 | 敵のperson(ally)の構成 |
| --- | --- |
| 日本語 | `[person_base(enemy)][actionPerson(enemy)]` |
| 英語 | `[person_base(enemy)] [actionPerson(enemy)]` |

敵由来のperson(ally)は`[person_base(enemy)][actionPerson(enemy)]`のみとする。敵名の前へ修飾を置く専用候補は削除し、勇者の直前への修飾はactionPerson(enemy)のdefaultで用意する（2026-10-15 オーナー合意）。外側の再帰展開の結果として先頭へ修飾が付くことは排除しない。英語側は対応する語順を言語別リソースで定義する。

上記の英語の空白は構成リソースに含める。語順を変える場合もその言語の構成リソースで対応する。識別子と展開ルールは共通とし、テンプレートの文字列・語句は言語別に持つ。

action(enemy)は厳密な動詞に限らず、構成に合う接続部分を含む表現として定義する。日本語の固定の「を」はこの構成側へ追加せず、必要な場合は語句候補へ含める。「対象の後ろにつながる」は現在の構成での役割であり、全言語の語順を固定する制約ではない。参考資料の旧行動一覧を確定候補として流用しない。

直前に提示して合意した定義例：

| action(enemy)の候補 | 敵名がゴブリンの場合の展開例 |
| --- | --- |
| キラー | ゴブリンキラー |
| を討つ[person(ally)] | ゴブリンを討つ戦士 |
| を統べる[person(ally)] | ゴブリンを統べる戦士 |
| の天敵 | ゴブリンの天敵 |

上表は接続方法を示す例。候補ごとの情報種別・情報共通への配置はまだ決めていない。

### actionPerson(enemy)による整理案

actionは行為の部分、actionPersonは行為を担う人まで含む表現として区別する。従来のactionに人まで含めた定義例は説明用とし、上の配置表ではaction部分だけへ整理した。

| 配置 | actionPerson(enemy)の候補 |
| --- | --- |
| actionPerson × enemyのデフォルト | `[action(enemy)][person_base(ally)]`、`[action(enemy)][modifier(ally)][person_base(ally)]` |
| 武勇タグ | キラー |
| 加護タグ | の天敵 |

上記の配置はオーナー指定。武勇・加護はactionPerson(enemy)を定義し、他の提示済み情報種別はaction(enemy)を定義する。合成構成を情報共通の通常候補には入れない。actionPerson(enemy)の通常候補があればそこから選び、空の場合だけデフォルトの合成構成を展開する。

日本語では空白なしで連結し、英語の構成は`[action(enemy)] [person_base(ally)]`等の言語別テンプレートで定義する。英語の語句・構成の最終表現は別途検討する。

展開例：`[person_base(enemy)][actionPerson(enemy)]`→`ゴブリン[action(enemy)][person_base(ally)]`→`ゴブリンを討つ戦士`。またはactionPersonで「キラー」を選び、`ゴブリンキラー`。person(ally)は再帰可能な候補なので、修飾付きの呼び名にも展開できる。

固定の「者」は`[person(ally)]`へ置き換え、集約済みの味方＋共通の人候補から再帰展開する（オーナー指定）。「者」自体を候補として登録した指示ではない。

## デフォルト定義

展開のキーワードとフィルターの組み合わせごとに定義する。例えばperson(enemy)とperson(ally)は別のデフォルト定義を参照する。

通常候補とは別に管理し、展開時に指定カテゴリー・使用区分で絞り込んだ候補が空の場合だけ参照する。情報カテゴリー「敵」の有無だけで一律に追加せず、展開要求の候補が存在するかで判断する。

例：敵を1体も倒しておらず、選択された敵名などのperson(enemy)候補がないHeroでも、`[person(enemy)]`を「強敵」のようなデフォルト候補で展開できるようにする。現在のdefaultは本書の確定一覧および本番データに記載する。

## シミュレーション前の確認事項

- actionPerson(enemy)のデフォルト構成は定義済み。
- person(ally)、person(enemy)、modifier(ally)、modifier(enemy)、action(enemy)の終端デフォルト語句は未確定。提案：勇者／強敵／伝説の／恐るべき／を倒す。提案を合意前にデータへ登録しない。
- modifier(enemy)の通常候補は現在未定義。情報共通のperson(enemy)の再帰構成がこの参照を使うため、少なくともデフォルトが必要。
- 再帰停止時に通常候補に終端語句がない場合の補完方法を確認する。通常の候補ゼロへのデフォルトだけでは、再帰構成のみ存在する状態の終端を保証しない。
- シミュレーションの深さ・文字列長の制御値は調整可能にする。固定の本番値をこの時点で確定しない。
- 英語の全語句とテンプレートは本番データへ実装済み。日本語と異なる接続・語順を言語別に定義する。

## 情報共通のperson構成

| 区分 | 候補 |
| --- | --- |
| person(ally) | `[person_base(ally)]`、`[modifier(ally)][person_base(ally)]`、`[modifier(ally)][qualifiedPerson(ally)]` |
| person(enemy) | `[person_base(enemy)]`、`[modifier(enemy)][person_base(enemy)]` |

対象別の呼び名はperson_base(ally)、敵名はperson_base(enemy)へ置き、person_baseは終端語句だけに限定せず、循環参照にならない組み立て定義も許容する。敵由来構成はperson(ally)へ置く。actionPerson(enemy)のdefaultはperson_base(ally)へ進むためpersonの構成へ戻らない。敵なしでもperson_base(enemy)のdefault「強敵」へ到達できる。

## タグスキル由来の呼び名（2026-10-15 オーナー合意）

- ステータス系タグのperson_base(ally)に [tagSkill]の[skillPerson(ally)] を追加する。属性系タグには追加しない。
- ステータス系タグが情報種別に選ばれたら、対象Heroの今回ランの最大保持数に対応する既存タグスキル名をtagSkillへセットする。タグ数1以上で取得できる。
- skillPerson(ally)の候補は使い手・達人・名人・匠。一般のmodifierやqualifiedPersonと混ぜない。
- tagSkillのdefaultは不要とオーナーが指定。候補集合を組み立てる際に実際のスキル名を必ず供給する。

タグスキル名は文中と区別するため日本語では「スキル名」、英語では引用符付きにしてtagSkillへ供給する。
