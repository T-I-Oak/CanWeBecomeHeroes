# レコード画面の開発計画

## 合意内容

- ブランチ: `feature/v0.46-record-screen`
- 予定バージョン: `0.46.0`。package.json・package-lock.jsonは初回実装開始時に更新する。
- タイトルの仮レコード表示を、全アチーブメントの累積評価と試験モードのランキングを閲覧できる画面へ置き換える。
- チャレンジモード関連は将来の追加を想定するが、表示・切替・動作確認を含め今回の対象外とする。

## 開発スコープ

- タイトルからレコード画面を開き、アチーブメント・ランキングを切り替え、タイトルへ戻れるようにする。
- アチーブメントは累積集計を既存定義で評価し、全項目を定義順に表示する。カテゴリ・評価項目と条件・判定・所見を既存のAchievementTableのrecordモードと共通CSSで描画する。
- 未達成項目も表示する。評価・条件・所見は既存定義を使用し、新しい達成条件を設けない。
- 試験ランキングは残り期限・討伐数・獲得貢献ポイントの基準を切り替えて上位10件を表示する。順位計算はRunRankingsを使用する。
- ランキングには順位、選択基準の値、合否、終了日時、開始Hero・終了メンバーを表示する。時間・数値・名前は既存のゲーム内表現と整合させる。
- 記録がないランキングには案内を表示する。レコードを開くたびに最新のRepositoryの状態を参照し、閲覧操作では保存・集計・削除を行わない。
- 日本語・英語の文言、画面内スクロール、スマートフォン縦横画面での閲覧と戻る操作に対応する。
- 関連仕様書とバックログを更新する。チャレンジモードの将来構想は下記の注意事項に合わせて整理する。

## 表示と責務

- レコード画面は見出し、アチーブメント／ランキングの切替、内容領域、戻る操作で構成する。
- アチーブメントは既存の通知表形式を踏襲し、全項目をスクロールして読む。終了画面の10件選定は使用しない。
- ランキングは基準選択と表で構成し、データなしの表示を同じ画面内に設ける。
- TitleMenuは開閉とタイトルへの復帰、レコード画面の部品は描画と切替、既存のゲーム側クラスは評価・順位付けを担当する。
- 具体的な余白・列幅・スマートフォンでの表の収め方は実装時に調整し、確認可能な画面をオーナーへ提示する。
- モードと順位基準の既存データ構造を維持し、試験専用の別ランキング計算を複製しない。

## 対象外

- チャレンジモードの画面、記録表示、モード切替、進行・終了処理、関連動作確認。
- Heroの解放時期や解放条件の変更。
- 解放状況、統計、終了履歴、クリアー記録の専用閲覧画面とラン詳細画面。
- 保存形式の変更、保存失敗の通知・再試行UI、記録削除・出力・共有。
- 過去ログ、正式な合否通知と二つ名の選定・表示、ゲームバランス調整。
- GameWorksOAKの変更。

## 完了条件

- タイトルから開閉でき、試験終了後に再度開くと最新の記録を表示する。
- 全アチーブメントの条件・累積判定・所見とカテゴリ結合が既存定義に一致する。
- 試験の3順位基準が既存の順位規則・上限10件に一致し、空の状態を表示できる。
- 閲覧・切替・言語変更で保存データやゲームの集計を変更しない。
- 日本語・英語、スマートフォン縦横画面で表示内容と閉じる操作へ到達できる。
- 必要なオーナー検証を実装時に1件ずつ提示し、判断と対応を実装報告へ記録する。保留はオーナーの明示的な判断がある項目だけとする。
- 対象テスト、全テスト、本番ビルドの結果を実装報告へ記録し、失敗があれば原因と扱いを明記する。

## 実装・テスト方針

- GameAppから既存RunRecordsRepositoryを表示側へ接続する。累積評価と順位取得は既存クラスを再利用し、表示用データを組み立てる。
- tests/implementationのAchievementTable・Achievements・RunRankings・RunRecordsRepositoryの既存テストを確認し、表示用データ、順位基準切替、未達成・空状態、最新データ再読込、非破壊な閲覧の検証を追加する。
- 状態管理など複雑な処理を追加する場合は、共通ルールに従い先にテストで挙動を定める。
- ブラウザでタイトルからの開閉、全項目の閲覧、各順位基準、言語変更、スマートフォン縦横の表示を確認する。
- 実装終了草案の提示前に `npm.cmd test` と `npm.cmd run build` を実行する。計画フェーズでは実装とバージョン更新を行わない。

## 次担当への注意事項

- 「チャレンジモード」は仮称。オーナーは将来「実力判定試験」のように実力を測るモードを構想している。正式名称・具体的な進行方式・終了条件は未確定であり、今回確定しない。
- バックログの「エンドレス」を確定した前提として扱わない。既存のチャレンジ用集計・ランキング定義は維持する。
- docs/specifications/16.run_records.mdとdocs/requirements/06.run_records.mdには以前の開発範囲を示す後続UIの記述がある。更新時は現在の実装済み範囲と今回の範囲を区別し、チャレンジ関連を実装済みと記載しない。
- フェーズ判定・承認・終了コミットはdocs/planning/01.branch_workflow.mdに従う。
