# レコード画面の開発計画

## 合意内容

- ブランチ: feature/v0.46-record-screen、予定バージョン: 0.46.0。
- 実装フェーズの会話で設計を固めることをオーナーと合意した。
- レコード画面内を「勇者認定試験ランキング」「アチーブメント」「課題記録」の3タブで切り替える。
- 当初の2タブ案に課題記録を追加し、比率表示は実装しない。
- 実力判定試験（既存のチャレンジモード）のランキング・画面・進行は対象外。
- オーナーの指示により、課題記録の正確な再現を妨げるボス数の課題番号依存をブロッキングバグとして修正対象へ含める。基準レベルは課題番号+2、抽選幅は±2であることを確認し、ボス数をmax(1, ceil((level - 2) / 14))とする。
- 課題記録は各種類の最高クリアーレベル上位5構成に変更することを合意した。未クリアーは表示せず、同レベルはその最高レベルを最後にクリアーした日時が新しい構成を優先する。日時の追加収集・保存も合意済み。

## 開発スコープと表示

- タイトルから開き、タイトルへ戻れる。開くたびにRepositoryの最新状態を参照する。
- 閲覧・タブ切替・順位基準切替・言語変更では保存・集計・削除しない。
- scale使用は共通モバイル規約の条件に従う。操作部を拡縮から外し、本文は75%を下限として内部スクロールで閲覧する。終了画面は縮小下限を設けず紙全体を表示枠に収め、本文も紙面内に全件表示する。裏返し・タイトル復帰ボタンは紙とは独立したサイズとする。適用時と後続機能の実装時に座標・スクロール・ツールチップ・配置への影響を確認する。詳細は16.run_records.md・17.trial_result_screen.mdを参照する。
- 日本語・英語、画面内スクロール、スマートフォン縦横画面に対応する。

### 勇者認定試験ランキング

- 上部に残り期限・討伐数・獲得貢献ポイントの基準ボタンを置く。順位付けはRunRankingsを再利用し、各上位10件とする。
- どの基準でも共通の表を使い、選択した基準の値をやや大きく表示する。
- 列は順位、クリアー課題数、残り期限、討伐数、獲得貢献ポイント、メンバー、達成日時（試験終了日時）。
- 不合格は残り期限の値の代わりに「不合格」を表示する。
- メンバーは終了時の順序を保持し、画面外Heroの方向アイコンと同様の顔のアップ画像で表示する。
- 開始ペア、独立した合否列は表示しない。空状態には案内を表示する。

### アチーブメント

- 既存定義による累積評価を定義順にすべて表示する。終了画面の10件選定は使わない。
- 列はカテゴリ、評価項目、判定、判定基準、達成度。同じカテゴリは縦に結合する。
- 判定は現在の評価。判定基準は「アヴェリーとブライアーで試験に挑む」のような行動の文言とする。
- タグの判定基準は「いずれかの受験者で○○タグを集める」とする。通常項目は目標tを維持してG=15×sqrt(p/t)へ変更する。タグは0個E、1〜7個をD・C・B・A・A＋・S・S＋に分ける。所見は1〜2個・3〜4個・5〜6個・7個以上で分け、1〜2個に「○○が使えるようになりましたね。」を新設する。
- 達成度は次評価に必要な値に対する「3 / 5」と控えめなバーで示す。最高判定は「達成」とする。
- 所見は表示しない。AchievementTableのrecordモードと共通CSSを拡張し、result・toastの形式を維持する。
- 新しい達成条件を設けず、次評価の必要値は既存の評価式から求める。

### 課題記録

- 通常・エリート・ボスを縦に並べ、それぞれ最高クリアーレベル上位5構成の表を置く。同じ構成は1件。同レベルは最高レベルの直近クリアー日時降順、同日時は定義順。日時の欠落チェックや旧データ向けのフォールバックは設けない。
- 列は敵の構成、レベル、達成日時（最高レベルの直近クリアー日時）。勇者やペアによらない、全プレイを通した累積最高値を使う。
- 敵構成は記録された最高レベルから実際の生成処理で求めた6スロット配置とし、元画像を切り取らず、サイズ比と中心の高さを維持して配置する。オーナー確認により切り取りなしを採用する。空きスロットも保持する。
- 敵構成のレベルは課題の進行で上がることと、各構成の最高クリアーレベルであることを補足する。計算式や範囲は書かない。
- 未クリアー構成は表示しない。記録なしの種類には案内を表示する。アチーブメントはオーナー確認により未達成を含め全件表示する。
- 切り出し方式が効果的なら課題選択画面への適用を将来検討する。今回は課題選択画面を変更しない。

## 対象外

- 実力判定試験の画面、記録表示、モード切替、進行・終了処理、関連動作確認。
- 比率表示、解放状況、終了履歴、ラン詳細、記録削除・出力・共有。保存データには最高レベルの直近クリアー日時と成績表選定用の開始累積G値・増加量を追加する。旧データの日時は推測しない。
- Hero解放条件、ゲームバランス、正式な二つ名の選定。結果画面は合意済みの縮小表示・成績表の選定変更に限定する。
- GameWorksOAKの変更。

## 完了条件と検証

- タイトルから開閉でき、再度開くと最新データを反映する。
- アチーブメントの累積判定、カテゴリ結合、次評価の目標値が既存定義に一致する。
- ランキングの3基準が既存順位規則と上限10件に一致し、空状態も表示できる。
- 各種類の上位5構成が最高レベル・直近クリアー日時の順序に一致し、未クリアーを除外する。実ゲームと記録表示の敵配置が同じ構成・レベルで一致する。
- 閲覧操作は非破壊で、日本語・英語とスマートフォン縦横で表示・戻る操作に到達できる。
- 表示用データ、閾値、切替、再読込、非破壊な閲覧に対応するテストを追加する。
- 対象テスト・全テスト・本番ビルド・ブラウザ確認の結果を実装報告へ記録する。
- オーナー検証は確認できる実装を1件ずつ提示し、判断と対応を記録する。未回答を保留扱いしない。
- フェーズ判定・承認・終了コミットは01.branch_workflow.mdに従う。承認前に引継ぎ書を更新しない。

- ランキングのメンバー画像・課題記録の敵画像から既存の定義情報ウィンドウを表示する。レコード専用ツリーでは関連情報を含めピンを表示せず、画面終了時にまとめて破棄する。

- 成績表はグレードアップ項目を優先し、更新・非更新それぞれで累積G値の開始時から終了時への増加量順、同値は定義順で最大10件選ぶ。表示順は定義順とする。開始イベント前に開始G値を保持する。
