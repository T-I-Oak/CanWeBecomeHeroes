# 起動時表示・画面サイズ追従の実装報告

## 対象

- ブランチ: `fix/v0.47-startup-responsive-ui`
- バージョン: `0.47.3`
- 計画書: [改善計画](phase_fix-v0.47-startup-responsive-ui_plan.md)

## 実装

- オーナーの追加指示に基づき、残り72・48・24時間を上から通過した瞬間に「試験の残り期限 あと○日」を警告ログとして表示する`TrialDeadlineWarning`を実装し、`TrialSession`のシミュレーション更新へ接続した。延長処理前後の両方で判定するため、同一tickでの境界通過と延長も扱う。延長後に境界へ再到達すれば再表示し、境界以下に留まるだけでは再表示しない。英語のログも追加した。

- `index.html`のheadから`src/styles.css`を読み込み、`GameApp.js`のCSS importを除いた。JavaScriptの読み込み順に依存せず、初期HTMLの描画前にHUDロゴの寸法を適用する。本番ビルドでもheadにCSSリンクが出力されることを確認した。
- フロートログの基準文字サイズを`clamp(18px, 4vmin, 32px)`とした。通常・幸運・不運・警告の倍率を本文へ適用し、アイコンの1.5em比率を維持した。従来は本文の32px固定指定が親の強調サイズを上書きしていた。
- 日本語のタイトルメニュー名を計画どおり変更した。英語も同じ意味の「Take the Hero Certification Exam／Ability Assessment／Records／Settings」とした。メニューの遷移処理と実力判定試験の解放判定は既存処理を使用する。主ボタンの文字サイズは縦横両方に追従させ、メニュー幅を画面内に制限した。
- UIスタイル仕様書へCSSの初期読み込み、メニュー名、ログの寸法管理を記載した。
- `tests/manual/phase_startup-responsive.html`に本番のFlowLog・ローカライズ・CSSを使用する表示確認ページを用意した。「4種類を流す」「配置して静止」「再開」「消去」で確認できる。静止表示は確認用ページだけの処理である。

### ブラウザ表示

- 本番画面でタイトルの`v0.47.3`を確認。日本語の通常メニュー、設定の開閉、日英の往復切替、英語の成績表の開閉、通常試験のパーティー選択への遷移を確認した。
- 390×844の縦画面、844×390の横画面、1280×720のPC画面でタイトルを確認。横画面の日本語主ボタンは幅280px・文字16pxで、文字の横方向のはみ出しなし。
- 確認ページで390×844から844×390へリサイズし、通常18px・幸運23.625px・不運20.25px・警告25.875px、参照アイコンは本文の1.5倍になることを確認した。
- 1280×900では通常32px・幸運42px・不運36px・警告46px、アイコン48px・63px・54px・69pxを確認した。
- 再開時に4種類の横断アニメーションと6・9・7・10秒の寿命、警告の脈動が適用されることを確認。実ゲームの一時停止はログのCSSアニメーションを停止しない既存仕様であり、今回その処理は変更していない。
- 「4種類を流す」の実行後、寿命を迎えた4件すべてがDOMから削除され、残数0件になることを確認した。実ゲームは開始劇をスキップして第1試験の課題選択まで進行し、ブラウザのコンソールエラーは0件だった。

## オーナー確認

STARTUP-01で準備途中のHUDが見えるとの指摘を受け、初期HTMLのAppShellへ`state-title`を設定した。従来はテキスト取得後にこの状態を付けていたため、取得待ちのHUDが表示されていた。実際のindex.htmlから起動スクリプトだけを外した一時ページで、JavaScript未実行時のHUDが`visibility: hidden`で背景だけ表示されることを確認した。通常起動・パーティー選択中も非表示で、試験への出発後は`visible`になることを確認した。一時ページは検証後に削除した。

英語名を日本語と同じ意味へ揃えるフィードバックを受け、英語の開始・実力判定メニューを修正した。390×844・844×390・1280×720で英語の開始ボタンに横方向のはみ出しがないことを確認した。主ボタンの幅はそれぞれ約353px・285px・431pxだった。修正版でも全テストと本番ビルドを再実行した。
