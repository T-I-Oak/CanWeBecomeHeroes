# スマホ課題選択画面のチップサイズ修正計画

## 合意内容

- ブランチ：`fix/v0.74-stage-selection-chip-scale`
- 予定バージョン：`0.74.0`。初回の実装開始時にpackage.json・package-lock.jsonを更新する。
- スマホの課題選択画面でチップの表示サイズ・比率が正しくない問題を修正する。
- 小:中:大 = `1:1.5:3`のサイズ比率は維持する。
- チップの配置方法はオーナーとのレビューで決定し、合意後に実装へ反映する。配置はこの計画では確定しない。

## スコープ

- 課題選択モーダルのレスポンシブなサイズ計算と配置を調査・修正する。
- スマホ縦・横画面で表示を確認し、PC表示と敵・タグのタップ判定への影響を確認する。
- 決定した配置に合わせ、必要な仕様記述と回帰テストを更新する。
- オーナー指示により削除済みの、ブラウザー検証手順と重複するバックログの調査記録を本ブランチに含める。

## 対象外

- 戦闘画面のチップサイズ変更。
- ゲーム内文言の変更。
- ブラウザーテストの制限環境自体への対応。
- 既存の保留中オーナー検証項目の一括再確認。

## 調査結果と実装方針

- `src/styles/flow-log.css`は960px以下で基準サイズを設定するが、`src/styles/screens.css`の敵表示列は同じ変数を100pxに再定義している。
- Canvasには枠幅による上限もあるため、基準サイズの上書きと枠による縮小が表示比率へ与える影響を実ブラウザーで確認する。原因は再現・寸法測定後に確定する。
- `StageSelectionModal.js`の描画、CSS上の表示寸法、`getPreviewTagAtPoint`の座標変換を照合する。
- 比率を維持した配置案を確認可能な形で提示し、オーナーとレビューする。合意前に配置を確定・実装しない。確認用ページなどは`tmp_`配下に置く。
- 6敵スロット・ボスの横2スロット占有などの現行仕様と配置案の関係を明示し、仕様変更が必要なら合意後に反映する。
- ゲーム内文言の変更が必要になった場合は、変更箇所と変更前後の全文を提示し、合意後に反映する。

## 完了条件

- オーナーと配置方法をレビューし、合意内容を実装報告に記録する。
- 小:中:大 = `1:1.5:3`を、表示後の実寸で確認する。
- 合意した配置でスマホ縦・横画面に収まり、チップ・タグの操作を妨げない。
- PCの課題選択画面と、敵・タグのタップ判定に問題がない。
- 必要なオーナー検証を一意ID付きで提示し、判断と対応を記録する。未回答を保留扱いしない。
- 対象テスト、全テスト、本番ビルドの結果を実装報告に記録する。失敗時は原因と対応を記録する。

## テスト方針

- `tests/implementation/app/StageSelectionPreview.test.js`等の既存テストを確認し、JS側のサイズ設定とタグ判定を検証する。
- 実ブラウザーでスマホ縦・横、PCの表示寸法と比率を測定する。DOMの模擬テストだけでCSSの正しさを判断しない。
- 小・中・大の混在と大サイズを含む敵構成を確認する。表示案に適した画面幅と確認条件はオーナーレビュー時に明示する。
- 実装終了草案前に`npm.cmd test`と`npm.cmd run build`を実行する。
- ブラウザー検証は`tests/02.browser_verification.md`に従い、Windowsでは`node scripts/verify-browser-tests.js`を権限制限外で実行し、テスト成功・正常終了・プロセスと待受の解放を確認する。
- 自動ブラウザー検証とスマホ実機の見た目・操作確認を区別する。
