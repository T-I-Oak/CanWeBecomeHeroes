# v0.81 合格通知サイン修正計画

## 合意内容

- 対象: CanWeBecomeHeroes。
- ブランチ: `fix/v0.81-certificate-signature`。
- 予定バージョン: `0.81.0`。初回の実装開始時に`package.json`と`package-lock.json`を更新する。計画中は`1.0.0`を維持する。
- 未公開のv1.0への更新を撤回し、サイン修正をv0系の開発として扱う。
- v1.0直前は`refactor/v0.80-periodic-review`の`0.80.0`。v1.0の実装コミット`5da78f0`の通常ファイルの変更はバージョン設定のみである。

## 開発スコープ

- v1.0へのバージョン更新を撤回し、設定とタイトル・倉庫の表示を`0.81.0`へ変更する。
- 合格通知のゼインのサインを、文字と飾り線を含むSVGパスへ変更する。端末のフォントに依存させない。
- 通知画面と共有画像が共通で使用する`TrialResultPaper.js`へ反映する。
- サインの描画方式を試験終了画面仕様へ反映する。

## 対象外

- 過去のv0.80のコード全体への巻き戻し、履歴の書き換え。
- 他の機能、ゲーム内文言、認定印の変更。
- 公開用JSONの変更、公開切替、再リリース。
- GameWorksOAKの変更。共通側は参照専用とする。
- 現在タグは存在しないため、タグ削除は行わない。

## 実装・テスト方針

1. `package.json`と`package-lock.json`のバージョンを`0.81.0`へ変更し、タイトルと倉庫の表示経路・実表示との一致を確認する。
2. SVGの`text`によるフォント描画を廃止し、Zaneの文字と飾り線をパスで描く。既存の配置・色・表示領域に収める。
3. 計画前に担当AIが無断で変更した`src/app/TrialResultPaper.js`と`docs/specifications/17.trial_result_screen.md`には未コミット差分がある。実装済みの成果とは扱わず、実装フェーズで差分と見た目を改めて確認し、本計画に適合する内容を採用・調整する。計画フェーズでは両ファイルを追加変更しない。
4. 通知画面と共有画像は`renderTrialResultPaper`を共有し、共有画像はDOMをシリアライズして生成する。両方でサインの欠け・位置ずれ・文字と飾り線の分離がないか確認する。
5. `tests/README.md`と`tests/02.browser_verification.md`に従い、関連テスト、`npm.cmd test`、`npm.cmd run build`、所定のブラウザー検証を実行し、コマンドと結果を実装報告へ記録する。失敗は原因を調査し、範囲内なら修正・再実行する。
6. Safariでの通知画面と共有画像の見た目を、それぞれ一意ID・理由・操作手順・期待結果・確認バージョン付きでオーナーへ提示する。自動検証をSafari実機確認済みと扱わない。
7. オーナー判断とフィードバック対応を実装報告へ記録する。未回答を保留と解釈せず、明示的な保留だけをバックログへ反映する。

## 完了条件

- バージョン設定とタイトル・倉庫の表示が`0.81.0`で一致する。
- サインの文字と飾り線がSVGパスで描かれ、端末のフォントに依存しない。
- 合格通知と共有画像でサインが表示領域に収まり、文字と飾り線の位置関係が維持される。
- 関連テスト・全テスト・本番ビルド・ブラウザー検証の結果が記録され、失敗時の原因と対応が説明されている。
- 必要なオーナー検証の判断・対応が記録され、未回答・未対応のフィードバックがない。明示保留は規定に従って記録されている。
- 公開用JSONや対象外の機能・文言・認定印に変更がない。

## オーナー指示による配信範囲の追加

- Safari実機検証のため、オーナーから「このブランチから直接公開してください」と指示された。
- 実装フェーズ中にこのブランチのv0.81.0をビルドし、gh-pagesへ直接配信する。masterへはマージしない。上記の再リリース対象外は、この検証用本体配信を除く。
- 公開用JSONの切替は行わない。配信後にSIGN-081-01・SIGN-081-02の判断を得る。両項目を保留扱いにしてフェーズを進めない。
