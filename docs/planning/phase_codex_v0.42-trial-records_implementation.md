## 実装した内容

- GameStatistics：今回ランと累積を独立して保持。全28組の開始・合格・不合格、課題、敵討伐、獲得ポイント、施設、Hero別タグ・武器・施設詳細を集約。Hero別討伐者情報はラン内のみ保持する。
- GuildSystem：成立した実消費貢献ポイントを通知し、今回ランと累積へ加算。獲得ポイントは別に保持し、過去の消費量を推測しない。
- StatisticsCollector：フックを2つの集計へ配信。開始前・直前のグレード表を保持し、表示段階の上昇と通知段階の上昇を区別する。
- AchievementDefinitions：68種類をJS定義で生成。通常58種類は立方根式・15段階、タグ10種類は(p-1)/2・3段階（B＋・A＋・S＋、未達成E）。共通段階テーブルを参照する。
- Achievements：G値から高い段階順に判定。E、判定、所見番号、通知段階を求め、前回との差分を返す。通常の所見はD/C・B/A・Sで3種類を共有。通知は初取得と文字が変わる節目のみ。上限到達後も今回のG値は制限せず保持する。
- public/data/text/achievement.json：確定した日本語所見と英語リソース。JS定義の生成時に敵名・タグスキル名を差し込み、言語別完成文として保持する。
- TrialStatisticsSessionとTrialRunResult.record：開始・フック・終了を接続。終了情報には累積評価、今回G値、更新の有無を全候補について定義順で渡す。表示件数による選定は後続UIの担当とする。
- RunRecordsRepository：課題決定時・ゲーム終了時に保存。終了履歴50件、通算統計、合格日時・回数、解放職業を保持し、終了通知・保存再試行で二重加算しない。旧クリアー情報の日時や回数を生成しない。
- RunRankings：試験3基準・チャレンジ4基準それぞれの上位10件の和集合を保持。どの基準にも入らないランキング結果を削除。一般集計とアチーブメントから独立する。
- 既存UIへの追加を除去。TitleMenu、TrialRunResultModal、UI文言、スタイル、表示検証ページの追加は今回の変更に含めない。GameAppとTrialSessionには収集・保存の接続だけを残した。

### 失敗時の調査・対応

- 初期の判定テストで前回グレードの入力例が期待結果と一致しなかったため、合意した差分方式に合わせて開始前グレードを明示するテストに修正した。
- 通常15段階への変更で、従来の3段階を前提にした収集テストの期待結果が失敗。新しい段階では敵討伐・ショップも達成するため、期待結果を新仕様に合わせた。
- 立方根計算の境界で丸め誤差が判定を1段階下げないよう、機械精度に応じた許容差を使用し、全定義の境界をテストした。
- 全テストでNodeのlocalstorage-file警告が出るが、テスト失敗はない。
