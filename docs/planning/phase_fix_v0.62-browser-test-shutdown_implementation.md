# Windowsのブラウザーテスト終了待ち：調査・実装結果

## 現在の実装（0.62.1）

終了草案後の指摘に対応し、バージョンを0.62.1へ更新した。
tests/README.mdの抽象的な確認手順を、実行・結果取得まで実施できる手順へ置き換えた。
Windows専用の`scripts/verify-browser-tests.js`を追加し、専用ポートの事前照会、
90秒上限、ルート・子孫プロセスの識別記録、Playwright JSON結果の読取、
終了コードとポート・プロセス解放の確認、正常時の連続再実行を一つのコマンドで行う。
標準ブラウザーテストに`--reporter=line,json`を付け、テスト内容・webServer設定は維持する。
失敗時の後処理は今回起動したプロセスの識別情報を照合して行い、後処理による成功への変更はしない。
判定と子孫識別の契約テストを実装前に作成し、未実装での失敗から成功を確認した。
ゲームのソース・表示・操作とLinux CIの実行方法は変更していない。

### 修正した手順の実行検証

最終版READMEの通常手順として`node scripts/verify-browser-tests.js`を制限外で実行し、
ツールの同じセッションの完了を待った。その後READMEのGet-Contentコマンドで
summary.json、run-1.json、run-2.jsonを読み、結果を照合した。
通常手順の検証中に別の起動スクリプトや手動のポート・プロセス照会・後処理を補っていない。

この異常系検証後に、上記の最終版通常手順を実施して再実行可能であることも確認した。

## 初回調査での判断と変更（0.62.0）

- バージョンを`0.62.0`に更新した（package.jsonとpackage-lock.json）。依存バージョンは変更していない。
- 制限環境で全4件の成功後に終了待ちを再現した。同一設定の制限外実行では2回とも正常終了した。
- この環境では、プロセス終了の権限を持つ実行環境を使うことで標準コマンドを運用できる。
  ゲームのソース、Playwright設定、起動方法、CI、依存パッケージの修正は不要と判断した。
- tests/README.mdへWindowsの終了処理と終了コード・後処理の確認手順を追記した。
  WindowsのCodex環境ではAI担当がブラウザーテストのサンドボックス外実行を申請し、
  承認範囲で実行する方針を明記した。全テストとビルドは通常の実行環境で実行する。
- バックログには終了待ちの観測条件と残る不確実性を残した。性能2件は未検証の調査候補として維持した。
  過去の作業条件の削除と事実・推測の整理は開始時点で反映済みだった。

## 再現と切り分け

| 実行 | 開始→終了（日本時間） | テスト | コマンド終了・後処理 |
| --- | --- | --- | --- |
| 制限環境の標準コマンド | 09:15頃→09:23頃に手動後処理 | 4件成功 | 正常終了せず。最終終了コードは未採取。成功扱いにしない |
| 制限外・残存サーバーあり | 09:23:43.660→09:23:44.486 | 未実行 | 4174使用中を検知し終了コード1、0.827秒 |
| 制限外・ポート解放後 | 09:24:03.229→09:24:27.935 | 4件成功 | 終了コード0、24.706秒 |
| 制限外・連続再実行 | 09:26:40.771→09:27:03.302 | 4件成功 | 終了コード0、22.532秒。外側90秒上限に達せず |

初回の事前ポート確認は制限環境で出力がなく、権限制限外での事前照会は行っていない。
初回は計画どおりの自動外側上限と厳密な開始・最終テスト完了時刻を設定できなかった。
ツールの待機で終了しないことを確認後、プロセス・ポートを採取して後処理した。
そのため初回の正確な終了待ち時間は比較できない。連続再実行では90秒の外側上限を設けた。

制限外のプロセス照会では、初回のPlaywright PID 58272配下に次が残っていた。

- 開発サーバー：cmd 24756 → npm 53356 → cmd 45624 → Vite 55512、4174で待受。
- 本番preview：cmd 16752 → npm 52228 → cmd 47196 → Vite 53648、4175で待受。

ビルドは完了してpreviewが起動し、開発・本番両方のテストが成功しているため、
ビルドやテスト本体の完了待ちではなく、サーバーとシェルの終了段階に問題が絞られる。
制限内のWin32_Process照会はアクセス拒否だった。
制限外のStop-Processによる後処理もエラーになり、ポートが残ったため、
確認済みの今回のサーバー親PID 24756・16752へ`taskkill /T /F`を実行して解放した。
続けて58272の終了も確認した。別用途の既存Vite PID 10152は対象にしていない。

インストール済みPlaywrightの実装を確認した。
`node_modules/playwright/lib/runner/index.js`のwebServerはWindowsで強制終了経路へ進み、
`node_modules/playwright-core/lib/coreBundle.js`は`taskkill /pid ... /T /F`の後に
子プロセスのcloseと後処理を待つ。この経路のtaskkillの終了値は確認されない。
権限制限で終了に失敗するとclose待ちに残る実装と、今回の残存状態は整合する。
ただし初回のtaskkill自身の戻り値・アクセス拒否ログは採取しておらず、
権限制限の具体的な拒否箇所まで確定したとは扱わない。過去の記録の原因も未確定。

制限外1回目は09:24:26.626から27.887までの約1.261秒で両サーバーの終了処理を完了した。
2回目は最終テスト完了09:27:02.045、終了処理02.262→03.238、コマンド終了03.302だった。
両実行後に制限外で4174・4175の待受なし、対応するnode/cmdプロセスなしを確認した。
TCPのTIME_WAIT（PID 0）は残るがサーバー待受ではない。実際に続けて標準コマンドを再実行できた。
