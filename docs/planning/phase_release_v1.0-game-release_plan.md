# v1.0 ゲーム本体の配信準備計画

## 合意内容

- 対象: CanWeBecomeHeroes。
- ブランチ: `release/v1.0-game-release`。
- 予定バージョン: `1.0.0`。初回実装開始時に`package.json`と`package-lock.json`を更新する。計画中は`0.80.0`を維持する。
- オーナーはv1へ更新してゲーム本体をpushし、その後に公開用JSONを準備してpushせず保持する順序を指示した。
- ポータルでの公開予定日は2026-11-01。ゲーム本体の事前配信と、当日の公開情報・導線の切替を分ける。

## 開発スコープ

- ゲーム本体のバージョンを`1.0.0`へ更新する。
- 設定とタイトル・倉庫左下のバージョン表示の一致を確認する。
- 対象テスト、全テスト、本番ビルド、ブラウザー検証を実行し、必要なオーナー確認を扱う。
- レビュー後、所定のマージ手順でmasterへマージ・pushする。
- GitHub Actionsのデプロイ完了と対象コミットを確認し、配信されたゲームを直接URLで確認する。
- ポータル向けデータが予告表示・無効ボタン・空の更新履歴を維持していることを確認する。

## 対象外と境界

- `public/data/project_info.json`と`public/data/update_history.json`はこのブランチで変更しない。前者は予告文言と`button.type: pending`、後者は空配列を維持する。
- 公開情報のJSONはポータルから参照されるため、本体配信前にこのブランチへ混ぜない。v1本体のpushと配信確認の後、別のローカルブランチで準備する。そのJSON変更は公開当日までマージ・pushしない。
- 上記はオーナーが指定した公開順序であり、一般の公開手順にある更新履歴整備は後続のJSON準備で扱う。本体がv1になったことだけを理由に更新履歴を先行公開しない。
- 新規機能、ゲーム仕様・バランス・文言・アセットの変更は行わない。
- GameWorksOAKは参照専用。ポータル一覧にCanWeBecomeHeroesが登録済みであることは読み取り確認済み。
- 実際のポータル公開、公開バッジの反映、更新履歴の公開、公開完了宣言は今回の本体事前配信とは区別する。

## 実装・検証方針

1. バージョン設定を更新し、`AppMetadata.APP_VERSION`からタイトルと倉庫へ伝わる経路と実表示を確認する。依存物は更新しない。
2. `tests/README.md`と`tests/02.browser_verification.md`に従い、変更に対応する対象テスト、`npm.cmd test`、`npm.cmd run build`を実行する。
3. Windowsのブラウザー検証は`node scripts/verify-browser-tests.js`のサンドボックス外実行を申請し、標準5件の2回連続成功、正常終了とポート・プロセス解放を記録する。公開ワークフロー上の検証成功とは区別する。
4. 必要な実機・視覚判断は一意ID、理由、操作、期待結果、確認バージョン付きで提示する。オーナーの確認済み・却下・フィードバック・明示保留を記録し、未回答を保留扱いにしない。
5. 検証失敗は原因を調査する。仕様変更や範囲拡大が必要なら合意を得る。修正を行う場合は実装フェーズのバージョン規定に従う。
6. 実装結果とコマンド・結果・オーナー判断を`phase_release_v1.0-game-release_implementation.md`へ記録する。実装担当はレビュー結果を代行して記録しない。
7. レビュー後、マージ着手前とpush直前に共通ライブラリの公開状態を所定の6コマンドで確認する。全フォルダーの`dev_`・`tmp_`・`phase_`成果物を安全確認して削除・再走査し、削除をコミットしてmasterへマージ・pushする。
8. ローカル・リモートmasterのコミット一致、デプロイ対象コミット・共通参照・配信先を確認する。公開URL `https://t-i-oak.github.io/CanWeBecomeHeroes/`で入口・読み込み・主要操作・素材・バージョンを確認する。
9. 配信先の2つのJSONが予告のままであることを確認し、本体配信結果と未実施の当日作業を報告する。

## 完了条件

- ゲーム本体の設定とタイトル・倉庫の表示が`1.0.0`で一致している。
- 対象テスト、全テスト、本番ビルド、ブラウザー検証のコマンドと結果が記録されている。失敗時は調査と対応が記録されている。
- 必要なオーナー検証の判断・対応が記録され、未回答・未対応のフィードバックがない。明示保留だけがバックログへ反映されている。
- レビューを通過し、公開先で対象コミットのゲーム本体が配信され、主要な動作を確認できる。
- このブランチに2つの公開用JSONの差分がなく、配信先でも予告表示・`pending`・空の更新履歴が維持される。
- 後続のJSON準備と当日の公開切替が未実施であることを明示し、ゲーム本体の配信だけで公開完了としない。
