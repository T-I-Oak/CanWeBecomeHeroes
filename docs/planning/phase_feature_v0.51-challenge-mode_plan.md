# 実力判定試験の開発計画

## 合意した進め方

- ブランチ: `feature/v0.51-challenge-mode`。
- 予定バージョン: `0.51.0`。設定ファイルの更新は初回の実装開始時に行う。
- 実力判定試験の具体的な設計は、既存仕様と実装を調査し、オーナーと相談して決定する。未決事項を推測で補わない。
- 計画フェーズでは実装しない。相談結果を計画へ反映し、計画書と引継ぎ書の草案を提示する。終了草案の承認後に引継ぎ書を保存し、変更一式をコミットする。
- 課題記録のチップ表示は課題選択画面へ適用しない。オーナーの指示によりバックログの検討項目を削除した。

## 対象と対象外

実力判定試験の開始・進行・終了、背景プログレス、専用チュートリアル、終了通知、記録保存、ランキング閲覧を実装する。終了時に合格・不合格を付けず成績を示す。

共有機能、戦闘バランス調整は対象外。実力判定試験のランキング閲覧は対象に含め、以下のオーナー合意に従う。

## 調査で確認した既存事項

- `docs/requirements/01.game_settings.md` は、無限挑戦モードを7日間の期限で開始し、期限が切れるまで敵へ挑戦するものと定義している。これを今回どのように具体化するかは相談する。
- `src/app/TitleMenu.js` は試験合格後にチャレンジの項目を表示する。一方、`src/app/GameApp.js` は `trial` 以外の選択では開始処理へ進まない。
- `src/game/RunController.js` は試験の第7課題の合格・期限切れを扱う。チャレンジの終了判定を実装済みと扱わない。
- `src/game/TrialStatisticsSession.js` の開始・終了記録は `trial` 固定。
- `src/game/RunRankings.js` にチャレンジの順位基準がある。`docs/requirements/06.run_records.md` はクリアー課題数・経過時間・討伐数・獲得貢献ptを基準としている。これは結果画面の表示項目への合意ではない。
- `docs/specifications/17.trial_result_screen.md` は試験の合格・不合格通知を対象とし、チャレンジの結果画面は未定義。

## オーナーと確認した進行ルール

- 勇者認定試験は、第7課題までクリアーすると合格する。
- 実力判定試験には第7課題クリアーによる終了条件がなく、進めるだけ課題を進む。第7課題までの繰り返しとは解釈しない。
- 初期の残り期限は7日間。ギルドで延長でき、延長分を含む残り期限が尽きた時点で終了する。
- 実力判定試験には合格・不合格を設けず、終了時に成績を示す。
- 正式名称は「実力判定試験」。既存文書の「無限挑戦モード」やバックログの「チャレンジモード（エンドレス）」は名称の不整合として扱う。内部識別子の変更要否は別途検討する。

## オーナーと合意したゲーム中の表示・既存計算

- 課題レベル、敵の編成・能力・装備タグ、報酬、加入上限の既存計算は実力判定試験を想定済みとして維持する。第7課題の上限撤廃を理由とする調整は行わない。
- ギルドの課題番号と重なる背景プログレスは、7課題ごとに紫系と赤系を交互に重ねて塗り替える。
- 第1～7課題は現状と同じ進行表示。第8～14課題は前の巡で満ちた紫系を残し、左から赤系で1/7～7/7を置き換える。
- 第15～21課題は満ちた赤系を左から紫系で1/7～7/7置き換える。以後も同じ交互切替を続ける。区切りでバーを空へ戻さない。
- 課題番号の表示位置は維持し、印・巡数・別の表示行は追加しない。色の具体値は実装時に見た目を確認する。
- この帯は7課題ごとの進行を示す。途中の課題でもボスは出現するため、「次のボスまでの進捗」や「ボス撃破数」とは説明しない。

## オーナーと合意したチュートリアル追加

- チュートリアルのシナリオに、実力判定試験のチュートリアルを追加する。
- 先行条件は設けない。チュートリアル開始時、通常チュートリアルの先頭と同じタイミングで提示する。
- シナリオの日本語本文は以下のとおりオーナー承認済み。以下の3ブロックのページ分割は未確定。その他の未指定の詳細は推測で決めず相談する。

> やあ、君たちか。よく来てくれた。
> 実力判定試験は初めてかな？ それでは、試験について案内しよう。
> 勇者認定試験を受けた君たちなら、すぐに分かるはずだ。

> 期限は7日間。
> 勇者認定試験とは違い、第7課題をクリアーしても試験は終わらない。
> 期限が尽きるまでに、どこまで課題をクリアーできるか。その実力を測る試験だ。

> これまでと同じく、ギルドで貢献ポイントを使えば期限を延ばせる。
> 持てる力を尽くし、どこまで進めるか見せてくれ。
> 君たちの健闘を祈る。

## オーナーと合意した実力判定試験の終了画面

- 見出し: 「勇者実力判定試験 試験結果」。
- 本文（オーナー承認済み）: 「今回の実力判定試験では、試験期限内に第○課題まで到達しました。」「この成果を糧に、さらなる高みを目指してください。」の2文。○は到達課題番号に置き換える。
- メンバー: 勇者認定試験の合格通知と同じく、終了メンバーを二つ名付きで表示する。
- 日付: 「判定日」。
- 発行者: 「勇者ギルド試験委員会」。
- 署名・印: 表示しない。
- 演出: 不合格時と同じ。ただし、紙面の導入アニメーションは合格時と同じものとする。「試験終了」の表示後、大きく透明な紙面が縮小しながら現れ、紙吹雪は出さない、という解釈で記録する。
- 裏面: 既存の共通成績表を使用する。
- 本文の「到達」は、終了時に挑戦していた課題番号を指す。1課題もクリアーしていない場合も、第1課題まで到達したものとして同じ文言を使用できる。
- ランキングで使用するのはクリアーした課題数。本文の到達課題番号をランキングのクリアー課題数として使用しない。たとえば第8課題に挑戦中に終了した場合、本文は第8課題まで到達、クリアー課題数は7となる。

## オーナーと合意したランキング

- 実力判定試験のランキングは、トップメニューと同じく勇者認定試験をクリアーするまでレコード画面で非表示にする。ランキングデータの有無を解放条件の代用にしない。
- レコード画面のセレクターが長くなりすぎる場合は、「勇者認定試験」「実力判定試験」のラベルとして「ランキング」を省略する。
- 実力判定試験のランキングは勇者認定試験とほぼ同じ構成とし、「残り時間」を「経過時間」に置き換える。
- 既存のカラム名「クリアー課題数」をそのまま維持する。値は終了通知の到達課題番号ではなくクリアーした課題数を使用する。
- 経過時間は既存の順位定義どおり長い方を上位とする。
- 既存のチャレンジ用順位基準（クリアー課題数・経過時間・討伐数・獲得貢献pt）を参照し、画面の具体的な列・切替との対応は勇者認定試験の実装を照合して整理する。未指定の独自機能は追加しない。

## 開始時の共通動作

初期メンバー選択・開始劇・初期配置などの開始時の動作は、勇者認定試験と同じものを使用する（オーナー合意済み）。

既存の試験合格による実力判定試験の解放を維持する。内部識別子 `challenge` と合意済みブランチ名は維持し、利用者向け表記・文書を正式名称へ整合させる。新たに仕様判断が必要になった場合は、確定事項と提案を分けて相談し、未回答を合意と扱わない。

## 実装・検証方針

1. `GameApp`・`TrialSession`・`RunController` のモード分岐を整備する。共通の開始動作を使用し、実力判定試験だけ第7課題で終了しないようにする。
2. `GuildPanel` の背景に7課題単位の交互の塗り替えを追加する。第1・7・8・14・15・21・22課題の境界と、勇者認定試験の既存表示を検証する。
3. チュートリアルのシナリオ定義・選択条件を整備し、実力判定試験の開始時に先行条件なしで承認済み本文を提示する。通常試験用の説明との誤混在、既読・リセット動作を確認する。本文は3ブロックを基に画面へ収め、内容変更が必要なら相談する。
4. 終了通知の型・本文・二つ名の生成・演出を整備する。合否、紙吹雪、署名・印の有無を単一の合格フラグで決めず、実力判定試験の指定に対応する。表裏操作・タイトル復帰は既存の動作を使用する。
5. `TrialStatisticsSession` のモード固定を解消し、実力判定試験の開始・終了・集計・ランキング登録を既存の保存構造に接続する。合否を誤集計せず、終了・保存再試行・表裏操作で二重集計しないことを確認する。既存の記録・解放・アチーブメントを維持する。
6. `RecordScreen` に実力判定試験ランキングの閲覧を追加する。順位・クリアー課題数・経過時間・討伐数・獲得貢献pt・メンバー・日時を既存表と同じ構成で扱い、既存のモード別順位基準へ接続する。
7. 日英リソースと要求・仕様文書を更新する。旧名称・未実装記述・対象外記述を実装結果に合わせて整理する。

進行・終了・保存に複雑なロジックを追加する場合は、合意した挙動のテストを先に作成する。第7課題クリアー後の継続、期限切れ終了、0課題クリアー、第8課題挑戦中の終了、期限延長、記録のモード分離を検証する。通知の到達番号とランキングのクリアー課題数を別々に検証する。実装中に対象テストを行い、終了草案の提示前に `npm.cmd test` と `npm.cmd run build` を実行する。日英表示・スマートフォン縦横で、通知の表裏・二つ名・ボタン、ランキングの列・切替、チュートリアルの収まりを確認する。

必要なオーナー検証は確認可能な実装ができた時点で、バージョン・理由・操作・期待結果を項目ごとに提示する。未回答の検証を担当者判断で保留しない。

## 計画の完了条件

相談事項について合意または明示的な対象外の判断を記録し、実装スコープ・対象外・完了条件・検証方針を具体化する。その後、次フェーズを実装とする引継ぎ書の草案を提示して承認を得る。

## 実装の完了条件とオーナー検証方針

- 共通の開始動作から実力判定試験へ入り、第7課題を越えて進み、延長分を含む期限終了で指定の通知と共通成績表を表示してタイトルへ戻れる。
- 課題番号を維持したまま背景が7課題ごとに交互に塗り替わり、専用チュートリアルは指定のタイミングで提示される。
- モード別の記録・ランキングが保存され、既存カラム名を維持しつつ経過時間で閲覧できる。勇者認定試験の合否・解放・記録・表示に退行がない。
- 勇者認定試験クリアー前は実力判定試験のランキングをレコード画面で非表示とし、クリアー後に表示する。日英・スマートフォン縦横でセレクターの収まりを確認し、長すぎる場合はラベルから「ランキング」を省略する。
- 対象テスト・全テスト・本番ビルドの結果を実装報告へ記録する。
- オーナー検証として、背景の色と塗り替え境界、専用チュートリアル、終了通知の文面・二つ名・導入演出・共通裏面、ランキングの表示と切替を、実装後に1件ずつ判断できる項目で提示する。必要な判断とフィードバック対応を記録し、明示的に保留された項目だけをバックログへ残す。
