# ブランチ作業フロー

## 適用する共通ルール

このプロジェクトの開発は、以下の共通ルールに従う。

- [共通ワークフローガイド](../../../GameWorksOAK/docs/common/03.workflow_guide.md): バージョン、バックログ、ブランチ、検証、定期見直し。
- [フェーズ作業手順](../../../GameWorksOAK/docs/common/03.phase_workflow.md): フェーズ判定、開始合意、終了草案承認、引継ぎ書、コミット、マージ・push。
- [共通構成](../../../GameWorksOAK/docs/common/04.common_structure.md#フェーズ成果物): phase_成果物の配置・追跡・削除。
- [共通ライブラリの公開状態確認](../../../GameWorksOAK/docs/common/90.common_library.md#公開状態の確認): ゲームのマージ着手前・push直前の確認。
- [共通仕様準拠チェックリスト](../../../GameWorksOAK/docs/common/99.compliance_checklist.md): 開発完了・レビュー時の照合。

文書・コーディング・CSS・モバイル対応もGameWorksOAKの共通ガイドに従う。
共通側の未コミット変更を正式適用済みの規定として扱わない。

## このプロジェクトの担当範囲

担当AIの責務はCanWeBecomeHeroesの開発である。
GameWorksOAKは開発ルールと共通ライブラリの参照専用とし、変更しない。
共通基盤に修正が必要な場合は、問題と必要な変更をオーナーへ報告し、共通部担当による対応を求める。

## 検証時の具体的な確認先

- オーナー指示：URLパラメーターへバージョン番号を付ける対応は禁止する。表示・読み込みの不具合をキャッシュの問題と推測して回避せず、配信内容と実際の取得・処理結果を照合して原因を調査する。

- オーナーへゲームの確認を依頼するときは、package.jsonのバージョンをチャットに記載する。
- タイトルと倉庫左下の `vX.Y.Z` が設定と一致することを確認条件とする。
- 検証項目の一意ID、判断・フィードバックの記録、バックログ追加時のチャット通知は共通のフェーズ作業手順に従う。
- 自動検証のコマンドと対象は[テストの構成と実行](../../tests/README.md)を参照する。
