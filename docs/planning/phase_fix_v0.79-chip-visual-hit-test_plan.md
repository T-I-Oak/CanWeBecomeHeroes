# Chip表示位置に合わせた操作判定の開発計画

## 合意した開発内容

- ブランチ: `fix/v0.79-chip-visual-hit-test`
- 予定バージョン: `0.79.0`。新規不具合対応としてMinorを更新し、初回の実装開始時にpackage.json・package-lock.jsonへ反映する。計画時点の設定は`0.78.0`のままとする。
- バックログ対象: バウンド中のChipの操作判定が地上位置に残り、表示中のChip本体とずれる問題。

## 開発スコープ

- Chip本体の表示位置に、ドラッグ開始・ドラッグ先・タップ・カーソルの操作判定を合わせる。
- 高さと演出オフセットを反映した描画座標と、操作判定の座標を整合させる。
- 重なり時は描画上の手前のChipを優先する。
- 関連する要求・仕様を更新し、対応結果に基づいてバックログを更新する。

## 対象外

- バウンド・落下・衝突などの物理挙動の変更。
- ゲームルールおよびゲーム内文言の変更。
- 共通リポジトリGameWorksOAKの変更。

## 調査で確認した現状

- `src/chips/ChipRenderer.js`は本体中心を`x + effectOffsetX`, `y - height + effectOffsetY`で描画している。
- `src/game/HeroItemInteractionController.js`の`getEntityAt`は描画順を逆順で走査するが、地上位置`x, y`と半径による円形判定を使用している。
- `src/app/GameCanvasInput.js`のドラッグ開始・移動先・確定処理は共通のエンティティ取得を利用し、タップ・カーソルも呼出し経路の確認が必要である。
- タグなどの個別情報判定は既に表示位置を使う箇所があるため、Chip本体の判定と照合する。

## 完了条件

- 浮いているChipを表示位置で操作でき、Chip本体から離れた影の位置では選択されない。
- ドラッグ開始・ドラッグ先・タップ・カーソルで表示位置に整合した判定が使われる。
- 静止時・重なり時・ズーム時の操作に退行がなく、重なり時は描画上の手前が優先される。
- 対象回帰テスト、全テスト、本番ビルドの結果を実装報告へ記録する。失敗時は原因と対応または対象外とする根拠を記録する。
- オーナーへ操作確認を提示し、各項目の判断と対応を記録する。保留はオーナーが明示した場合だけとする。

## 実装方針

- 描画と入力が参照する表示中心の算出方法を揃え、座標式の不一致を防ぐ。
- 既存の描画順とカメラの画面座標からワールド座標への変換を維持し、操作対象の取得経路を確認する。
- 本体形状・表示倍率などの既存描画変換を確認し、今回の位置補正に伴う判定範囲の不整合を防ぐ。
- 物理計算用の地上位置は操作判定の補正のために変更しない。

## テスト・検証方針

- 実装前に表示位置と地上位置が十分離れた状態の回帰テストを追加し、現状で失敗することを確認する。
- 高さ・演出オフセット・静止状態・重なり順について、表示位置での選択と、本体から離れた地上位置での非選択を検証する。
- `tests/implementation/app/DragControls.test.js`、入力関連テスト、要求02のテストなどでドラッグ・タップ・カーソルの経路を検証し、必要な箇所に回帰条件を追加する。
- 実ブラウザーで浮いているChipの操作と、ズーム時・重なり時の判定を確認する。合成入力の確認と実機での操作感を区別する。
- 全テストは`npm.cmd test`、本番ビルドは`npm.cmd run build`を実施する。ブラウザー検証は`tests/README.md`に従い対象を選択する。
- オーナー確認には一意ID、理由、操作手順、期待結果、設定とタイトル・倉庫左下の表示に一致する確認バージョンを提示する。
