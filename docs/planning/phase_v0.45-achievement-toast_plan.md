# アチーブメント取得トーストの開発計画

## 合意した開発単位

- ブランチ：`feature/v0.45-achievement-toast`
- 予定バージョン：`0.45.0`。初回の実装開始時にpackage.jsonとpackage-lock.jsonを更新する。
- 目的：ゲーム中のアチーブメント達成を、既存の評価・集計と共通表示部品を利用して利用者へ通知する。

## 開発範囲

- TrialStatisticsSessionの通知コールバックを表示側へ接続する。ラン開始・初期Heroの接続時に生じる通知も扱う。
- createAchievementTableのtoastモードと共通CSSを利用し、評価項目と到達した判定を表示する。
- 同時または連続して発生する通知の待ち行列と表示のライフサイクルを管理する。
- 日本語・英語の既存リソースへ接続する。
- タイトル復帰・セッション終了時に表示、待ち行列、タイマーやイベントの後始末を行う。結果画面への遷移時の扱いは実装中に確認する。
- 確定した通知条件・表示仕様を関連文書へ反映し、バックログの実装済み記述と後続作業を整理する。

## 実装中に確認して決める事項

- 通知条件、特にC−／C／C＋のような同じ文字の細分段階をCという1つの通知段階にまとめるか、細分段階ごとに通知するか。
- 表示位置、表示時間、複数通知の表示順・まとめ方、表示開始・終了のアニメーション。
- ラン開始の演出、各モーダル、終了画面との重なりと通知の扱い。
- 日本語・英語およびモバイル画面での読みやすさと操作への影響。

既存仕様は初取得と通知段階の上昇を通知し、通常項目の−／無印／＋は同じ文字の通知段階にまとめている。この通知段階の粒度は、実装中に再調整する。一方、E→C＋のように1回の更新で複数段階を越えた場合は、最終到達段階を1件だけ通知し、途中段階を個別に通知しないことがオーナー確認済みである。画面上部中央に1件ずつ約3秒表示する案は検討の出発点であり、確定要件ではない。表示方法・アニメーションを含め、実装中にオーナーが確認しながら決める。

## 対象外

- レコード閲覧画面、統計・ランキングの閲覧表示。
- Hero解放のタイミングの変更。
- チャレンジモードの実装。
- 終了画面の追加変更。ただしトーストの表示終了・通知処理との接続は本開発で扱う。
- アチーブメントの収集範囲、達成条件式、保存形式の拡張。
- GameWorksOAK側の変更。

## 実装方針

- 集計・評価は既存のGameStatistics、StatisticsCollector、Achievementsに委ね、表示側に個別条件や集計処理を持たせない。
- 通知の待ち行列・時間管理・破棄処理は表示の責務として分離する。共通DOM生成は翻訳・判定・保存を担当しない。
- 通知条件を調整する場合は、通知段階の比較と整数達成グレードの比較を区別し、終了画面の評価・選定と保存へ影響させない。
- 表示のために再集計・再保存しない。保存済み達成の初期評価を新規取得として通知しない。
- 操作対象を遮らない配置と入力処理を採用し、既存の共通CSS・モバイル規約を参照する。

## 検証方針

- 通知条件を変更する場合、合意した条件を先にテストへ反映し、初取得・同通知段階内の上昇・段階跨ぎ・複数段階跨ぎを検証する。
- E→C＋などの複数段階跨ぎは、途中段階を通知せず最終到達段階の1件だけを通知することを検証する。
- 通知の順序・重複・取りこぼし、ラン開始時の通知、表示中の追加通知、タイトル復帰・再開始時の破棄を対象テストで検証する。
- 終了時の通知と結果画面の達成表示が独立し、通知によって保存・集計が再実行されないことを確認する。
- オーナーが判断できる実装を用意した時点で、表示・演出・通知条件を確認項目として提示する。各項目に理由・操作・期待結果と実装バージョンを示す。
- 項目ごとの判断とフィードバック対応を実装報告へ記録する。未回答を保留とせず、オーナーが現時点で確認しないと判断した項目のみバックログへ残す。
- 実装の終了草案提示前に、対象テスト、`npm.cmd test`、`npm.cmd run build`を実行し、コマンドと結果を実装報告へ記録する。

## 完了条件

- 合意した通知条件・表示方法・アニメーションでトーストが動作し、日本語・英語へ対応している。
- 複数通知が合意した方針で処理され、画面遷移・再開始時に不要な通知やタイマーが残らない。
- 集計・保存・終了画面の判定を壊さず、必要な対象テスト・全テスト・本番ビルドの結果が記録されている。
- 必要なオーナー検証の判断と対応が記録され、未対応のフィードバックや未回答項目がない。明示的な保留はバックログに記録されている。
- 確定した仕様とバックログが現在の実装に一致している。
