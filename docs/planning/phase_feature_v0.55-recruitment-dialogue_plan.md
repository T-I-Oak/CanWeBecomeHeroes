# Hero加入会話の見直し計画

## 開発範囲

- ブランチ: `feature/v0.55-recruitment-dialogue`
- 予定バージョン: `0.55.0`。初回実装開始時にpackage.jsonとpackage-lock.jsonを更新する。
- 一般用48件と知人用24件の日本語を本書の確定台詞へ合わせ、英語も同じ意味・人物像で整備する。
- 知人がPartyにいる場合、2人PartyではB、3人PartyではCへ優先配置する。知人は最大1人。知人を除くメンバーは既存の配役優先順で残る役へ割り当てる。
- 知人関係はアヴェリー／ブライアー、ケイシー／ダーシー、エリス／フィンリー、ガーネット／ハーパーの4組。
- 知人の有無に応じ、Xの登場・B(C)の誘い・Xの承諾を一式で切り替える。知人用は一般用と同文でも独立して定義し、一般用へのフォールバックを設けない。
- 加入劇の仕様と関連文書を更新する。人物設定資料の魔法・属性に関する表現を確認し、無属性の魔法攻撃と属性の軽減を混同させる箇所があれば修正する。
- バックログから整備済みの紹介情報、オーナーが調整不要と判断した使い魔の威力・戦闘時間・試験難易度、今回実装する加入会話の項目を整理する。既存の保留オーナー検証は維持する。

## 対象外

- 登場・交戦・移動等の演出追加、開始劇の台詞変更、戦闘バランス変更。
- 以前の3対3シミュレーションのログ件数差の原因究明。本会話中の2対1の測定は、その原因を説明する根拠には使用しない。
- GameWorksOAK側の変更。

## 実装方針

- 呼び出し側で知人関係と配役を確定し、シナリオ生成へ必要な情報を明示的に渡す。現行のRecruitmentCast、TrialSession、RecruitmentVignette、RecruitmentVignetteScenarios、GameTextRepositoryの責務を調査して変更箇所を決める。
- 表示の6発言順はA→B→X→B(C)→X→Aを維持する。知人用でもAの感想・Bの労い・Aの締めは一般用を使う。
- 知人同士は、試験場で偶然会った反応から誘い・承諾へつなぐ。「同じ試験」と断定せず、合否のない実力判定試験でも成立させる。
- アヴェリーが張り合い、ブライアーが穏やかに付き合う関係を保つ。他の組も開始劇と人物設定に合わせる。
- 英語は日本語確定稿を基準に作成する。日本語の内容を独断で変えない。

## 完了条件と検証

- 下記72件の日本語と対応する英語が揃い、一般用／知人用の選択が正しい。
- 2人・3人Partyそれぞれで、知人あり／なし、既存優先順と知人位置が異なるケース、4組の両加入方向を確認する。
- 配役の重複・欠落がなく、加入者を既存Partyの役へ配置しない。知人なしの既存配役順は維持する。
- 6発言、Skip、加入確定、時計停止・再開、次課題への進行を維持する。
- 既存の加入劇テストと翻訳整合性検証を確認し、配役・分岐に対する意味のある回帰テストを追加する。複雑な選択ロジックは先にテストを書く。
- 対象テスト、`npm.cmd test`、`npm.cmd run build`を実装終了草案前に実行して結果を実装報告へ記録する。
- 画面で一般用と知人用の台詞の収まり、再会から承諾・締めへの流れ、2人／3人の配役を確認できるオーナー検証を提示し、判断を記録する。

## 会話の確認結果

- 一般用A→Bの同一人物を除く56通りは、番号3の修正後に確認済み。番号8からの接続はオーナーが許容範囲と判断した。
- 一般用X→B(C)→Xの56通りは、番号20の質問を手当ての申し出へ修正して確認済み。
- B→Xは登場で会話が切り替わるため、直接の受け答えではない。最後のAは加入を受けた全体の締め。
- 知人用は4組・両方向をオーナーが確認し、試験場での偶然の再会を加えて最終調整した。実画面での収まりと締めへの流れは実装中のオーナー検証でも確認する。
