# レコード画面の敵Ex情報への導線

## 開発スコープ

- 予定バージョンは `v0.59.0`、ブランチは `feature/v0.59-record-enemy-ex-info` とする。バージョン設定は実装開始時に更新する。
- レコード画面で開く静的なEnemy情報に、中ボスは `Ex1`、ボスは `Ex2` のクリック可能な表示を置く。
- その表示から、対応する固有スキルの静的な情報ウィンドウを子として開く。親ウィンドウは残し、既存の子ウィンドウ管理規則を使う。
- 静的Enemy情報の共通描画に適用し、レコード画面専用の実体やスキル対応表は作らない。
- 情報ウィンドウの要求・仕様を更新し、実装完了時に今回の要望をバックログから除く。

## 対象外

- Enemyの実体生成・実体への紐付け、現在HP・装備などの動的情報の追加。
- 戦闘処理、固有スキルの効果・説明文、レコードの保存形式の変更。
- 既存のオーナー検証項目の一括再確認。

## 完了条件

- 中ボス・ボスの定義に対応したEx段階とスキルへの導線を表示する。
- スキルを持たない雑魚や、Hero・Itemの静的情報にはExを追加しない。
- Ex表示の操作で正しい固有スキルの子ウィンドウが開き、既存の閉じる・子の置換の規則を維持する。
- 実体情報での既存のEx表示・導線を維持する。
- 対象テスト、全テスト、本番ビルドの結果を実装報告へ記録する。
- 必要なオーナー検証はID・手順・期待結果・確認バージョン付きで提示し、判断と対応を記録する。

## 実装方針

- `RecordInformation` は定義情報を開き、`CatalogInformationRenderer` が静的Enemy情報を描画している。Enemy定義は `EnemyCatalog` に固有スキルIDと段階を保持しているため、その値を参照する。
- `EntityInformationRenderer` の実体用Exボタンの表示・子情報を開く動作に揃える。必要に応じて小さな共通生成処理へまとめ、静的情報でも実体を要求しない構造にする。
- 既存の固有スキル詳細表示を使用し、独自の詳細画面や効果データを作らない。
- 文言は既存のローカライズ経路とアクセシブルな名称を使用する。

## テスト方針

- `tests/spec/05.information_window.test.js` と関連する描画テストで、静的な中ボス・ボスのEx表示、対応スキルの子ウィンドウ、雑魚・Hero・Itemへの非表示、実体情報の既存動作を確認する。
- レコード画面の定義情報を開く経路との接続を確認する。既存のDOMテスト構成を優先して利用する。
- 対象テストを随時実行し、実装終了草案前に `npm.cmd test` と `npm.cmd run build` を実行する。失敗時は原因と対応を記録する。
- オーナー検証では、レコード画面の中ボスとボスについて、それぞれのEx表示とタップ後のスキル詳細を確認できる項目を提示する。

## 検証結果の非同期反映

- `OV-CLOTH-10` と `OV-FIRE-06` はオーナーが確認済みと判断したため、バックログから削除済み。今回の計画終了コミットにこの更新を含める。
