# 計画: v0.40 定期見直し

## 開発スコープ
新規開発においてMinorの下1桁が0（v0.40.0）となるため、機能の実装を行わず「文書とソースの定期見直し」のみを実施する。
このリポジトリの `docs/planning/01.branch_workflow.md` の「定期見直し」に基づき、以下の範囲を見直す。10回おきの見直しとフェーズ運用は、このリポジトリでの実験適用である。
- **開発ルール**: プロジェクトの `docs/planning/01.branch_workflow.md` 等の開発手順を読み直し、着手前判定に使う。
- **文書**: 存在しない仕様の削除、章構成の整合性確認、ファイルサイズ（1文書100〜300行程度）の点検。
- **テスト**: 文書に記述された挙動とテスト対象が一致していることの点検。
- **ソース**: 未使用関数の削除、文書と実装の整合性確認、ファイルサイズ（1ファイル500行程度）の点検、`npm test` 全件合格の確認。
- **バックログ**: `オーナー検証` の各項目が画面操作・見た目で1件ずつ判定できる状態か点検。`要望・バグ指摘` の順序が依存関係・優先順に合っているかの点検。

## 対象外
- 新規機能の実装、機能の仕様変更。
- 新たに発見されたバグの修正（軽微なコードのずれや未使用関数の削除等の「見直し」範疇を除く）。バグを発見した場合はバックログの `要望・バグ指摘` へ追記する。

## オーナー指示による追加範囲

- GitHub Actionsの本番ビルドで共通ライブラリの相対importが解決できない不具合を調査・修正する。オーナーが今回の全体見直しでの修正を明示的に依頼したため、このCI設定修正を対象に含める。ゲーム機能の変更と共通リポジトリの変更は行わない。

## 完了条件
- 上記スコープに記載されたすべての見直し項目が点検され、必要な修正・整理が完了していること。
- `npm test` が全件合格すること。
- 見直した範囲と直した点に関する報告内容がまとめられていること。

## 実装・テスト方針
- ブランチ上で対象の文書・ソース群を静的解析（目視および検索）して不整合を洗い出す。
- ソースについては Lint / 未使用チェック等も活用し、未使用コードを削る。
- 修正によるデグレードを防ぐため、修正後は全体テストを実行してパスすることを確認する。
