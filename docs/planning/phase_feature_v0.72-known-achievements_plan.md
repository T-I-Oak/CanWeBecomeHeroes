# 成績表の既知項目表示の開発計画

## 合意した開発内容

- ブランチ: `feature/v0.72-known-achievements`
- 予定バージョン: `0.72.0`。package.json・package-lock.jsonは初回実装開始時に更新する。
- バックログ先頭の成績表の既知判定・保存・表示を対象とする。

## スコープと完了条件

1. レコード表示時にD-以上の項目を既知として扱う。D-以上への到達で既知フラグを更新する必要はない。
2. D-以上の判定は評価データに基づき、トーストごとの表示判定を条件にしない。表示待ち・モーダルによる通知抑止でも表示対象になる。
3. 結果画面の表示項目が確定した時点で、Eを含め項目IDごとの既知フラグを保存し、再読込後も維持する。裏面を開く操作は条件にしない。繰り返し結果表示で既知状態や集計を重複更新しない。
4. レコード画面の成績表は既知項目だけを定義順に表示する。既知項目の評価・判定基準・達成度の表示は維持する。
5. 既知項目がない初期状態では空の成績表を表示せず、「試験を受けると、ここに成績表が表示されます。」という案内を表示する。英語表示にも対応する。
6. 保存形式を変更してもフォールバックは禁止する。旧形式への補完、既存データからの既知フラグ推定・自動移行、形式不整合時の黙示的な初期化は設けない。データ未保存の新規作成と、非対応の保存形式は区別する。
7. 対象テスト、全テスト、本番ビルドの結果を実装報告に記録し、必要なオーナー検証の判断・対応を得る。

## 対象外

- 評価式、結果画面の項目選定、トースト通知条件・演出の変更。
- タグスキルの上限変更、バックログの他項目。
- 旧保存データの移行・復元・互換処理、共通部GameWorksOAKの変更。

## 実装方針

- RunRecordsRepositoryに項目IDごとの既知状態と保存責務を持たせ、保存形式と対応形式チェックを明確にする。既知化の入力と保存タイミングは既存の集計・保存フローに合わせ、保存失敗時のメモリ保持・再保存を維持する。
- RecordScreenDataの表示判定で、評価がD-以上または保存済み既知フラグがtrueの項目を採用する。評価の更新・通知の経路に既知フラグ更新を追加しない。
- 結果画面の表示項目確定時に、選定済み項目だけを既知化して終了記録とともに保存する。結果用の全評価候補を一括で既知にせず、裏面の閲覧を条件にしない。
- RecordScreenData・RecordScreenへ既知状態を渡して成績表を絞り込み、空状態の案内を日英の文言定義へ追加する。閲覧・言語切替では評価集計や保存を行わない。
- 既存の「未達成を含む全項目表示」の仕様を今回の合意に置き換える。バックログの対象項目は実装結果に合わせて整理する。

## テスト・検証方針

- 状態管理とイベント接続は先にテストで条件を定義する。D-境界、Eの未表示と結果表示、通知待ち・抑止、重複、永続化・再読込、保存失敗時の再保存、非対応形式の拒否を対象とする。
- レコードの未発見行の非表示、既知行の定義順、全件未発見時の案内、日英切替を検証する。結果選定・評価式・ランキング等の既存挙動が変わらないことを確認する。
- tests/README.mdに従い、対象テストを随時実行し、終了草案前に `npm.cmd test` と `npm.cmd run build` を実行する。ブラウザー検証は tests/02.browser_verification.md に従う。
- オーナーへ初期状態の案内と、試験後の既知項目だけが表示される見た目を、個別の検証IDで提示する。設定・タイトル・倉庫左下のバージョン表示は `0.72.0` と一致させる。
- 一時検証用成果物はtmp_配下へ置き、恒久的な確認ページを追加しない。全テスト・ビルドの失敗は原因と対応を記録する。
