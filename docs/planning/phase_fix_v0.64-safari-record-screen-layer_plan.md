# Safariでの画面回転時のレコード画面表示

## 合意した開発内容

- ブランチ: `fix/v0.64-safari-record-screen-layer`
- 予定バージョン: `0.64.0`。現在は `0.63.1`。実装開始時に設定を更新する。
- Safariでレコード画面を表示中に端末を縦横へ回転すると、タイトルの落下チップ演出の背面に回り込む問題を調査し、修正する。
- 原因は未確定であり、z-indexの問題と断定しない。

## 対象外

- 準備エリアの説明チュートリアルの開始タイミング。
- 情報ウィンドウなどの性能改善。
- 成績表の既知項目管理や、レコード画面の新機能・意匠変更。
- GameWorksOAKの変更。共通側に問題があれば必要な対応をオーナーへ報告する。

## 完了条件

- レコード画面を開いた状態で縦→横→縦へ回転しても、落下チップ演出より前面に表示され続ける。
- 回転後もタブ切替、表のスクロール、閉じる操作ができる。
- タイトルへ戻った後も落下チップ演出が正常に表示される。
- 関連テスト、全テスト、本番ビルドを実行し、結果を実装報告へ記録する。
- 実機Safariの確認結果を記録する。確認を保留できるのはオーナーが明示的に「現時点で確認しない」と判断した項目だけとする。

## 調査と実装の方針

1. Safariでの再現条件を確認し、回転前後の表示・要素の寸法・重なり順・描画状態を比較する。未再現の場合は、その環境と制約を記録し、実機で得られる情報と照合する。
2. `TitleMenu.js` の画面構造・開閉処理、`screens.css` と `record_screen.css` の重なり順・overflow・拡縮、`RecordScreen.js` の寸法更新、`TitleChipRain.js` のcanvasリサイズを調査する。
3. 原因に応じた最小限の修正を行う。数値のz-index追加だけで解決と判断せず、回転後の描画と操作を検証する。
4. レコードの保存内容・表示内容、表の可読性を維持する。拡縮や座標処理を変更する場合は、スクロールと関連情報ウィンドウへの影響も確認する。
5. 必要な仕様・テスト手順を更新し、バックログ先頭の項目を実際の結果に合わせて整理する。

## 検証方針

- 原因に対応する回帰テストを追加する。複雑な状態管理を変更する場合は、先に失敗するテストで期待する挙動を示す。
- ブラウザーではスマートフォン・タブレット相当の縦横viewportを往復し、表示と操作を確認する。利用可能ならWebKitでも検証し、実機Safariの確認結果と区別して記録する。
- タブ切替、縦横スクロール、閉じる、再度開く、タイトルの演出を確認する。変更の影響があれば関連情報ウィンドウも確認する。
- 対象テストに加え、`npm.cmd test` と `npm.cmd run build` を実行する。ブラウザーテストは `tests/README.md` の実行順・終了確認に従う。
- 失敗時は原因を調査し、今回の範囲内なら修正・再実行する。既存または範囲外の失敗は、根拠と今回修正しない理由を実装報告に記録する。
