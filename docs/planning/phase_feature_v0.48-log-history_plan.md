# ログ履歴パネルの開発計画

## 合意内容

- ブランチ: `feature/v0.48-log-history`。
- 予定バージョン: `0.48.0`。初回実装開始時にpackage.json・package-lock.jsonを更新する。
- 現在のランのログを読み返す履歴パネルを実装する。
- アチーブメント達成を履歴に追加する。トーストと同じ通知対象を使い、フロートログには表示しない。
- 「実力判定試験」を現在の正式名称として扱う。

## 開発スコープ

- ゲーム画面にログ履歴の開閉ボタンを設ける。
- 現在のランのGameLogの履歴を発生順で表示し、開いた直後は最新位置を表示する。過去の記録は内部スクロールで閲覧する。
- notifyがfalseの記録も履歴の表示対象に含める。
- 履歴表示中はGameClockを専用理由で停止する。閉じるとその理由だけを解除し、手動一時停止や他の停止理由を維持する。
- ログ内のタグ・ステータス・用語・Enemyなどの参照をアイコン付き情報リンクにする。既存の定義情報を表示し、過去時点の個体ステータスを再現しない。
- アチーブメント達成は、トーストへ渡す通知と同じ時点・同じ項目単位で記録する。評価項目名と到達判定を読み取れる表示にする。
- 達成記録には既存GameLogのnotify: falseを使用し、トーストは従来どおり表示する。
- 日本語・英語、PC・スマートフォン縦横の表示と開閉・スクロール・情報リンクの操作に対応する。
- 関連する仕様・構成文書とバックログを実装内容に合わせて更新する。

## 実装方針

- GameLogのgetRecordsと既存の記録を使用し、別のログ収集台帳を作らない。ラン開始時に新しいGameLogを作る既存の寿命に合わせる。
- 履歴パネルの描画・開閉・破棄は専用部品へ分離し、TrialSessionからGameLog・GameClock・表示に必要な依存を接続する。
- createLogMessagePartsを利用し、流れるログの非操作表示と履歴の情報リンク表示で文言・アイコンの解決処理を共用する。
- 情報ウィンドウは静的な定義参照を使い、履歴パネルを閉じた際の破棄とゲーム側の既存ウィンドウへの影響を確認する。
- StatisticsCollectorのonGradeRaisedで受け取る通知を、トーストへのenqueueと履歴への記録に接続する。UIの描画・演出から記録しない。
- 通知のIDと判定値を保持し、履歴の表示時に既存アチーブメント定義から言語に応じた項目名・判定を解決する。
- 通常15段階・タグ7段階の既存通知規則を使う。複数段階を越えた場合は最終到達判定を1件記録し、別の更新で同じ項目を達成した場合は別件にする。
- トーストの表示待ち・再表示・破棄で履歴を重複記録しない。保存済み達成の初期評価は新規記録にしない。ラン開始・初期Hero接続時の新規通知も受け取る。
- 履歴表示中は既存のモーダル表示中と同様にトーストの演出・寿命を停止し、閉じた後に再開する。
- 閲覧・言語変更では集計・保存・アチーブメントの評価を再実行しない。
- 共通のCSS・モバイル規定と既存のモーダル構成に従う。長文は折り返し、画面内に戻る操作を確保する。

## 対象外

- 過去ランのログ保存・再読込、検索・絞り込み、出力・共有。
- アチーブメント達成以外のログイベント追加、達成条件やトーストの演出変更。
- Hero解放タイミングの変更。期待する現行動作は試験合格時に終了メンバーを解放すること。
- 通算成績タブや解放状況・統計等の専用閲覧画面の追加。
- 実力判定試験の進行・終了・結果画面の実装。旧称のエンドレスという記述から進行方式を決定しない。
- GameWorksOAK側の変更。

## 完了条件

- 記録がない状態でも開閉でき、ログの件数・順序・内容がGameLogと一致する。
- 開いた直後に最新位置を表示し、過去の記録と長文を内部スクロールで読める。
- 履歴内の情報リンクを開閉でき、履歴の背後へゲーム操作が伝わらない。
- 閉じた後に履歴表示の停止理由だけが解除され、もとの一時停止状態を保つ。
- トースト通知に対応したアチーブメント達成が1件ずつ履歴へ入り、フロートログには表示されない。
- 既存達成の初期評価・描画・トースト再表示・言語変更で達成ログが増えない。
- 新しいランへ履歴や情報ウィンドウ・停止理由を持ち越さない。
- 日本語・英語、PC・スマートフォン縦横で開閉・末尾と先頭の閲覧・情報リンクを確認する。
- 必要なオーナー検証は実装中に理由・手順・期待結果と更新済みバージョンを添えて提示し、判断と対応を記録する。
- 対象テスト・全テスト・本番ビルドの結果を実装報告へ記録する。

## テスト方針

- 履歴の表示・開閉・停止理由の独立性・ラン終了時の破棄を検証する。
- アチーブメント通知の接続を先にテストで定義し、ラン開始時、複数同時達成、段階飛び越し、同じ項目の再達成を検証する。
- notify: falseでも履歴へ入り、FlowLogの表示対象に入らないことを検証する。
- 日英の表示解決、静的情報参照、閲覧時の非破壊性を検証する。
- ブラウザでPC・スマートフォン縦横の表示、スクロール、情報リンク、手動一時停止との併用、トーストの停止・再開を確認する。
- 実装終了草案の提示前に `npm.cmd test` と `npm.cmd run build` を実行する。

## 次担当への注意事項

- backlog.mdからHero解放タイミングと解放状況・統計等の閲覧表示の2項目を削除済み。オーナーが不要と判断した項目であり、実装や新規提案として復活させない。
- 正式な合否通知と二つ名は実装済み。残存する古いバックログ・過去の対象外記述を新規要求と解釈しない。
- 正式名称は実力判定試験。過去の「名称未確定」は現在の判断として扱わない。
- 本計画はログ履歴の範囲に限定する。他の残存バックログ項目を自動的に追加しない。
- フェーズ宣言・草案承認・終了コミットは01.branch_workflow.mdに従う。
