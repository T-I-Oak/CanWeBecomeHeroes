# ログ履歴ウィンドウの開発計画

## 合意内容

- ブランチ: feature/v0.48-log-history。予定バージョン: 0.48.0。
- 実装フェーズ開始と、調査後に設計合意を得てから実装することをオーナーが承認。
- ログ履歴は特殊な情報ウィンドウとし、移動・ピン止め・拡縮・親子関係・停止制御を既存の共通機構へ委ねる。
- フォーカスを残さず、既存のPaperScrollを使用する。

## 開発スコープ

- HUDの設定ボタンをログ履歴ボタンへ置き換える。
- 設定はタイトル・ゲーム共通の右上ギアボタンへ移す。タイトルメニューの設定コマンドを除く。
- ギアはホバー回転・押下反応を備え、日英の読み上げラベル・ツールチップ、safe area、動き低減設定へ対応する。
- 現在のランのGameLogを発生順で全件さかのぼれるようにする。notify: falseも含める。
- 初回表示は最新位置。末尾閲覧中は新着へ追従し、過去閲覧中は位置を保つ。「最新へ」を設ける。
- 本文の表示範囲と前後だけを描画し、可変行高と長文折返しに対応する。
- スイッチは「通常ダメージ・ミスを表示」「Exスキル関連を表示」の2つ。初期値は両方ONとする。
- スイッチ変更は過去分を含む表示だけへ作用させ、全記録を保持する。文面解析は行わない。
- Exスキル専用の19種のログをex-skill channelへ分離する。フロート表示位置は戦闘と同じに保つ。
- 通常ダメージ・ミスはlogDamage・logMissキーで判定する。会心・撃破は残す。
- ログの静的参照をアイコン付き情報リンクにし、既存の定義情報を表示する。
- アチーブメント通知と同じ項目単位をGameLogへnotify: falseで記録する。IDと到達判定を保持し、表示時に既存定義から日英の名前・判定を解決する。
- 日英、PC・スマートフォン縦横へ対応し、仕様・構成・バックログを更新する。

## 実装方針

- GameLogを唯一の記録元とし、別のログ台帳を作らない。現在のランの寿命に従う。
- InformationWindowLayerへ履歴のコンテンツを追加する。通常ウィンドウと同じManager・Tree・操作部品を使用する。
- 履歴コンテンツと仮想スクロール部品を分離する。再描画で閲覧位置を保持する。
- createLogMessagePartsとLogMessageViewをフロート・履歴で共用する。
- リンク先は定義参照とし、過去の個体状態を再現しない。
- createAchievementNotifierを統計セッション構築前に接続し、ラン開始・初期Hero通知も受け取る。
- 既存の通知規則を使い、段階飛び越しは通知された最終判定を1件記録する。同項目の別の更新は別件にする。
- トーストの描画・再表示・破棄を記録元にしない。閲覧・言語変更から集計・保存・達成評価を呼ばない。
- 履歴独自の停止理由やトースト停止処理は設けない。情報ウィンドウの設定・ピン止めの既存動作に従う。
- ラン終了時に情報ウィンドウと履歴部品を破棄し、次のランへ持ち越さない。

## 対象外

- 過去ランのログ保存・再読込、検索、出力・共有。
- 使い魔のダメージ調整。低すぎる可能性の確認をバックログへ記録する。
- Hero解放タイミング、専用統計画面、試験進行・結果画面の変更。
- GameWorksOAK側の変更。

## 完了条件と検証

- 全記録の順序・内容を維持し、空の状態でも開閉できる。
- 長文・多数記録を内部スクロールで先頭・末尾まで読める。
- スイッチ、最新への移動、新着追従、過去閲覧中の位置維持を確認する。
- 既存のピン止め・拡縮・停止・親子の情報リンクが動き、背後へ操作が漏れない。
- 達成通知は重複せず、silent記録はFlowLogへ流れない。言語変更と閲覧は非破壊。
- 対象テスト・全テスト・本番ビルドを実施し、コマンドと結果を実装報告へ記録する。
- 日英、PC・スマートフォン縦横をブラウザで確認する。
- 必要なオーナー検証を理由・手順・期待結果・更新済みバージョンとともに提示し、項目別の判断を記録する。
- フェーズ終了草案とコミットは01.branch_workflow.mdに従う。保存済み引継ぎ書は承認まで更新しない。
