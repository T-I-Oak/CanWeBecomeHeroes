# 実装結果: 操作の実装とモバイルビュー調整

## 対象とバージョン

- 対象ブランチ: `feature/expand-controls`
- バージョン: `0.36.0`。新規開発として直前の`0.35.7`からMinorを更新し、初回実装のPatchを0にした。計画書にはMinorの明記がなかったため、この根拠を記録する。
- チュートリアルとリセット機能は対象外。

## 実装

- `GameCanvasInput`に描画フレームごとの更新を追加した。選択ドラッグ中、画面内の辺から56px以内で、端への距離に応じて最大360画面px/秒でカメラをスクロールする。長いフレームの移動量は0.05秒分に制限する。
- ポインタを保持してもスクロールを継続する。画面外、ドラッグ解除・キャンセル、ピンチへの移行では停止する。空白からのドラッグには適用しない。移動範囲は既存Cameraの制限を使い、一時停止中も描画時間で操作する。
- 水滴表示のHeroを選択元にする。ホバー・解除位置に水滴がある場合は、そのHeroを選択先として渡す。タップによるHero中央への移動は維持する。
- `HeroItemInteractionController`のホバー更新と選択確定は、画面上の対象を明示できるよう拡張した。Hero→Itemの出発とItem→袋の格納など、既存の組合せルールを共用する。任意チップの移動・入れ替えを新設していない。
- HUDに`touch-action: none`と長押し選択抑止を指定し、HUD上に重なる水滴のドラッグを扱う。HUD位置はsafe areaを考慮する。
- ページ全体のスクロールを抑止し、ダイアログの高さから親レイヤーの上下余白を差し引く。
- カメラ初期倍率、各エリアの寸法、HUDの均等縮小は既存仕様を維持する。

## 文書とテスト

- 操作確認前に`tests/manual/controls.md`へ操作一覧と表示一覧を作成した。
- UI仕様へエッジスクロールと水滴のドラッグを記載した。
- バックログの実装対象3項目を、個別のオーナー検証項目へ移した。開始時から存在した「説明書と」の削除差分は保持した。

## ブラウザ確認と限界

Codex内ブラウザで390×844、844×390、768×1024の表示を確認した。実機の指入力をエミュレートした検証ではない。

- 縦画面: タイトル・設定・出撃選択・課題選択の表示、マップ全体表示、Hero情報ウィンドウの開閉を確認した。
- Hero→倉庫Itemのドラッグ後に出発ログを確認した。拡大時の水滴から倉庫Itemへのドラッグ後、対応Heroが倉庫へ移動してItemを拾う表示を確認した。
- 横画面: 出撃選択が収まり、課題選択と設定は本文を内部スクロールでき、設定の閉じるボタンが画面内に残ることを確認した。設定の境界は左202、上11.70、右642、下378.30で844×390内に収まった。
- タブレット: 設定の境界は左164、上154.89、幅440、高さ714.22で768×1024内に収まった。
- 横画面のページ寸法は844×390、縦画面のページ寸法は390×844で、ページ全体に余分なスクロール領域がない。ブラウザのエラーログは0件。
- HUDを幅だけで調整する変更は、ランタイム仕様136行の均等縮小を見落としていたため取り消した。関連するテストも原状復帰した。上記の一部表示確認は一時的なHUD変更中に行ったため、HUDの最終的な見た目の確認根拠には使わない。最終状態の均等縮小は既存コードと対象テストで確認した。
- エッジ保持、画面外への離脱、水滴上での選択確定、Item→袋、ピンチへの切替は自動テストで検証した。スマートフォン実機の指操作・SafariのブラウザUI・safe areaでの確認と結果ダイアログの目視は未実施である。
