# チップ負荷の調査と性能修正

## 対象

- 起点は全体レビューで挙がった性能問題の可能性であり、オーナーが実ゲームで遅さを感じて報告したものではない。

- バージョン0.68.1。提案に加え必要な修正まで対象とする。
- 修正前の測定と制約は phase_chore_v0.68-chip-performance-investigation_baseline.md を参照する。
- 描画品質、既存のメモリ予算、ゲーム挙動を維持する。他の性能や品質との引き換えが必要な変更は、利点と不利益を示してオーナーの判断を仰ぐ。

## 採用する修正

- ChipBoardの接触候補について、軸方向だけで接触しない組を距離計算より先に除外する。
- 走査用のslice・filterと、組キー生成用の配列・ソートを除く。
- 地上分離の逐次処理順、高度・拾得・転送の除外、重なり中の上下順を維持する。
- 密集した混合状態70チップを15回更新し、従来の逐次分離処理との全座標一致を検証する。

## 撤去した試作

- 合成Canvasキャッシュ、描画器への有効化、描画完了判定の追加、および専用テスト・画素比較スクリプトを撤去した。
- 既存24MiBの画像段階キャッシュは、通常画面の66種類について全段階20.74462890625MiBという容量計算に基づく。
- 試作の別枠16MiBには組み合わせ数・拡大時の容量根拠がなく、メモリ使用量を増やしていた。採用しない。
- 撤去前の試作を測った chips-fixed-* および chips-implementation-* の既存結果は、現在の修正の効果を示す根拠に使わない。
- ChipRenderer、ScaledImage、TrialSessionはHEADの実装へ復元し、追加の画像キャッシュは残さない。

## 計測と検証

- 計測専用ビルドで固定seed・同一個数・同一課題の旧処理→修正処理→旧処理を比較する。通常ビルドに計測フックを含めない。
- 撤去後の性能測定と全テストの結果を下記に記録する。

## オーナー判断と今回の完了範囲

- 2026-10-26、既存のメモリ予算・描画品質を維持した計算負荷削減で、今回のスコープとして十分との判断を受けた。
- 人工的なCPU速度制限下で長いフレームが残ることだけを理由に、追加の性能対策を必須とはしない。
- 実ゲームで遅いと感じる問題が発生した場合、その条件を確認して改めて改善方法を検討する。今回は新たな実機確認や追加対策を要求しない。
- バックログに追加した描画負荷・全組合せ走査の継続対策2項目を取り下げた。調査結果と測定上の制約は資料に残す。起動時JavaScriptなど別件の項目は変更しない。
