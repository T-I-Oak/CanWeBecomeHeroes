## 未解決指摘

### RV-SHUTDOWN-01（P2）：最初の起動後照会失敗で起動済みプロセスを残す

対象：`scripts/verify-browser-tests.js` の74〜79行、106〜133行。

`known`は空で初期化され、spawn後の最初のinventory成功時に初めてルートの識別情報が入る。
このinventoryが15秒上限や一時的な照会エラーで失敗すると、テストは既に起動しているが
`known`は空のままcatch/finallyへ進む。finallyで照会が回復してルートと子孫が見えても、
`descendants(current.processes, [])`は空なのでtaskkillは一度も実行されない。
その後ストリームを破棄しchild.unref()するため、検証補助だけが失敗終了し、
起動済みのテスト・サーバーが残り得る。次回は専用ポート使用中で起動できなくなる。

最初の事前照会中にSIGINT/SIGTERMを受けた場合も、stopRequestedを確認せずspawnし、
最初の観測ループを飛ばすため同じ識別情報なしの経路へ入る。

起動前の中断時には起動せず、起動直後の観測失敗でも、今回起動したプロセスの
所有を安全に確認して後処理できるようライフサイクルを修正する。
無関係なPIDを終了するフォールバックは追加しない。
最初の起動後照会だけが失敗して後処理時には回復するケースと、事前照会中の中断を
制御したテストで検証する。現在の契約テスト2件は判定関数と子孫探索だけで、
この実行フローを検証していない。

この指摘は制御フローの静的確認に基づく。実プロセスを残す障害注入は実施していない。
