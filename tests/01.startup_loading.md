# 起動時の読み込み負荷調査

`normal`は現在の本番設定を使う。画像マニフェストの静的分割が本番へ適用されているため、
初回調査の単一チャンク構成を再現する場合は、Git履歴にある適用前のソース・設定を使う。

`node scripts/measure-startup-loading.js --list`で比較条件を確認する。
警告とチャンク構成だけを確認する場合は`node scripts/measure-startup-loading.js --build-only normal static trial compact`を使う。
通常の警告設定のままビルドし、`results.json`へ警告文とチャンクサイズを記録する。ブラウザー測定は行わない。
`node scripts/measure-startup-loading.js`は全条件を同じ本番相当ビルド・配信条件で順番に測定する。
条件名を引数へ渡すと、その条件だけを実行する。
通常ビルド`normal`と計測フック付き`baseline`を区別し、`bootstrap`は入口の非同期起動方法だけを変更する対照条件とする。
`trial`・`records`は単独の遅延読み込み、`both`は併用、`prefetch`は併用とタイトル操作可能後の先読み、
`compact`は画像マニフェストの表現縮小、`combined`は遅延読み込み・先読み・マニフェスト縮小の併用。
`static`は画像マニフェストを静的な別チャンクへ分け、起動時に読み込む構成を維持する。
これらは調査用の変換であり、通常のVite設定や本番の読み込み構成を変更しない。

4188ポートを空け、ゲームルートで実行する。既定はインストール済みChromeのheadless、1024×768・DPR1、
CPU4倍制限、CDPのlatency=40ms、下り2621440byte/s・上り1310720byte/s、非圧縮配信、各3反復。
各反復は新しいブラウザーコンテキストでの初回取得と、そのコンテキスト内での再訪を区別する。
保存内容は毎回同じ状態（挑戦モード開放・チュートリアル既読）へ戻し、乱数seedを固定する。
他のビルド・テストや性能計測を並行実行しない。

`STARTUP_REPEATS`で反復数、`STARTUP_OUTPUT`でリポジトリ内の`tmp_`出力先、
`STARTUP_CHANNEL=chromium`でブラウザーを変更できる。
`STARTUP_ACTIONS=records`等で操作を絞れる（既定は`records,trial,challenge`）。
`STARTUP_TRACE=0`はトレース採取なしの対照測定。解析・実行指標は未取得として`null`になる。
予備測定は反復1回・別の出力先で行い、主要比較へ混ぜない。

タイトルの同期初期化完了時刻と、DOM生成を観測して即座に送った入力から対象画面の生成までを記録する。
実際の開始ボタン・タブ・再表示・言語切替・課題選択も検証し、到達失敗や通信・実行時エラーは成功として記録しない。
試験開始のメンバー選択までの待ちと、開始劇をスキップして課題選択が表示されるまでの待ちは別指標とする。
先読み条件は即時入力と先読み完了後の入力を別に測る。

`results.json`にはチャンクの静的依存・動的依存・モジュール寄与、非圧縮／gzip参考サイズ、
各反復の時刻・Resource Timing・トレース集計・検証結果を保存する。トレース本体も同じ出力先へ保存する。
通信量は完了済みリソースの実測値で、gzip参考値や未完了の通信を含めた総量と混同しない。
解析・コンパイルと実行はトレースイベントの区間和をカテゴリ別・スレッド別に集計する。
同一カテゴリ内の入れ子は重複加算しないが、カテゴリ間は重なるため加算しない。
コンパイル待機専用イベントは除外する。トレースの経過時間は純粋なCPU時間とは限らない。
ローカルの制限付きPC測定を公開配信・モバイル実機の保証とせず、ばらつき・計測負荷・共有依存の限界を実装報告へ記録する。
