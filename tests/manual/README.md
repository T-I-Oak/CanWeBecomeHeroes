# 画面の手動確認

通常のVite開発サーバーを起動し、以下のURLを開く。これらは開発用入口であり、通常の本番ビルドには含まれない。自動テストの配置と要求との対応は[テスト構成](../README.md)を参照する。

## Safariのレコード画面回転の切り分け（実機確認用）

例外として`/CanWeBecomeHeroes/tests/manual/record-rotation.html`は、実機Safariの原因調査のため本番ビルドにも含める。実機では通常のゲームを更新し、タイトル画面の「Safari回転検証」から開く。一度の配信で全条件を比較する専用入口であり、通常のゲームには切替機能を追加しない。調査が完了した時点でタイトルのリンク・公開入口・Viteの追加エントリーを撤去する。

本番のTitleMenu・RecordScreen・TitleChipRain・CSSを使い、サンプルランキング10件と同じ乱数seedを使用する。ゲームの保存データは読取・変更しない。検証記録だけを専用sessionStorageキーに保持し、条件を切り替えても同じタブ内に残す。「検証記録を消す」で削除できる。

縦画面で条件を選択し、「この条件で最初から試す」を押す。パネルを畳み、横→縦へ回転する。パネルを開く前に紙・操作部・表とチップの前後関係を確認してスクリーンショットを撮り、「異常あり／異常なし」を記録する。条件変更時はページ全体を読み直す。Aで再現しなければ、この専用入口で得た比較から原因を判断しない。

| 条件 | 変更するもの | 意図した表示差 |
| --- | --- | --- |
| A：変更前 | 外側のtransformを除去し、重なり順変更を撤回した実装を再現 | 比較基準。最初に症状が出るか確認する |
| B：表の拡縮なし | 本文のtransformを除去し、スクロール範囲を等倍に整合 | 表が大きくなり横スクロールが増える |
| C：canvasのサイズ更新停止 | 初回以降の描画サイズ更新を止める。CSS寸法・演出は追従・継続 | 回転中のチップ画像が伸縮・変形する場合がある |
| D：表の内部スクロールなし | 表のScrollViewportのoverflowだけvisibleへ変更 | 外側の枠で表が切れ、末尾まで操作できない場合がある |
| E：紙・操作部・表をまとめて描画 | レコード全体の外側にtranslateZ(0)。canvas更新・内部スクロール・本文の縮小は維持 | 現行の修正候補。初期選択はE |

v0.64.3以降のA〜Dは、外側のtranslateZ(0)を検証ページ内で除去し、v0.64.2と同じ比較条件を保つ。通常ゲームはEと同じ外側の指定を使う。

「記録を表示」で条件、バージョン、画面寸法、DPR、VisualViewport、canvasのCSS寸法・描画寸法・更新回数、本文transform、スクロール寸法、判定を確認できる。ブラウザー情報も含む。記録は自動送信しない。各条件は原因を特定するための比較実験であり、どれかで症状が消えても、その条件を製品の修正として直ちに採用しない。

## 暴風の翼

`/CanWeBecomeHeroes/tests/manual/gust.html`

本番のBattleSystem・ChipBoard・ChipRenderer・移動／装備処理を使う。プレイ記録は保存しない。ページと実ゲームのタイトル・倉庫左下が同じバージョンであることを確認する。

- 「再生」でHeroが等倍のまま着地点へ移動しながら上へ飛ばされ、影も追従することを確認する（`OV-GUST-ASCENT-01`）。
- 装備がHeroの位置から離れて上昇中に広がり、上昇から落下への切替で地上位置・高さが飛ばず、倉庫へHeroと装備Itemが同時に落下する見え方を確認する（`OV-GUST-DROP-02`）。
- 通常／1/4速度で繰り返し再生できる。着地後の行動を切り替えると、第1武器の再取得または準備エリアへの帰還を確認できる。
- 頭・胴・両手・足の全5装備を使用する。装備は方向と距離が不規則にばらつき、倉庫内でHeroから離れて落下する。

## 情報ウィンドウの多言語表示

`/CanWeBecomeHeroes/tests/manual/localization.html`

本番のGameTextRepositoryと情報ウィンドウRendererを使う。言語選択は共通設定へ保存されるため、確認後は元の言語へ戻す。

Detailにはエリア、施設、ステータス、タグ、用語、Item、Hero、固有スキルを列挙する。固有スキルはEx1・Ex2を含む共通の静的情報を開く。件数は現行リソースから生成する。敵の詳細は実ゲームまたはレコード画面から確認する。

Itemは代表の画像とタグを用いる。個別のItem画像ではなく、多言語の文言・参照・配置を確認するための入口である。

1280×720、800×600、390×844を目安に、日本語と英語で以下を確認する。

- ウィンドウが画面内に配置され、本文が横にはみ出さない。
- 長い本文を内部の縦スクロールで最後まで読める。
- Hero、タグスキル、施設など長さの異なる説明で、文字と操作が収まる。

`node scripts/review-localization.mjs`で日英文言を出力できる。言語リソースの整合性と設定・状態維持の回帰検証は`npm.cmd test`で行う。

## 実力判定試験

`/CanWeBecomeHeroes/tests/manual/challenge-mode.html`

本番の描画・チュートリアル・終了通知・レコード画面を、保存しない表示用サンプルへ接続する。ページのバージョンが実ゲームのタイトル・倉庫のバージョンと一致することを確認する。

- 課題を1・7・8・14・15・21・22へ切り替え、背景帯が7課題ごとに紫系と赤系で塗り替わることを確認する。
- 専用チュートリアルを開き、承認済み本文3ページとボタンの収まりを確認する。
- 終了通知は第8課題到達・7課題クリアーの4人パーティーを表示する。導入演出、二つ名、判定日、署名・印・紙吹雪がないこと、表裏操作を確認する。
- クリアー済みのチェックを切り替えてレコードを開き、実力判定試験タブの非表示・表示を確認する。クリアー課題数は7、経過時間は8日0時間となる。
- 日本語・英語とPC・スマートフォン縦横で確認する。言語選択は共通設定へ保存されるため確認後は元に戻す。

## 終了結果の共有

`/CanWeBecomeHeroes/tests/manual/result-sharing.html`

表示用サンプルで、プレイ記録は保存しない。日本語・英語、合格・不合格・実力判定、長い二つ名を選択して「共有画像を表示」でPNGを確認する。「終了画面を開く」から裏返し・結果をシェアする・タイトル復帰を操作できる。画像はタイトル画像→通知→成績表10件→copyrightの順。端末の縦横や表示中の面によって内容が変わらず、紙の質感・文字色・罫線・印影が画面と一致することを確認する。

PCでは画像コピー後の確認画面から「Xを開く」で本文入りの投稿画面を開き、画像を貼り付ける。「閉じる」・EscapeではXを開かない。モバイルでは端末の共有画面へ画像・本文が渡ることを確認する。クリップボードや共有機能の非対応・権限不足では失敗案内が出る。キャンセル後の再操作、生成失敗時の案内と再試行も確認する。ページのバージョンと実ゲームのタイトル・倉庫のバージョンが一致することを確認する。実機での検証済みを意味しない。

言語選択は共通設定へ保存されるため、確認後は元に戻す。

## Hero加入会話

`/CanWeBecomeHeroes/tests/manual/recruitment-dialogue.html`

加入者、2人／3人Partyの既存メンバー、日本語／英語を選んで「再生」する。選択時に本番の処理で知人の有無・配役・会話を自動決定し、判定結果と6発言の一覧を表示する。知人の有無を手動指定する操作はない。プレイ記録は保存しない。言語選択は共通設定へ保存されるため、確認後は元へ戻す。

- メンバー1→2→3は通常の配役優先順（試験場スロット2→3→1）。加入者の知人を含めると、通常順によらず2人ならB、3人ならCへ配役される。加入者・メンバー間の人物の重複は選べない。
- 一般用と知人用で全6発言の収まり、再会から誘い・承諾・締めへの流れを確認する。再生後に配役と台詞一覧も読める。
- Skipで閉じて再生できることを確認する。実ゲームでの加入確定・次課題への進行は別途確認する。
- 確認ページと実ゲームのタイトル・倉庫左下のバージョンが一致することを確認する。
